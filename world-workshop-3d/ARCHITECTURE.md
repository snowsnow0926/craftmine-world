# 最中幻想 · craftmine world 0.2：实现边界与继续开发的接点

正式名称以「craftmine world / 最中幻想」为准。更名只更新产品展示和下载文件名；`world-workshop-voxel-v02` 存储键、`world-workshop-save/0.2` 存档格式、`world-workshop-cartridge/0.2` 卡带格式及已有内容 ID 保持兼容。不要仅因品牌更名而更改这些数据标识。

## 这一轮的目的

把上一版的“观看一个世界”升级为“人在可玩的 3D 世界中提出修改”，同时继续验证 Harness 的闭环。不是为了把平台立刻做成完整游戏引擎，也不是用大量预设假装任意需求已经可以由 AI 开发。

## 两层组织

`VoxelRuntime` 负责游戏本身：世界数据、区块网格、相机与输入、碰撞、方块编辑、交互和运行快照。`workshop.js` 负责创作流程：意图、对象上下文、任务、候选变更、应用与回退、素材选择、版本、卡带和存储。

二者通过构造回调及有限方法连接。主要运行接点：

```js
const engine = new WorldRuntime.VoxelRuntime(canvas, callbacks);
engine.generate(config, snapshot); // 构建或重建世界，传入当前状态
engine.snapshot();                // 导出玩家进度与世界差量
engine.pauseInput();              // 释放输入，世界画面仍可存在
engine.setActive(false);          // 暂停模拟 / 绘制
engine.respawn();                 // 回到出生点
engine.dispose();                 // 清理监听器和图形资源
```

应用还暴露 `window.workshop` 供原型调试与确定性测试，不能把这一全局对象当作权限边界。若日后接入不可信代码，应另建隔离运行环境，不能直接把模型返回代码交给当前页面执行。

## 世界与稳定身份

体素数据：`Uint8Array(96 * 96 * 40)`。水平按 16 格分块，共 36 个区块。只创建空气相邻的可见表面；不是逐方块一个 DOM，也不是逐方块一个绘制调用。手动修改重建受影响区块及邻接区块；整树采集处理所有涉及的区块。

树木具有稳定 ID，例如 `tree-001`。射线命中体素后可关联到树木实体，因此 Agent 的上下文能够表达“这棵树”，而非只传一张没有关联信息的截图。当前实体上下文仍是演示用途，尚未映射到真实游戏项目的源代码位置。

基础地形与树木位置由确定性代码生成。重建顺序为：

```text
基础世界与当前规则 / 外观
→ 移除已采集的原生树木
→ 应用手动方块差量
→ 恢复玩家状态并检查安全位置
```

手动修改优先，避免换素材时把玩家自己的搭建抹掉。这也意味着个别被手动编辑的原生树木部位不会完全服从整树采集；未来通用对象系统需要进一步明确对象所有权与编辑覆盖策略。

小地图是地形与主要实体概览，不是所有手动搭建的精确俯视渲染。

## 运行与修改的关系

当前预设适配器只返回受限配置补丁，不生成代码。流程是解析、字段校验、候选差异、用户应用。阶段延时用于演示候选准备的交互节奏，不表示真实模型正在编译或测试。

配置候选带有基准版本。用户点击应用时才捕获最新快照，所以准备候选期间继续游玩的进度会被保留。随后暂停运行、使用新配置重建，并恢复快照。并非对任意代码做通用热替换。

配置历史、手动撤销和完整世界归档是三个不同层次：配置历史不会倒退进度；Z 只撤销当前会话最近的手动方块；世界归档才保存完整运行快照。应用或恢复后会清空手动撤销栈，防止撤销旧几何操作覆盖新世界。

## 素材与行为

当前树冠样式是一个稳定外观字段，采集能力与掉落量是独立规则字段。它们组合后进入同一运行世界，不通过替换整个项目来改外观。

下一阶段接入真实素材服务时，需要稳定资产 ID、来源、版本、对象绑定与适配检查；模型文件本身不等于碰撞、动画与完整玩法。当前界面中的树木预览是程序化图形，而非真实 AI 生成模型预览。

## 卡带是受限内容格式，不是通用插件系统

当前只支持三类白名单 JSON：世界、玩法配置和素材样式。世界卡带包含实际手动方块差量和已采集树木；个人背包及位置通过完整存档单独流转。

严格拒绝不兼容运行版本、未知字段、脚本字段、额外权限、不合法坐标与过大数值。原型没有动态 `eval`、脚本插入或网络权限授权。这个限制保证的是本格式不提供任意代码执行入口，不是对未来第三方插件系统的完整安全证明。

安装世界卡带会产生新起点，并归档当前世界。它不实现两个世界自动合并，也不实现从任意游戏代码自动抽取可复用模块。依赖当前只支持 `runtime.core`，没有版本约束解析器、依赖图或包下载服务。

## 下一阶段的真实 Harness

建议优先替换预设适配器，而不是继续增加大量“假 AI 能做的指令”。让一个真实 Agent 在隔离项目副本中完成一项小玩法开发，把检查结果与构建产物交给主工作台；玩家明确应用后，运行器载入新构建。

模型提供商密钥与开发权限放在受控后端，不注入游戏 iframe 或分享卡带。真实代码候选需要源代码版本、构建产物、检查证据、状态兼容声明与失败恢复，而不仅是一段聊天回复。

随后把同一个稳定玩法提取为可安装模块，在第二个同运行约定项目中验证复用。这比过早做公开市场更能检验卡带机制。

多人共创应区分联机运行状态和项目版本的同步。邀请别人一起玩，不等于授予修改代码、安装插件或向所有人发布版本的权利。本版完全没有多人后端或权限实现。

最后，保留运行器可替换的方向。3D 方块世界适合作为第一个演示作品，未来二维、非方块三维或其他引擎适配器应能继续使用相同的任务、版本、素材与发布工作流。
