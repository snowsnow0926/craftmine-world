# 造物目标、源码和进度的可信边界

关联整体实施计划P1–P4。沿用宿主、源码事务和候选协调器。

此前模型填写targetSnapshot并与自己填写的值匹配，不能证明玩家指向。现在主窗获得opaque captureId，提交时由宿主验证项目、会话、世界、正式构建与运行实例，再持久绑定turn。模型读取此上下文，不能用自己生成的坐标授权修改。

后台移动不改变固定落点；当前位置只用于写入和采用前碰撞检查。同任务有界操作可以连续；其他源码变更不能静默扩大旧捕获范围。

新底座是真实3D场景，必须经构建检查与候选采用。磁盘mtime轮询不能表达正式内容身份，因此旧附加绘图器取消该路径。旧四底座保持原行为，造物工具不冒充已支持。

进度由真实候选默认驱动，Rust独立重算与JS一致后才准备采用。door/rule只补新键；旧位置、背包、开箱和规则状态保留；sourceTimeOfDay区分显式源码时间与游玩变化。自定义规则状态为JSON字典，语义由运行时validate_state验证。

纯逻辑、真实Godot、真实Rust和host/headless UI分别验收，不以任一单层通过代替整个故事。
