# FB02 全部要求与逻辑闭环审计

## 结论

**没有每一项都做到，也没有全部闭环。preview.16 是部分修复版，不能作为 FB02 全部要求完成版。**

本轮按 FB02 原始九项、八张原始截图、后续两张复测截图，以及用户后续澄清重新核对。审计的是源码 `6fb1dc01` 生成的 preview.16 ZIP；审计开始时 master `591ae9cd` 相比它只增加文档、截图和测试，产品实现相同。

上轮主要确认了首次加载、系统全屏、F2/Esc 回调、旧地面正常升级与保存退出的正常路径。不能由这些成绩推出二级入口、工作台视图保持、完整全自动、生成结果入口和预览应用流程也已完成。本轮还找到了设置返回、首次发送丢失世界面板、地面维护中断恢复三个确切断点。

## 用户已经明确的要求

- 黑屏最后会进入世界；需要的是等待期间可见的加载反馈，不能只按永久卡死处理。
- “F2 按下没反应”是实际体验事实；提示文案存在或直接调用处理器成功不能推翻它。
- 全自动的澄清原话：“我想要的全自动就是不用玩家任何操作 完完全全的自动”。内置 Craftmine 项目补丁自动执行的授权已经明确，不能再要求用户重复确认或额外勾选才能兑现承诺。
- 地面就是附件中的 3D Godot“第一个世界”。截图已经提供识别依据，不需要再问是哪一个世界。
- 用户连续确认了实际运行目录。2dc7748e 未通过复测，应检查实际交付和已有世界，不能把问题归结为用户解压错包。
- 保留有价值内容、草稿和存档；开发验证不得抢占键鼠、窗口焦点或 Pointer Lock。这些约束仍有效。

## 已定位的具体断点

### A. 工作台首条发送收起世界（FB02-005）

实际调用链：

`sendPrompt → materializeDraftSession → commitCreatedEmptySession → switchWorkPanelSession → 空的新会话面板`

- `src/stores/app-store.ts:2171` 首条发送物化草稿会话，`:4600` 切换会话的工作面板。
- `src/lib/work-panel-tabs.ts:64` 对没有既有上下文的新会话返回空面板。
- `src/App.tsx:284` 世界展示条件因此失效；`CraftmineNavigation.tsx:54` 初始化已执行，不会自动重开。
- 点击侧栏世界会重新打开世界，符合原图“给我生成一个博美犬”已经发送并得到回复的状态。
- `test/work-panel-tabs.test.mjs:26` 甚至断言新会话面板应为空。这个测试证明了旧会话隔离约定，没有证明反馈要求。

执行现有纯函数的结果是 `open:true/world tab → open:false/tabs:[]`，原世界仅保留在 HOME 上下文。它不是世界数据被删除，但玩家可见世界确实消失。

不能扩大为“每按一个字符必定出错”：`Composer.tsx:2158` 普通 onInput 只更新草稿；确定触发点是首条发送，以及 `:1781/:1880` 部分附件/粘贴创建会话。现有信息已足够开始修复，不应继续把用户补图当作前置条件。

### B. 暂停设置后回不去原游玩状态（FB02-002 的返回闭环）

- `src/App.tsx:2061` 点击设置先 `enterCraftmineMode("create", {explicit:true})`。
- `src/lib/craftmine-layout.ts:134` 因此持久写入 `playWhenWorldActivates=false`。
- `src/pages/SettingsPage.tsx:1290` 返回按钮仅 `setPage("chat")`，没有恢复原 play/暂停上下文。

这不是“设置按钮打不开”；它能打开通用设置页。缺的是“从游戏进入设置，完成后回到同一游戏状态”。现有暂停组件测试仅把 settings 回调写进数组，完整包测试没有走该路径。

### C. 生成完成与可操作结果之间断开（FB02-008）

- `plugins/craftmine-world/view.mjs:329`：没有事先打开预览时，`previewControlState` 返回 null。
- `src/components/CraftminePreviewControls.tsx:65`：没有 preview 就不渲染。
- 所以新增控制条只有在玩家已经去检查记录并打开预览后才出现，未解决“生成完成就从对话直接操作”。
- `App.tsx:1933` 的生成状态条仅在沉浸对话展开时挂载；普通创作工作台没有相同提示。
- `electron/main/creation-task-status.ts:18` 的状态不带可操作的 candidateId/buildId，不能直接把提示变成精确候选动作。

`autoOpen=false` 本身不是根因：创作模式的对话面板本来可见，已有预览的按钮可以显示。缺口在“检查完成 → 出现可操作结果卡”，不能错误地只改 autoOpen。

### D. 权限全自动与正式世界自动更新分离（FB02-007）

- `crates/host-core/src/rpc/mod.rs:2403` 已修内置工具全局 auto 对旧 ask 的覆盖。
- `electron/main/creation-target-service.ts:66/:221` 却从另一个默认 false 的每世界策略绑定 autoApply。
- `CreationTargetContext.tsx:25` 仍呈现独立复选框；原截图也同时显示“全自动”和未勾选的此世界自动应用。
- `creation-auto-apply-service.ts:20/:21` 因未授权自动采用或愿望不在可验证范围而返回 manual。
- `creation-check-requirements.ts:26/:55` 当前只识别有限愿望；场景对象/observer 升级还有明确禁用自动采用的分支。
- `index.ts:1194–1200` 还要求检查完成时原 turn 活跃、未收尾、仍在同一会话和世界。异步检查晚于 turn 结束时会落到手动处理；执行器 `godot-executor.cjs:1075` 记录需手动采用。

不能靠简单删除身份、世界、检查或存档保护来“实现全自动”。应把用户已选择的自动意图、检查任务归属和完成收尾保存到足以覆盖异步检查的生命周期，并提供失败自动修复/安全续作和清晰最终结果。

### E. 地面维护被打断后不恢复（FB02-006 的恢复闭环）

- `index.ts:1317` 在开始前把 instanceId 加入 `groundMaintenanceAttempts`。
- 玩家开始创作会正常取消后台维护，这是合理的让路。
- 取消后没有释放尝试标记或安排空闲恢复；`:1309` 之后同一实例的调度全部提前返回。

离线执行当前真实调度函数并模拟第一次服务被取消：调用两次调度，维护仅启动一次。玩家刚进入就开始创作，可能一直看到旧颜色，直到重新打开实例。该结论来自真实调度函数与模拟取消服务，不是另一轮完整成品中断实验。

## 本轮验证及证据边界

- 重读并核对原始截图、用户澄清、源码与实际封装提交，没有操作真实用户 profile 或物理键鼠。
- 复核成品正常路径：`test-results/desktop-native-fb02-VYzlfG/retained-world-report.json` 的实际加载可见性和截图；`ZNyMrV/profile/ground-retained-audit.json` 的存档/草稿保留；`rBgZJn/shortcuts-package-report.json` 的原生全屏、对话、暂停恢复和退出。
- 同目录 `rBgZJn/retained-world-report.json` 是开发构建；不能与其中的成品 shortcuts 报告混用。早期 `ZNyMrV` 还没有更强的 loadingCapture 断言，加载像素证据应引用后来的 VYzlfG。
- F2 测试直接 emit 原生处理器/发送 DOM 脚本事件；真实键盘到窗口焦点的整条路径未实测。它证明界面能被调起，不证明玩家反馈的全部失效条件已消除。
- headless 正常退出跳过真人确认对话；保存失败后的重试也没有在该报告触发。已有保存退出成功证据仍然有效，范围不能扩大。
- 本轮 21 项候选/预览控制/自动采用逻辑测试通过；其中部分测试就是验证落回 manual 的现状，所以通过不等于满足完整全自动要求。
- 三个状态断点的可重放证据在 `test-results/fb02-closure-audit-20260912/reproduce.mjs` 与 `reproduction.json`。内容是现有纯函数/真实调度函数的隔离执行，不启动应用。

## 必须补齐的开发与验收

这些都是既有要求或其正常返回/恢复逻辑，不应继续作为可忽略的“后续建议”。用户已经明确的权限和世界对象不再重复询问。

1. **工作台保持世界**：首条发送、附件导入、粘贴、流式回复和产物出现期间，世界保持可见且绑定正确。只继承当前世界上下文，保留普通历史会话的文件隔离。
2. **结果卡与完整全自动一起贯通**：绑定确切世界、会话、任务和候选；检查完成即可在对话中看到结果。全自动模式无需额外勾选、找标签或手动采用；手动模式可从此直接预览/采用/返回，状态在重进会话后仍能恢复。
3. **原预览按钮完整验证**：从原检查记录按钮到真实预览，退出不改变正式世界；采用后保存并重开仍在；旧候选和切世界不误应用；失败有可继续路径。
4. **设置与维护恢复**：设置返回同一游玩上下文且不改长期模式偏好；维护让路后空闲恢复，失败/取消/退出不损害旧存档，不永久锁死自动升级。
5. **完成二级入口**：稳定提供选择世界、创建后到工作台、仅对话生成三条实际可达路径，并有返回与取消。
6. **统一成品验收**：上述实现完成后，从最终 ZIP、旧世界副本和新会话开始跑连续流程；包括首次启动、重启、失败恢复和正确存档。真实模型流程使用玩家实际选中的模型、思考强度与配置，不增加用户未要求的 token/轮次/时长限制。

整体应形成：

`选择/创建世界 → 世界保持可见 → 对话创作 → 检查 → 自动采用或可操作结果卡 → 试玩/返回 → 保存重开`

其中每次失败、取消、设置跳转和异步完成都要能回到明确状态。当前最明显的断口在“发送 → 世界保持”和“检查完成 → 用户看到并使用结果”。

本轮交付的是完整审计和纠正后的开发清单，没有把尚未修复的断点标成完成。原始反馈与历史验证记录保留，当前状态以本文件为准。
