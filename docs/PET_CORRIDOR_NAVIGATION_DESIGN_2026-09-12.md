# 宠物平地通道与转身设计提案

当前行为组件使用竖直 CylinderShape3D：普通犬半径 0.75 米、高 0.77 米，白博美半径 0.36 米、高 0.48 米。普通犬的保守圆直径为 1.50 米，而现有门洞约 1.40 米；该组合应继续被物理碰撞拒绝，不能通过缩小碰撞、传送或把穿墙当作跟随成功。原生恢复检查已经覆盖 `PET_RESTORE_OVERLAP`、玩家/宠物重叠、倾斜/缩放和未知形状拒绝，作为本轮回归基线。

## 建议的最小范围

第一阶段只覆盖平整地面、静态直门和有转身空间的 L 通道。宠物继续由 `CharacterBody3D.move_and_slide()` 移动，跟随逻辑保持加速度、停止距离和碰撞响应；不新增瞬移、路径搜索或绕障碍猜测。

普通犬优先使用包络 BoxShape3D 表达长向外观，尺寸必须从最终 `motionEnvelope` 重新计算，并在实体根保持固定朝向约定。白博美可继续使用圆柱，或在证明收益后使用更小的长向盒体；不得把普通犬的盒体直接套给博美。所有尺寸应带来源 manifest 的解析包络和明确数值余量。

转身不是单纯比较门洞宽度：在直门前要验证沿门法线移动时的盒体碰撞，在 L 通道拐角要验证角色自身绕 Y 旋转时的扫掠包络。转角半径不足时应停下并保留位置；有足够转身空间时才允许通过。测试应实际放置门柱和墙体，以 `move_and_slide` 运行固定物理帧，读取实际位置/碰撞，不使用 AABB 近似替代物理结果。

## 恢复与持久化

保存的 position/yaw、following、appearanceKey 和 interactionCount 必须保持原 JSON 合同。恢复前后用实际 shape query 检查玩家、另一只宠物、门柱和墙体；任何重叠返回 `PET_RESTORE_OVERLAP`，不自动挪动位置。Box/Cylinder 切换后若形状不同，恢复报告应记录形状类型和最终尺寸，不能只比较外观名称。

## 测试矩阵（待实现）

1. 普通犬在 1.40 米直门前：应停下，门柱无穿透，position 保持在门外。
2. 白博美在同一门洞：若实际尺寸允许，应正常通过；否则明确停下，不把失败归因于渲染。
3. 宽直门：两种宠物沿平地通过，速度和停止距离仍由现有跟随逻辑决定。
4. L 通道宽度分别低于和高于转身扫掠界：窄通道停下，宽通道完成一次真实 Y 旋转并继续移动。
5. 拐角门柱、另一只宠物和玩家互相阻挡：运行时无穿透，恢复时 shape query 同样拒绝重叠状态。
6. 保存、冷启动重开：position/yaw/appearance/following/count 和碰撞形状逐字段一致。

本提案不改变产品权限、包格式、寻路能力或窗口输入。实现前需要确认长向盒体的轴向与最终尺寸；确认后再在独立 Godot 夹具中执行上述矩阵。任何只读 AABB 或静态几何计算只能作为预检，不能宣称已经通过真实通道。
