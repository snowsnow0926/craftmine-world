# DeepSeek 普通玩家测试与修复

用户授权读取本机附件指定的模型和 API Key，在应用中按真实玩家流程测试并修复发现的问题。
附件仅在测试控制进程内读取，凭据由独立客户端原有 Secret Store 保存；不写入源码、
报告、命令行或发行包。输出脱敏，保留失败记录。

## 原配置与已确认问题

实际玩家原配置：上下文 500,000、最大输出 384,000、最高思考，图像与文档输入已开启。
附件指定 `deepseek-v4.1-flash` 和官方 API 端点。账号 `/models` 只列出 `deepseek-flash`
及 `deepseek-v4-pro`，未列出完整 ID；这不直接证明完整 ID 不可用，须由普通请求验证，
不能自行换名并宣称同一模型验收。

原错误来自过早压缩与本地任务策略叠加：输入、384K 输出预留、工具余量整体达到窗口
85% 就压缩，约 39K 完整估算输入即触发；8 次后本地拒绝继续。只读复制原失败档案后，
在 preview.24 正常 Composer 中发送继续，再次得到相同错误，保留为失败基线。

## 本轮修复

- 保持玩家配置和实际请求输出额度，85% 提前线改为作用于扣除输出和工具余量后的输入
  容量。500K/384K 配置对应输入容量 113,952、开始整理的估算输入阈值 96,859。
- 界面区分上次请求的窗口剩余比例与当前配置的输出／输入预留，不声称配置推算为实时占用。
- 新普通任务不再默认限制累计请求、压缩次数或整轮时长，继续记录用量并保留取消与单次容量限制。
- 不擅自改写旧任务限额。提供明确玩家动作，审计解除旧任务的本地次数／时长限制，保留
  token 预算、草稿、计数与失败历史，然后按原任务恢复流程继续。

## 验收流程

使用独立 offscreen 应用与独立数据目录；不用真实鼠标／键盘，不置前或操作用户窗口。
先在原奥格瑞玛大帐篷和原对话副本上测试恢复与角色制作，再验证检查、应用、实际画面、
走近／互动、多轮修改和保存冷开。按真实目标处理澄清；不把动态玩法改成静态摆设。
遇到模型 ID 或服务能力错误保留原始证据，不偷偷切模型或关闭玩家开启的能力。

`D:/cm-deepseek-player/test-results/desktop-native-product-oUgGvo/`。
这是各文件时间点复制加两份 SQLite 在线备份，不冒充暂停应用后的全档案一致快照。
原世界、会话、任务与 3/6 探索进度保留；原用户资料未被测试改写。

后续实际模型、采用、游玩、冷开和 Windows 交付结果在执行后追加，不以单元测试代替。
