# 沉浸式造物世界开发记录（2026-09-11）

本轮按[整体实施计划](OVERALL_DEVELOPMENT_PLAN_2026-09-11.md)推进 P0–P7，使用 Codex 子 agent 与独立工作树。开发基线为 e61bae85；统一验收代码为 a6e0e224。下述结果来自本轮实际执行，历史测试不叠加计数。

## 本轮完成的产品链路

- 官方空白3D造物底座 creation-sandbox：真实网格、碰撞、准星射线、稳定实体身份，以及树、岩石、宝箱、门和标记。
- 主进程捕获“这里／这个对象”，按项目、会话、世界、正式构建和运行实例绑定；模型只能引用opaque captureId，不能自己提交目标快照证明身份。
- 生产源码服务支持放置、修改、有限复制、改变时间与源码机关，实际Rust分页读取、CAS写入、完整哈希、丢回复恢复及同任务连续操作。新任务源码重新编号时，只接受核心证明的完整相同正式源码。
- 后台检查通过后，可依据玩家事先勾选且仍有效的授权自动采用；也保留原有预览／手动采用入口。采用重新保存最新玩家进度，不展示中间预览；撤权、取消、来源变化和失败均保留正式世界。
- 采用后任务释放写租约，模型转为只读收尾，不会因读取已完成任务而报错或重新获取写权限。
- 顺序机关与普通GDScript双按机关均真实可玩；后者使用自定义规则状态，已验证跨进程保留部分进度后继续完成。脚本哈希错误时实际引擎拒绝。
- 保存重开、再次创造、复制世界后独立采用并继续编辑、完整备份恢复全部接通；保留位置、背包、门、规则与宝箱一次奖励。
- 五个底座均进入实际分发资源。中文HUD和Label3D使用保留OFL许可的完整30890字符字库，中文及生僻字不再显示方框。

## 本轮发现并修复的问题

早先“没有Godot”的记录不准确，固定4.7.2引擎实际上在缓存中。此前纯投影测试不能证明玩法，已移除伪造目标快照和重复的纯函数状态机；旧绘图层只在启动时读取，正式内容更新必须经候选采用。

还修复了单页读取超过Rust上限、将最初baseBuild误当正式build、模型自行填写目标、候选采用把玩家恢复进新碰撞体、世界边缘错误拒绝创造、自动采用私有路由参数错误，以及采用后任务上下文仍要求写租约的问题。

默认导出会转换脚本文本，使成品中的动态规则SHA校验失败。可信Web与Windows预设现保留源码文本和JSON，校验没有放宽，篡改规则依旧拒绝。世界操作日志从64条扩到4096条并保留全部重放历史，日志上限4MiB；这仍是明确的Alpha资源边界，不宣称无限容量。

## 2026-09-11 沉浸模式改造记录

根据玩家反馈，本次把沉浸世界提升为应用启动时的一级入口，与工作台游戏创造并列显示。沉浸模式进入后隐藏世界页眉、模式栏和常驻侧栏，3D 世界占满客户端；F2 呼出轻量对话，Shift+F2 呼出完整工作台，两个窗口均以居中浮层覆盖在原有世界上，不改变世界尺寸、位置或运行任务。任务打开文件和评审标签时，仍由沉浸世界保持前台，返回工作台后恢复原标签。

游玩时玩家点击画布后隐藏鼠标；暂停、失焦、鼠标锁定释放和打开创作浮层时恢复鼠标。Godot 与 Web 控制器均释放暂停状态下的捕获，后台测试不申请 Pointer Lock。

验证结果：24 项桌面纯逻辑测试通过，14 项 Escape/全屏策略测试通过，9 项光标与暂停测试通过，沉浸渲染 headless 检查通过，桌面 TypeScript 检查通过。原生 Electron 叠放夹具在独立窗口和测试目录中验证了同一世界尺寸下的 UI 叠放；未进行真实鼠标键盘或前台窗口验收。
