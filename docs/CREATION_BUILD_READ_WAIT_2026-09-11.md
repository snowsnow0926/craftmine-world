# NB5：模型作业读取的有界等待

日期：2026-09-11。原因：真实 CA01 记录中，模型在 Godot 导入/导出期间重复调用 `godot_build_read`，消耗了大量无新信息的请求。

生产插件在创建工具时固定注入 `buildReadWaitMs: 30000`；模型不能传入或修改等待时间。仅模型读取工具每 500 毫秒读取同一个核心作业，作业到 passed/failed/cancelled/interrupted/blocked 立即返回。每次读取前后检查活动任务、选中世界和不可变作业身份；核心请求最多 5 秒且等待总窗有界，任务取消在待决请求期间也能被及时发现。不会启动、恢复或重复入队任何引擎工作。

返回值保留实际核心状态，附加实际 `waitedMs`、最后一次成功读取距现在的 `lastReadAgeMs`、`waitReason`（terminal/deadline/read-timeout）。到期或后续读取超时时返回最后一次真实观察并明确其年龄，不捏造通过。首次核心读取超时则报错。直接 UI 仍使用原来的即时核心读取；普通工具夹具未配置等待时保持原行为。

测试覆盖实际终态、时限、零等待、取消、世界切换、作业身份改变、无响应核心、绑定参数被修改、真实 500 毫秒等待及打包后文件完整性。前后真实模型请求数由总控用同一 CA01 另行对照；本实现不自行宣称 token 或时延改善幅度。
