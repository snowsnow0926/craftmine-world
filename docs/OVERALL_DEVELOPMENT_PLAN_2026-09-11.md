# Craftmine World 沉浸式造物世界首版整体实施计划

版本：2.0，2026-09-11。执行依据：用户要求生成中文整体计划并持续开发直至计划完成。基线：e61bae85；产品版本仍为 0.14.4-preview.9。

## 一、交付目标与范围

完成 Windows 单人创作 Alpha 的真实闭环：创建空白 **3D 造物世界** → 打字或按住说话提出愿望 → 固定“这里／这个对象”的真实目标 → 修改持久源码 → 后台构建检查 → 预览并采用 → 游玩新增机关 → 保存退出 → 重开继续创造 → 导出并在第二世界恢复。

沿用既有沉浸外壳、语音草稿、Rust 源码与版本事务、Godot 执行器、候选协调器和备份复用服务。主世界使用 creation-sandbox；第一人称、俯视、横版、采矿四种已有底座保持原功能并分别回归。二维坐标投影不能充当主世界完成证据。

本实施计划覆盖下表 P0–P7。既有长期专项继续保留：多人、社区、经济、云部署、原生迁移、所有底座同等造物能力，以及大规模模型策略优化不混入本次 Alpha 完成定义。真实玩家体验和真实麦克风测量保留独立记录，自动检查不冒充玩家评测。不得因为暂时缺少依赖而将必须的引擎验证改成仅静态验证。

## 二、重新核实的基线

已存在：沉浸面板和语音代码、造物操作编译器、初步绘图、目标选择纯函数、候选与存档基础。实质缺口：主世界未完整登记；模型能提交未经宿主证明的目标快照；文件读取超出 Rust 单页上限；绘图器缺少碰撞、真实交互与进度；纯函数测试不能证明运行；曾因只检查 PATH 而误记 Godot 不可用。

已找到中断工作树里的完整造物底座、目标 UI 和宿主绑定初稿。恢复时只读旧目录，在新的独立工作树审计合并，不覆盖原始工作。已有用户文档、反馈原话和历史测试证据保留。

## 四、完整故事与失败验收

1. 生产创建链生成空白主世界，没有测试专用预摆树或机关。
2. 固定宿主采样的地面落点，放置树，真实实例观察到稳定ID和碰撞体。
3. 固定树目标改为两倍尺寸，采用后ID不变；错误世界和过期请求不写入。
4. 有限复制、改变时间；后台任务期间改变玩家位置和物品进度，采用时保留最新值。
5. 新增门和标记，再新增GDScript顺序规则；错误顺序不开门，正确顺序只完成一次，直接交互不能绕过。
6. 领取宝箱，保存退出，全新进程加载；树、尺寸、门、规则、背包和奖励不丢失不重复。
7. 继续创建另一对象；复制或备份到第二世界，身份独立，新规则仍能加载。
8. 注入源码冲突、无效脚本、取消、丢回复和恢复失败；正式内容与已确认存档可恢复。

## 五、证据和状态

每个出口记录命令、版本、源码身份、独立数据目录、原始输出和结果。静态/纯逻辑、真实Godot、真实Rust RPC、host/UI、真实模型和真实玩家分别计数。skip不算通过；接口存在、读取同一JSON两次、模拟开门纯函数都不能证明端到端完成。

DEVELOPMENT_STATUS.json增加本轮状态并保留历史；中文开发记录修正早先不准确的完成描述。模型首次成功、自修复、人工改写、环境不可用分别登记；失败保留分母，没有真实成本或耗时则为未知。

## 六、执行纪律与完成条件

测试不得抢占鼠标、发送真实鼠标键盘、请求Pointer Lock、激活窗口或操控用户浏览器。浏览器使用独立headless进程和数据目录，初始化禁用requestPointerLock；以HTTP、页面脚本和逻辑接口验证，不使用Playwright mouse/keyboard/click/fill。Godot使用--headless和独立用户目录，隐藏启动。

不自动发布公网、不替换正在使用的安装、不输出密钥、不购买服务。本地构建、测试、修复、隔离备份恢复和本地合并在授权范围内持续推进。容量中断从状态表继续，不以部分测试通过或用时较长宣布完成。

当前：P0进行中；P1/P2并行恢复与开发；P3–P7按依赖继续。
