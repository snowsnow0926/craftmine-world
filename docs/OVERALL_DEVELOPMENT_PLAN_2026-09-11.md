# Craftmine World 整体开发计划书

版本：1.0（2026-09-11）  
适用范围：Windows 单人创作 Alpha；以当前 `master` 实际代码和证据为准。

## 一、目标与交付边界

最终交付一条可重复的本地创作闭环：玩家进入空白造物世界，用文字或按住说话提出愿望，系统绑定“这里/这个对象”的真实上下文，调用已有能力或开发新规则，经过检查后应用到世界；保存、退出、重开、复用后对象、玩法和进度仍正确。工作台与沉浸模式共用世界、会话、任务、候选和历史。

本计划不把方案文档、单次模型回复、固定演示夹具或接口存在当成交付；多人、公开社区、交易、云服务和原生运行迁移属于后续阶段，除非另立验收并满足依赖。

## 二、现状基线

- Alpha 0.5–0.8 已完成真实代码生成、模块记忆、连续创作与失败修复、图片/GLB 导入及跨项目复用。
- Godot 多底座已具备第一人称、俯视、横版和采矿方向的工程与状态基础；M5.1 接口和沉浸式界面已接入，空白世界实体及持久操作正在扩展。
- 已有候选检查、版本/进度保存、作品包、素材引用、暂停与语音转写基础；真实模型完整故事和 Godot 实机 headless 验收仍需完成。
- `DEVELOPMENT_STATUS.json` 与各历史报告可能滞后，开发时以当前代码、测试输出、提交哈希和运行回执重新核对，并保留原始记录。

## 四、核心验收故事

1. 新玩家创建空白造物世界并进入沉浸模式。
2. 看向地面说“在这里种一棵树”，树出现在真实落点并可碰撞。
3. 说“把这棵树变大一倍”，系统使用同一实体 ID，重开后尺寸仍正确。
4. 提出“按顺序触碰三块石头后开门”等新规则；后台构建、检查并应用，原有进度保留。
5. 完成互动，保存退出再重开；继续创造时树、机关、背包、任务和历史均一致。
6. 将世界/模块导出到第二项目，验证依赖、版本、卸载和回退。

## 五、统一技术与数据原则

所有操作绑定 `worldId`、实例、任务、会话、构建和操作 ID；目标使用实体 ID、资源版本、采样坐标/表面与必要状态，不能用显示名或旧快照猜测。永久创作进入候选、检查和版本事务；临时环境状态、个人设置和游玩进度分别归属。应用前重新读取最新正式进度，失败自动保留旧版本。模型不能填写检查结果、授权或最终回执。

能力按 L0 数据/场景、L1 玩法脚本、L2 可复用扩展、L3 受控底层组件、L4 策略实验管理；每层都需依赖锁、版本、检查和回退。接口以现有 Rust/VM、Godot base contract、创作包和素材库契约为准，不另起同义数据结构。

## 六、测试与安全纪律

- 浏览器验收只用独立 headless 进程和独立数据目录，初始化禁用 `requestPointerLock`；不得使用真实鼠标、键盘、Pointer Lock、抢焦点或可见测试窗口。
- 不运行历史输入操作入口 `tests/browser.mjs`、`tests/modules-browser.mjs`，除非用户另行明确要求。
- 每项验收记录版本、底座、引擎、数据目录、源码/资源哈希、模型与工具版本、命令、原始输出和失败分母；接口通过不等于玩法通过。
- 测试覆盖取消、超时、重复请求、目标变化、崩溃恢复、版本不兼容、重复奖励、备份导入和卸载回退；不因 UI 文案或固定夹具记为成功。
- 普通开发可并行使用 Codex 子 agent；总控负责依赖顺序、合并、回归和中文记录。每次合并后运行受影响测试并更新状态。

## 七、外部阻塞处理

Godot 未安装、实机运行器、模型额度、供应商限制、签名/部署、账号或服务不可用时，先完成源码、契约、模拟/静态检查和可复现实验；在报告中标记“环境阻塞”，给出所需版本、命令和恢复步骤。不得购买服务、读取密钥正文、上传作品、发布公网或删除历史工作树来绕过阻塞。阻塞解除后从原证据点继续，不重写已完成记录。

## 八、完成定义与持续更新

个人 Windows 创作 Alpha 仅在 P0、IW0–IW3、GD0–GD2、AI0–AI2 和 M5 的出口全部通过后宣布完成；每个未支持能力、人工介入和外部阻塞都保留在交付报告。每轮开发同步更新本文件引用的状态表、开发记录、测试证据和提交哈希，确保计划与实际实现一致。
