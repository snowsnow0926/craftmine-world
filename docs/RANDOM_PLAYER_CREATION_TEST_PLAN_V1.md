# Craftmine World：随机真实玩家连续创作测试方案 v1

日期：2026-09-11  
状态：方案设计，尚未运行；无本轮测试成绩、无模型调用授权、无源码或成品修改。  
对象：craftmine world / 最中幻想的同一份冻结 Windows 成品。  
目标：玩家在同一世界中边玩边创造、改主意、复用、保存和继续；验证实际游戏效果、身份与进度，而不是只验证模型会说“完成”。

## 1. 本轮回答什么问题

核心问题是：一个不懂源码、会省略指代、会觉得不好看、会临时改主意的玩家，是否能持续把自己的世界改得更符合想法，且之前的劳动不丢失？

本方案不是随机向模型发送几十条互不相关的题目，也不是连续注入已写好的游戏结果。它是一场有记忆、受世界实际状态约束的随机故事。

三种结论必须分开：

1. **核心承诺是否可靠**：放置、选中修改、有限复制、常规编辑、实际采用、保存重开等。
2. **组合玩法能走多远**：采集、再生、奖励、机关、带行为复用等。不能因为引擎理论上支持就判定产品已承诺。
3. **开放想法如何处理**：例如会躲人的树、跟随宝箱。做出来是探索成果；明确说明限制是合理边界；声称成功但实际没做出来是错误。

这里的“真实”是：真实成品、真实模型请求、真实生成工程、真实引擎和真实存储。模拟玩家不等于真人用户实验；offscreen/页面脚本验证不等于真人鼠标、键盘、手感、语音和可见桌面验收。

## 2. 执行前冻结与授权

### 2.1 成品和环境

参考的是此前审阅的 preview.11，以及源码快照 `7f815914634fe862a48857f228e1116b7cf9d7bf`。执行当天先识别实际最新成品，再冻结，不假定此快照一直最新。

冻结记录至少包括：

- 成品版本、构建源码提交、完整文件清单与 SHA-256；测试前后各校验一次。
- 真正运行的 EXE、ASAR、插件、Rust 服务、Godot 及模板身份；不混用工作树的最新脚本或旧缓存。
- 操作系统、CPU/GPU、内存、窗口/渲染方式与独立测试档案。
- 供应商、精确模型 ID、思考配置、上下文、工具集、自动采用策略、产品内部自动修复策略。
- 测试驱动、断言、卡牌库、随机算法和种子的版本；它们不提供生成结果。
- 产品自己的任务请求、压缩和时限限制；不能为跑过测试偷偷取消限制。

只创建独立测试档案和官方空白世界，不使用用户个人世界、密钥目录或安装目录作为可写试验区。凭据只通过已有受保护机制读取；证据中不得包含密钥。

本文件中的数值是建议的停止上限，不是已经授权的开销或预期耗时。历史批次的额度不能视为本轮可重新使用的授权。

| 项目 | 轻量探索轮 | 标准连续轮 |
|---|---:|---:|
| 玩家步骤上限（对话和游玩均计） | 12 | 24 |
| 全产品模型请求尝试上限 | 40 | 80 |
| 单个常规目标请求尝试上限 | 8 | 8 |
| 单个预先标注的复杂目标上限 | 12，仍受总上限约束 | 12，仍受总上限约束 |
| 单目标玩家纠正机会 | 最多 1 次 | 最多 1 次 |
| 全轮墙钟停止上限 | 45 分钟 | 90 分钟 |
| 需求卡生成方式 | 本地种子抽卡，不调用模型 | 本地种子抽卡，不调用模型 |

产品内的生成、规划、自动修复、独立模型评审和压缩若实际发起请求，都计入总账；失败重试也计入。一个用户目标内的请求循环不是一次模型请求。

框架不得额外无限重试。产品内原有修复策略在运行前记录并冻结，实际修复次数单列；若产品支持公开的修复次数配置，可另选“最多两次”作为本轮固定策略，但不得通过修改成品实现。

总预算作用于整个 run，不能通过新任务、新会话、复制世界或重启清零。产品内部更小的额度/时限先到先停；正常新任务可以继续同一故事，但必须真实记录草稿是否继承，不能伪造接续。没有明确的当轮授权额度时，仅完成驱动准备和零模型预检，真实模型部分标记未运行。

结束预算前不追加高成本需求；即使已耗尽请求额度，仍在墙钟和安全范围内记录现状、保存证据，完成无需模型的收尾。未做到的步骤标记未运行，不编造结果。

## 3. 三个角色及信息隔离

### 3.1 模拟玩家

知道：画面、对话、自己实际做过的事情、自己看到或听到的反馈、自己的偏好。  
不知道：源码、数据库、工具内部参数、断言、对象后台 ID、预设答案及开发修复方案。

玩家只把自然语言和正常的选择/游玩动作传给产品。不把“修改 creation.json”“保证 expectedHeadOid 正确”之类内部提示写进玩家台词。

### 3.2 产品 Agent

必须使用成品内真实创作入口、真实模型和原本的工具/检查/采用链。测试人员不替它写 GDScript、预先实现目标效果、直接更新场景 JSON、数据库或背包数值。

产品按正常授权能读取自己的工程和运行状态，这正是被测能力；但不能读取测试预期结果文件或未来卡牌。

### 3.3 裁判与测试驱动

裁判可只读正式运行状态、操作回执和持久化证据，并与画面及实际行为交叉核对。断言在提交需求前冻结，产品输出不能改低验收标准。

测试编排可使用 Codex 子 agent 分工；同一世界的写操作必须串行。产品自身既有的 PI 运行时继续正常工作，不等于通过 PI 另派测试子 agent。角色隔离不保证统计独立，只降低答案泄漏。

## 4. 玩家人物设定

默认人物：**一个随性的新手，最初只想做个小营地，后来把蓝树林改成一个奇怪的小游乐场。**

他不关心引擎和代码；喜欢蓝色；觉得东西不好看会改主意；经常说“这棵”“刚才那个”；会试着多点一次宝箱；生成时会走开继续采集；退出后期待自己的劳动还在。

随机人物可从四个独立档案中选一个。不要在同一轮中突然变成另外一个人。

| 人物 | 稳定偏好 | 容易提出的念头 |
|---|---|---|
| 装饰型 | 蓝色、整齐、不要挡路 | 改色、改高矮、摆成一排、改变布局 |
| 收集型 | 想积累东西，不想白忙 | 掉落、宝箱、再生、领奖、保存 |
| 好奇型 | 想知道世界还会怎样 | 给对象加行为、组合机关、带功能复制 |
| 急性子 | 不喜欢等，容易改变主意 | 生成中走开、取消、重复询问、重开 |

人物差异只是本方案的测试设计，不代表已经调查得到的真实用户比例。

## 5. 一条可以直接执行的 24 步示例故事

这是公开开发样例，不是保密测试集。“蓝色”“1.5 倍”“8 秒”等可以在运行开始前用种子替换成记录过的参数。

类型：**对话**必须从正常产品对话入口发送；**游玩**是产品已有的交互/编辑/保存路径，不必请求模型。

| 步骤 | 类型与玩家台词/动作 | 只给裁判看的检查重点 |
|---|---|---|
| 01 | 对话，指向空地：“这儿太空了，先在这里给我放棵树吧。” | 正式世界新增树；落点合理；记录实际对象身份和初始外观。 |
| 02 | 对话：“这棵再长高一半吧，别变胖。” | 相对于 01 的高度改变，宽度保持；解释含糊时可以正常澄清，不私自用测试答案补齐。 |
| 03 | 对话：“不行，太普通了，整棵改成蓝色。” | 修改的是同一实例，不是原地叠加另一棵；保留高度。 |
| 04 | 对话：“旁边再来两棵同样的，稍微隔开。” | 只增加两个新实例；不重叠；复制的是已采用版本。 |
| 05 | 游玩选择右边副本后对话：“只有我选的这一棵改成绿色，另外两棵别动。” | 真实目标选择正确；其他实例颜色、尺寸和状态不变。 |
| 06 | 游玩，通过已有撤销入口：“还是蓝色好看，撤销刚才那次。” | 只撤销 05；不删树、不回滚整个场景或玩家进度；直接 UI 操作的模型调用单列。 |
| 07 | 选择原树后对话：“这棵能不能砍？砍掉给我 3 个木头。” | 真实生成并采用行为；攻击/交互后树和背包发生一致变化。 |
| 08 | 游玩，实际砍树和拾取。 | 木材变化来自真实行为；不能直接给背包赋值；记录原树及奖励事件。 |
| 09 | 对话：“砍完空了不好看，让它 8 秒后重新长回来。” | 作用于原树的行为；时间、状态和再生不是单纯显示一句话。 |
| 10 | 游玩，砍掉→等待→再砍；正常保存一次。 | 验证至少两个周期；一次砍伐的奖励只给一次；等待使用实际游戏时间。 |
| 11 | 对话：“这个挺好，旁边再来一棵，也要能砍、会长回来。” | **探索/已知边界**：完整行为复制，不只是外观复制。明确拒绝不算造物成功；假称完整复制算错误。 |
| 12 | 游玩，两棵轮流砍，并观察一棵倒下时另一棵。 | 仅在 11 成功时执行；实例状态、计时、奖励独立。若 11 没成功，本步标记依赖阻塞，不用夹具造一棵。 |
| 13 | 对话：“树旁放个宝箱，第一次打开给 5 个木头，以后就不给了。” | 箱子可交互；一次性奖励是真实持久状态。 |
| 14 | 游玩，打开两次，再走开回来打开一次。 | 累计只给一次奖励；不是每次打开或离开范围都重置。 |
| 15 | 对话：“把天色改成傍晚，想在这里露营。” | 场景表现改变；已存在对象和行为保留；不要求裁判私自规定精确色号。 |
| 16 | 在 15 仍处理时继续游玩，采集原树并移动位置。 | **关键并发窗口**：新增背包和位置变化在采用后保留；如果采用过快未覆盖并发，标记未覆盖，不假造。 |
| 17 | 对话：“把宝箱挪到树另一边吧，我已经领过的奖励别重置。” | 真实移动同一箱子；奖励状态、身份和其他进度保持。 |
| 18 | 游玩，保存、正常退出、结束该测试实例，再冷启动打开同一世界。 | 从实际存储恢复；再打开箱子不重复领奖；对象、背包、规则保留；计时按产品实际约定核对。 |
| 19 | 对话：“加个小机关吧，先碰左边的标记，再碰右边的，门才打开。” | **组合玩法**：需生成真实门和标记关系；不能只做装饰或显示‘已开门’。 |
| 20 | 游玩，先故意按反顺序，再按正确顺序。 | 错序不通过、正序可通行；门体/碰撞实际改变；已知具体时序在需求提交前确定。 |
| 21 | 指代不够明确地对话：“把刚才那棵再变小一点，颜色留着。” | 系统是否利用真实焦点/最近操作或合理询问；裁判不能把模糊句强行对应隐藏 ID。玩家可答一次‘我现在选中的这棵’。 |
| 22 | 游玩，保存并通过已有入口复制整个世界，打开副本。 | 副本有独立世界、源码、会话和运行身份；状态语义符合产品约定。 |
| 23 | 在副本里对话：“这个副本的蓝树都改成红色，原来的世界别改。” | 副本的批量/连续修改；原世界不受影响；未完成目标不能靠直接源码补齐。 |
| 24 | 游玩，分别保存、关闭、重开原世界和副本，再试一次采集和宝箱。 | 世界隔离、角色背包、一次性奖励、行为及对象身份都可核对；新的任务确实发往当前世界。 |

### 5.1 因果失败处理

后续只引用实际成功且玩家知道的对象。07 未做成就不能假装已经有木头；11 只复制了外观就不能把 12 记为采集成功。

失败后玩家最多给一次自然反馈，例如：“它确实长得一样，但砍它没有木头啊。”反馈来自实际观察，不附带源码修复办法。仍失败则该目标结束；依赖步骤标记 blocked_dependency。可继续不依赖失败功能的剩余故事，不重置整个世界来掩盖失败。

### 5.2 轻量版本

用 01–10 加一次保存冷重开和一次“重开后继续修改”，形成 12 步。预算是上限，不保证能完成全部步骤。轻量版不覆盖奖励箱、完整行为复制、机关或世界副本；不得用其结果替代完整故事。

## 6. 随机化：有因果，不是乱扔题目

### 6.1 随机种子

每轮记录一个种子，例如 `20260911`。使用明确版本的伪随机算法和稳定的卡牌顺序；种子、抽样序号、候选卡、条件排除原因、抽中卡、参数及实际台词全部记入日志。

同一种子只能复现相同输入/观察条件下的抽牌策略。模型响应、实时世界、网络和时间都可能改变后续分支，所以种子不是完整确定性重放保证；还必须保存实际交互轨迹。

每轮冻结：人物、主题、颜色参数、数量范围、目标选择策略、预算、卡牌版本、基线验收范围和允许的随机事件。

### 6.2 抽牌权重（建议设计值）

| 类别 | 权重 | 示例 |
|---|---:|---|
| 修改已有对象 | 35% | 高一点、只改这一棵、保持其他属性 |
| 增加行为 | 20% | 掉落、再生、一次性奖励、互动 |
| 空间与组合 | 15% | 复制、搬位置、排一列、把机关连起来 |
| 改主意与纠正 | 10% | 算了、撤销、换目标、只改其中一个 |
| 实际游玩和生命周期 | 10% | 采集、反复互动、保存、重开 |
| 出乎意料的创作 | 10% | 会躲人的树、跟随宝箱、恶作剧门 |

这是条件权重，不是必须实现的样本比例。先按真实世界计算可用卡，再按权重归一化抽取；日志保留被排除卡及原因。不能因为某类题容易失败而私下减小权重或删除它。

约束：不要连续超过三个只改外观的目标；每个阶段至少一次实际玩法交互。无论怎么抽，都保留“修改指定对象”“带进度采用”“保存重开”“世界副本隔离”锚点。若前置失败，锚点如实阻塞，不填入答案。

### 6.3 动态世界记忆

驱动维护两份互不混用的记忆：

- 玩家记忆：看见什么、想要什么、讨厌什么、指过什么、哪些反馈是真实看到的。
- 裁判账本：世界/构建/实例 ID、源码身份、状态、操作回执、存档和期望变化。

玩家可见名字和实际选择可以经正常产品上下文传给 Agent；测试内部 ID 对照表不能注入自然语言。对象被删除或功能失败时，从玩家可选对象里更新，但在失败日志中保留历史。

### 6.4 候选台词库

#### 普通但真实的念头

- “太高了，看着像电线杆，矮一点。”
- “只改我选的这个，后面那个别跟着变。”
- “这俩靠得太近了，中间给我留条能走的路。”
- “我还是喜欢刚才的颜色，其他改动保留。”
- “摆成一排吧，不要挡住箱子。”
- “这块石头不想要了，删掉，树和机关留着。”

最后一条是删除依赖的边界探索；已有规则时安全拒绝和删除成功要分开记录，不能认定所有删除都已是承诺能力。

#### 在游玩中想到的念头

- “采一次太慢，改成每次掉 4 个。”
- “别把我已经攒的木头清掉啊。”
- “树都砍光有点秃，过一会儿长回来。”
- “这个箱子我都领过了，别让我刷无限奖励。”
- “这个机关开了以后就保持开着，重新进来也一样。”
- “复制一份去实验，我原来的营地别动。”

#### 突然冒出来的想法（探索，不冒充现有能力）

- “做一棵害羞的树，我走近它就往后躲。”
- “宝箱跟着我走，但是离近了就停。”
- “开门以后树叶变颜色，像庆祝一下。”
- “这棵树每砍一次换一种颜色。”
- “让我把树当弹簧，碰一下把我弹起来。”
- “把这段小机关做成一份能搬到另一个世界的玩具。”

#### 沟通与改主意

- “等等，先别做，我改主意了。”
- “不是右边，是我现在指着的这个。”
- “做完了吗？我这边看着好像没变。”
- “刚才说蓝色，现在还是绿色吧，其他不变。”
- “我先走开采点东西，你弄好告诉我。”
- “算了先保持现在这样，我保存一下。”

同一自然语言的变化不能只当字符串测试。例如“绿色”和“蓝色”都要从实际渲染/状态确认；“害羞”允许合理询问，不使用未告知玩家的动作速度作为硬断言。

## 7. 随机插入事件

每轮从前四类中预抽 1–2 个，不在发生失败后临时挑对产品有利的事件。故障注入只进单独可靠性扩展轮。

| 事件 | 实施方法 | 正确结论 |
|---|---|---|
| 生成期间走开 | 通过正常游戏动作移动和采集 | 提交时目标不被视线转移偷换；采用保留期间的新进度。 |
| 中途改主意/取消 | 使用正常取消入口；记录请求时刻和实际提交边界 | 取消在提交前被接受则不能偷偷采用；若已越过提交边界，应如实说明并提供正常恢复路径。不能把“取消晚到”一律判错。 |
| 再问一遍做完没 | 普通文字查询或公开状态入口 | 查询不应重新造两棵树；不重复提交未知结果。 |
| 换个目标说“这个” | 使用真实选择/视线，再通过对话发送 | 指代证据一致或正常澄清；不能混用之前的对象身份。 |
| 受控断网/丢回包 | 仅在独立扩展轮注入，明确范围与时间 | 记录失败来源、未知结果及恢复；不混入日常首轮成功率。 |
| 执行器或程序异常中断 | 仅隔离测试实例，不能伤及个人进程 | 保留持久状态，恢复有真实回执；不把人工数据库修复当产品恢复。 |

无法通过既有安全测试路径执行某个动作时，标记缺少驱动能力。不得临时打开可见窗口、抢鼠标或直接写状态来凑覆盖率。

## 8. 验收标准：任务意图、世界变化和进度三张账

### 8.1 需求账

每次发送前记录玩家实际说了什么、选了什么、明确要求哪些属性和保留项。将要求拆成必要项与审美项。

明确要求必须逐项核对：“复制并且也会再生”不是“复制了外观就通过”。模糊要求可以合理澄清或给出可预览方案，不能为了提高通过率自动翻译成已知模板。

### 8.2 世界账

保留请求前、候选、采用后的截图/实际运行状态；只以正式运行实例而非候选预览计造物完成。模型文本、工具成功、编译成功和画面加载成功各自只是阶段证据。

判定尽量同时满足：真实操作回执、引擎状态、实际游玩效果；外观需要截图，通行需要真实碰撞/移动验证，掉落需要真实采集事件与背包变化。测试可读取原始资料，但不能相信模型自写的“passed=true”或让生成内容替换裁判。

无法独立观察的效果标记 insufficient_evidence，不凭模型自报通过。

### 8.3 进度账

每次关键修改采样：

A. 发出需求前。  
B. 最后一次正式采用前，包含生成期间的玩家操作。  
C. 采用完成后。  
D. 保存冷重开后。

比较白名单内的语义字段，不比较整个动态 JSON 字节是否完全相同。对象和背包按稳定身份归一；保留本次允许改变的内容；动画帧、日志、计时等不做无意义的完全相等断言。

例：A 时有 3 个木头，等待期间真实采集了 3 个，B 时是 6。若本次只改天色，C/D 应保留 6，而不是退回 A 的 3。若需求明确消耗木头搭门，则按实际合法消耗计算，不一律禁止背包减少。

再生计时需明确采用实际产品约定：退出期间暂停还是计算离线经过时间。当前产品没有说明时记为契约未明，不假定其中一种为正确答案。

不可接受的严重问题包括：目标串写、原世界被副本修改、未授权的进度丢失、同一已领取奖励因无关修改重置、不确定操作无依据重复执行、检查通过冒充正式采用。发生后立即封存本轮状态；必要时停止写操作，不继续破坏现场。

## 9. 证据与度量

### 9.1 逐步日志字段

每个目标/动作记录：runId、seed、人物、步骤/目标 ID、类别、能力层、前置条件、实际台词、可见目标、正式世界/构建/实例、任务/操作 ID、前后状态、截图路径、模型原始回复、工具调用和采用回执。

时间记录至少含：提交、第一次可见反馈、模型请求区间、检查开始/结束、采用开始/结束、实际可玩、玩家验证结束。用户可感知耗时定义为“提交到目标已采用且可继续玩”，不以模型最后一个字为结束。

各阶段若并行，不能简单相加当总耗时。关闭/恢复等生命周期动作单独计时。统计给出所有样本、完成样本耗时和超时/失败数量；小样本不宣称稳定 P95 或总体用户表现。

请求与费用记录：产品生成请求、评审、压缩/其他请求、重试、已知/未知 token、缓存 token、供应商用量；请求身份去重。缺失用量和费用记 null/unknown，不记为 0。付费账单未确认时明确是估算还是未知。

人工介入分为：正常玩家选对象/采用/澄清，玩家纠正失败，工程师改代码或写数据。前两种不能与工程修复混淆。第三种出现后该原始测试不能改成自动成功。

### 9.2 两轴结论

**目标结果**：success / partial / unsupported / blocked_dependency / failed / budget_exhausted / insufficient_evidence / not_run。  
**达成方式**：first_submission / built_in_repair / clarification / player_retry / operator_repair。  
故意取消的目标另用 cancelled_intent 或 already_committed，按取消边界验收，不加入普通造物完成率。

不要强迫互相独立的属性挤入一个“通过”字段。一次目标可以是 success + built_in_repair；安全拒绝可以是 unsupported + safety_pass；视觉未确认可以是状态符合但 insufficient_evidence。

### 9.3 报告指标

- **已发出目标完成率**：最终成功目标 / 已发出的造物目标；已知能力与探索分开。不因失败、能力不足或预算耗尽移出分母；故意取消单列。
- **首轮完成率**：首次提交后，在正常产品链内完成、没有玩家纠正重试或工程介入的目标 / 同口径已发出目标；产品内修复数量另列。
- **无修复首轮完成率**：再排除依赖产品内部修复的成功，用于了解初次生成质量。
- **连续故事完成度**：计划步骤、尝试步骤、成功步骤、依赖阻塞和未运行步骤并列；不能只用已执行小部分算故事全通过。
- **数据安全**：严重错误次数，同时报告实际采用、冷重开和副本操作次数；一次小样本零错误不等于已证明长期安全。
- **成本与等待**：每个目标真实请求数、端到端耗时、修复次数及失败/超时；比较必须同成品策略、同预算和可对照工作负载。

“通过”建议用于：冻结基线承诺内的锚点都实际完成、无严重状态错误、证据完整。探索失败不必否决核心锚点，但必须在总体可用范围报告中保留。缺少环境、预算耗尽或断言证据不足时只能判部分完成，不能宣布发布验收通过。

## 10. 自动测试与真人体验边界

遵守项目 AGENTS：独立 headless/offscreen、独立数据目录、不可聚焦；初始化禁用 Pointer Lock；不发送真实鼠标键盘，不用 Playwright mouse/keyboard/click/fill，不激活窗口，不操作用户浏览器。

通过已存在的页面业务处理器、HTTP、IPC 或受限游戏动作入口，进入产品真实处理链。可以调用正常的“发消息”“选择对象”“开始交互”“保存”动作；不直接调用底层成功回调、不绕过检查采用、不设置木材数量和最终场景。

若成品缺少必要的只读观测或动作入口，先交付测试驱动缺口。需要新增入口时，应作为新版本开发、重新构建冻结后测试，不能修改已冻结包再继续使用旧 runId。任何只有开发模式才能做到的验证，不能写成成品验证。

本方案不检验真实麦克风、鼠标命中、键盘操作舒适度、窗口抢焦点或干净系统安装；这些属于另行明确的人工/环境验收。

## 11. 回放、修复与避免“越测越会”

首次运行期间不改产品代码、提示词、检查器或测试断言来让它通过。失败样本封存，修复开新版本、新 run。

保留两种回放：

1. **相同故障轨迹回归**：同需求和可比起始状态，验证已知故障；结论是已知回归。
2. **新种子/新措辞探索**：在产品冻结后形成新输入，检验不同表达和组合；不能把已用于开发的案例叫未见测试。

本方案给出的所有台词都属于公开开发样本。换颜色、换名称或改 seed 不自动变成独立保留集。真实保留集需要访问隔离、冻结时间和用途记录。

每个随机故障还可人工整理成最短复现步骤，但最短复现不能代替原始长故事，也不能删除中途失败和成本。
