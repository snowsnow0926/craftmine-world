# 宣传愿望调度：按真实依赖继续开发与验收

日期：2026-09-12。范围：裁判侧离线规划与调度提示，不启动产品、不调用模型、不证明宣传功能完成。

## 问题与行为

原规划把故事顺序直接当成依赖链，狗生成失败会阻塞后面的怪物。现将顺序与依赖分开：按原分镜顺序优先选择可运行项，失败仅阻塞依赖项；主线进入世界失败仍阻塞整条主线。

- 花草依赖已有树；宠物改名、变博美分别依赖原宠物；跟随观察依赖已经建立的行为和外观修改。
- 怪物不依赖宠物；巨大怪物依赖原怪物；尝试战斗与索要枪械依赖巨大怪物；持枪战斗依赖巨大怪物和枪械。没有原始攻击能力不会阻止索要枪械。
- 雨、驾驶、城市仍遵守各自实际前置。六组独立世界互不借用结果。
- 保存重开只需至少一个实际标为成功的愿望，返回 `preservedStepIds` 限定应检查的已有内容。失败内容不会因此被记为完成；后续正式驱动仍须验证真实保存、重开和状态证据。

## 调度输出

`nextWishStep` 保留 `status`、`stepId`，补充 `blockedSteps`，逐项记录未通过结果、未满足前置及其 ID。待运行前置也属于当前未满足条件，清单是当前快照，不是永久失败判断。

存在可运行项时返回 `PENDING`；没有可运行项但有失败或依赖缺口时返回 `DEPENDENCY_BLOCKED`；全部步骤标为通过时仅返回 `REVIEW_REQUIRED`，从不签发整组成功。部分内容保存重开通过，不能消除此前失败。

仅接受结果对象自身的真实步骤字段。未知字段不计成功；前置未满足的 `PASS` 记录为 `PASS_WITH_UNMET_DEPENDENCIES`，不能继续解锁后续。重复步骤和未知、前向依赖被拒绝。输出是调度提示，不能替代证据检查、世界身份核验或预算授权；实际驱动仍在请求前执行全局预算限制。

## 验证

入口：`npm run test:wish-evaluation`，Windows 实际运行 28 项通过。新增覆盖宠物失败后继续怪物、原有战斗能力缺失后索要枪、部分内容保存重开、伪造通过与原型属性、入口失败和非法依赖图。未运行产品模型或真实输入测试。
