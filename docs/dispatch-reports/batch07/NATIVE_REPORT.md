# 第 7 批原生验收报告

开发版和最终冻结安装包的三条原生链路均已跑通，共 62 项最终包检查。没有独立干净 Windows 环境，不能把本机隐藏进程验收写成干净系统安装验证。

## 已完成的实际链路

固定 D 示例通过正常旧世界导入进入独立测试 profile。固定测试作者使用真实 PI 会话和工具分发修改训练靶名称，交给实际 Rust/原生 Worker 检查及当前配置的 DeepSeek high 评审。这里的代码作者是固定示例，绝不计为 LLM 作者。

真实评审出现一条不合时点的意见：测试已经击破目标，但最终断言仍要求目标保留实体碰撞。原断言保持失败。新增独立“带评审提示应用”按钮，测试通过真实表单明确提交玩家决定，Rust 保存 acknowledgement 与原评审 hash。没有修改评审输出或伪造通过。

应用后，Rust 作品库真正捕获组合内容及其固定扩展；另一个世界、另一个真实 PI 会话按精确 id/version/hash 安装。安装再次经过实际机器检查、真实模型评审和玩家应用。正式游戏随后实际执行：

- 重力落地扣血、扩展吸血与按实际伤害回血。
- 射程外和射线未命中、实际命中、弹药消耗、近战范围与冷却。
- 扩展击破目标，下一次真实玩法 tick 发放一次奖励。
- 保存并完整结束 Electron，再启动确认生命、目标死亡、弹药、换弹、背包、初始化标记和扩展 calls 状态深等。
- 恢复后的 Worker 继续调用同一固定扩展，奖励不重复；玩家死亡后不能开枪。
- 显式规则记忆、真实本地备份文件导出/检查/恢复，再完整重启读取保留的状态。

主要证据位于 `native-evidence/development-report.json` 及其 `prior-attempt` 前序文件。末段记忆/备份采用零新增模型的状态续验，未重复作者、安装或玩法来制造新通过。独立 `formal-gameplay-zero-model.json` 也通过 25 项正式游戏/存档/备份检查，但它只证明固定导入玩法，不能替代作品库链证据。

实际工作台额度表单另已验通：在保留的真实超时任务上，通过 DOM requestSubmit 将累计额度设为 100，再明确解除为不限。Rust 中原 owner、1 次请求和 47,298 unknown 预估用量均保持不变；没有额外模型请求。证据为 `native-evidence/actual-budget-ui.json`，它证明 Main → 私有网关 → Rust 的真实链路，且没有把未知用量写成实际已知用量。

## 修复与保留的失败

1. **产品缺口：应用丢失新扩展。** Rust prepare 正确使用已验证扩展，commit 却使用目标世界的旧列表。现在最终存档使用相同已验证 artifact 中的精确扩展；新增持久化回归覆盖重开数据库。
2. **产品设计：评审意见必须由玩家裁决。** 默认调用依旧拒绝红评审。只有显式玩家 acknowledgement 能应用 completed/current/evidence-bound 的评审警告；机器验证、实际加载、旧版本/错误凭据拒绝均保留。重复请求改变 acknowledgement 会拒绝，已保存的红意见不改绿。
3. **真实供应商超时。** 第一条 high 评审超时，47,298 预估 token 保留为 unknown，不清零。退出前未完成的固定作者 turn 变为 interrupted，旧验证不能重评；这是正确拒绝。之后修正固定作者提交后正常结束的测试生命周期。
4. **真实模型格式与时点错误。** 新运行第一次评审格式错误被严格拒绝并留档；已有一次 schema 纠错生成第二份真实评审，其中目标碰撞断言时点错误。应用使用玩家明示 acknowledgement，没有额外请求逼模型变绿。
5. **测试缺口：opaque iframe 未收到原生 preload。** 改为专用、隔离上下文 preload 注入固定 CSP hash 的脚本。普通 renderer 的同名全局不能启动注入；普通正式世界 request-step 仍拒绝。
6. **测试误判与会话错误。** JSON 键序差异改用对象深等；源/目标世界错误共享会话被真实边界拒绝，改成真正新会话；备份之后旧关闭视图的等待改成实际再次启动程序。原失败证据保留。

最终包三场景合计 **35 次请求，382,194 已知 token，73,174 unknown 估额**。unknown 来自有意中断时的一次在途请求，账目仍保留。与前述开发阶段 60,854 已知及 47,298 unknown 分开，不互相替代或重复累计。没有开启额外手动模型重试；固定玩法场景上限 12 请求/15 分钟，两个 F 场景各 80 请求/20 分钟，全部在界内结束。

最终包组合作品的两份真实评审分别有 5 和 4 条红断言：第一份攻击/奖励轨迹未实际造成预期变化；第二份生成的近战玩家位置被实际 `REQUEST_PLAYER_BLOCKED` 拒绝，后续步骤未发生。原输出和失败断言完整保存。两次机器验证均 passed，玩家表单显式提交 acknowledgement，应用回执保存 true；正式游戏固定真实射击/近战/扩展/奖励链随后全过。这里证明玩家裁决链和实际玩法，不宣称模型评审断言全部正确。

实际 Agent 作者缓存统计按去重消息计，排除独立评审和 unknown：树作者+复用 18 次，cache read 105,344 / 总输入 196,065 = **53.73%**；恢复作者 11 次，66,432 / 106,955 = **62.11%**。这是完整真实任务的输入缓存占比，不是模型总 token 占比，也不是固定前缀对照实验；每条值在 `packaged-summary.json`。不能承诺 100% 或将其他组 98.24% 固定内容实验当作真实长任务结果。

本组另外读取最终领域日志核对：全部实际机器验证通过、应用落盘；组合评审仍红但 ack 封入回执；额度改为不限后 owner 和已知用量不清；恢复只有同一预算 owner，generation 确实前进且 unknown 未丢。原始报告及 SHA-256 索引收录在 `native-evidence/packaged-*.json`。

Root 同包三次压缩由 root 独立运行，本报告不代其签字；其结果应查看 G 报告。干净 Windows 安装与真实物理控制体验仍未验证。

## 尚未覆盖的外部条件

当前机器不是独立干净 Windows 虚拟机，未执行用户真实鼠标键盘、走路或战斗手感验收。所有自动化继续遵守隐藏不可聚焦窗口、独立 profile、无 Pointer Lock/真实输入；实际 UI 与玩法接受固定受限测试动作，未放开普通生产 renderer 的通用执行入口。
