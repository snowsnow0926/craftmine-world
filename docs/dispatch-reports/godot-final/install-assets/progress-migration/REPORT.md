# Additive progress migration — actual scene defaults

Root's complete-client package import failure desktop-native-complete-hk39NT was real: the new target was in the compiled source, import/export passed, but loading the old snapshot failed with Saved base_targets block does not match the scene. Changing only the runtime count check would also fail verifier and application full-state equality, and could lose old state. This commit supplies the bounded shared derivation and FPS runtime identity matching; the parent and core agent own the verifier/application/CAS integration.

Only first-person 0.1.0 is supported. deriveAdditiveProgress(previousSnapshot,defaultsSnapshot) preserves every old non-entity field and every existing entity entry by stable id. It adds only IDs present in the separately captured new scene defaults, at /body/targets and /body/interactables. Missing old IDs, duplicate IDs, incompatible old entity shapes, unknown envelope/body fields, different identity/version, invalid JSON and size overflow are rejected. It returns hashes, explicit added IDs and the complete derived snapshot. Defaults are evidence supplied by a trusted fresh runtime; this pure function alone does not prove their origin or authorize a core write.

Duplicate, unknown, missing and invalid state are refused with complete rollback. These tests use pinned headless Godot, no browser/input/focus/Pointer Lock and no model calls.
