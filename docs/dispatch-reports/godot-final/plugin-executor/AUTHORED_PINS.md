## Reproducible freeze workflow

1. Finish domain edits and commit a clean integration HEAD. Do not run while another agent is editing the source tree.
2. Run `node desktop/delivery/refresh-authored-pins.mjs --source-root <absolute-clean-root> --source-commit <full-HEAD> --output-root <same-root> --canonicalize`. Archive stdout outside tracked source before committing the generated manifests.
3. The generator validates each managed source's exact Git object identity. It only writes LF bytes when the CRLF checkout transforms to that **exact** object. Other changes, binary drift, links, unreviewed additions and changed third-party pins fail. Licence, redistribution and rights-status fields of existing entries are preserved. No wall-clock timestamp or self-referential commit is embedded in generated manifests, so a second run is reproducible.
4. Commit the generated delivery manifests. Record the generation's input commit and final package commit separately in the evidence. Run the generator again after the commit: no manifest changes should result. Run asset/notice/LGPL preflight and archive both failures and pending-rights warnings.
5. Build from that final clean commit. Runtime staging now verifies and writes the same Git blob bytes used by `git archive`, including GDScript, scenes, metadata and Web declarations. The resource hash manifest covers those actual staged bytes. The new narrow `.gitattributes` rules prevent fresh Windows checkouts from converting these source files back to CRLF.

The original source files are never granted new rights by hash refresh. Unknown third-party provenance cannot be fixed by choosing a new hash or setting `permitted`. Existing pending project licence application remains visible as warnings; binary/source identity and legal approval remain separate records.

Local regression: 9/9 tests passed for canonical-source verification, rejection of changed/unknown files, rights-field preservation, and complete runtime resource pins. The first attempt to run the full Git-backed generator in this subagent environment failed with `spawnSync git EPERM`, before writes. The root task must run it against the final clean integration tree and retain the real preflight output; this document alone does not claim those final pins have been generated or passed.
