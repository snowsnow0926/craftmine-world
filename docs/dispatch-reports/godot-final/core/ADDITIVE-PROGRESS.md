# Additive progress application transaction

The core now accepts first-person 0.1.0 additions only at `body.targets` and `body.interactables`. Every previous stable ID must remain, existing entry fields and value kinds must stay compatible, and every old entry value is copied intact. New entries come from actual checked candidate defaults. Unknown native envelope/body shapes are explicitly rejected. Other progress, including savedAt, player, inventory, equipment and quests, is preserved exactly.

`godotJob.checkDescriptor` records its first full descriptor and hash in nullable `craftmine_godot_jobs.check_input/check_input_hash`. Repeated calls preserve the initial check snapshot and require identical artifact/source identity. Optional executor result fields are `check.defaultsSnapshot` and `check.progressMigration`; both must occur together in a passing check. The core binds the owned job, input, world, base, build and artifacts, independently derives the checked result, and compares its complete snapshot and added list with the executor proof. External JS hashes are diagnostic; authorization never trusts them. Internal hashes use serde JSON and are marked `hashEncoding: "serde-json/1"`.

Application prepare still receives the current **old** formal snapshot and revision. It verifies exact equality, derives from the latest formal progress and authenticated checked defaults, and stores `input.previousSnapshot`, `input.snapshot` and `input.progressMigration`. This preserves play performed after checking. Existing jobs without migration evidence keep their prior exact-equality behavior. Candidate descriptors return the prepared new snapshot while checking the previous formal revision/hash. Commit independently rechecks the derivation, requires complete new-instance snapshot evidence, and atomically publishes the new build and full migrated state. The old complete world remains in the application receipt for recovery.

Validation: 274 Rust tests passed, 0 failed, 7 intentionally ignored; one documentation test remains ignored. New SQLite tests exercise descriptor replay after play, actual source patch/check ownership, prepare/descriptor/commit/restart, complete old-state recovery, forged data and added lists, foreign identity, removal and duplicate rejection, protected save during prepare, injected stale-row CAS rejection, and upgrade from a database without the new columns. Portable schema regression explicitly restores the old missing nullable columns; the existing full portable archive regressions also passed.

The executor in these Rust tests is a fixed fixture with on-disk artifacts; these tests do not claim a real Godot launch or model run. Root owns the actual verifier/runtime and complete-client acceptance. Failed setup/compiler runs are retained alongside the final passing raw log: visibility typo, initial fixture lacking a formally applied build, reused artifact identity, and a save correctly refused by the application lock were corrected without weakening product guards. The stale-row test deliberately injects a database race only after verifying the real save API refuses it.
