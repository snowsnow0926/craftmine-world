## 1. 用户能得到什么

已经应用的树或整组玩法可以保存为固定版本，重新启动后仍能找到原来的代码、依赖和来源；同一作品安装两次会形成两个独立实例。安装先进入草稿，还需要正常检查、评审和应用。

记忆区分玩家规则、经过验证的经验、任务历史和工作方法。模型自己写“验证通过”不能变成可信记忆。同一个世界的新会话可以找到该世界的规则，另一个世界默认不会混入这些规则。

任务崩溃后保留未应用代码，玩家可以明确恢复或丢弃。恢复不自动重发模型请求，也不会清空已使用预算。备份包含领域数据与最新进度，恢复先验证，再一次提交；损坏和版本冲突不会覆盖现有世界。

这些功能本组交付的是 Rust 服务及可信适配模块。完整桌面按钮、实际模型使用和 Windows 文件选择尚需 G/C/E/F 的集成验收。

## 7. 迁移和恢复

新增 SQLite 表采用增量创建；不清空旧世界。服务进程先持有操作系统文件锁，再恢复未决租约/作业，避免另一进程误取消活动任务。退出/崩溃由操作系统释放锁。

世界、草稿、作品与备份分别保持版本和哈希。恢复新任务保留原预算所有者；已结束请求的迟到结算可以补齐实际用量，不能恢复任务执行。备份恢复先在内存数据库检查，实际写入使用单个即时事务；旧指纹、损坏输入或约束失败会保留旧库。

外部未知备份不能冒充本机已验收来源：作品、规则会降级待复验，导入应用回执不能直接再次成为可信入库依据。备份不带凭据存储、浏览器缓存或原始旧项目目录。
