# B request-hook integration contract

Version: craftmine.request/1. Status: ready_for_integration.

## Files and types

`vendor/pi-desktop/packages/agent-runtime/src/craftmine-context.ts` exports `CraftmineRequestHooks`, `CraftmineTaskContext`, `CraftmineBinding`, `CraftmineEstimate`, `CraftminePurpose`, `createCraftmineRequestHooks`, `createCraftmineProxyHooks` and `craftmineGuardedStream`. The package index re-exports them.

`AgentRuntimeOptions`, `RuntimeMatchConfig` and sidecar `RuntimeParams` accept `craftmineWorld?: boolean`. This flag is desktop-host owned. Changing it retires a reused runtime. `AgentRuntimeOptions.craftmineHooks` is injectable for tests or a trusted in-process caller.

`OneShotCompleteOptions` adds `craftmineHooks?: CraftmineRequestHooks` and `craftminePurpose?: 'creation'|'summary'|'review'|'retry'`. Main review must pass its captured owner's hooks with purpose review. Each physical retry calls those hooks; normal reviews keep purpose review to permit an exact finished workspace. The main creation stream marks its setup retries retry. PI compact delegates actual summary requests to the guarded `Models.completeSimple` adapter.

## Reverse proxy to G

- `craftmine.context({sessionId,turnId})` returns A task.context, never selected-panel state.
- `craftmine.budget.reserve({sessionId,turnId,binding,generation,requestId,purpose,estimatedInputTokens,maxOutputTokens,limits?})`.
- `craftmine.budget.settle({sessionId,turnId,binding,generation,requestId,status,usage?,errorCode?})`.
- `craftmine.budget.boundary({sessionId,turnId,binding,generation,eventId,kind})`, kind compaction or tool.

G must compare binding/generation to its captured trusted owner. The model cannot supply or override them. A requestId is generated by the runtime; G should remember successful reservations and allow stopped/old-generation settlement only for that exact recorded request. Never redirect it to a newly selected world or current turn. Context, reserve and boundary remain revoked after cancellation. Normal turn completion can retain read-only review access for its exact current verification; a new task revokes old review access.

Binding fields: projectId/sessionId/turnId/taskId/baseBuild. The snapshot has generation/status/world{id,revision,buildId,hash}/draft{revision,hash}/requirements[{id,text,kind}]/modifiedResources/receipts/jobs/lease{owned}/budget. Optional scoped validated memories and exact library references are supported, but A/G must supply their trusted projection. B does not query arbitrary library contents or persist a second memory store. Unknown/malformed world identity, missing lease and cancelled/interrupted tasks fail closed. Finished review may lack a write lease; creation may not.

`limits` fields match A: maxRequests/maxTokens/maxCompactions/deadlineAt; deadlineAt is integer Unix milliseconds. The first durable reservation fixes limits; B does not reset them on model change or compaction. Tool-results reserve is included in estimatedInputTokens. Provider usage is `{inputTokens,outputTokens,totalTokens}`; total comes from PI's normalized provider total without re-adding reasoning/cache. Failed/unknown/cancelled attempts keep their durable reservation. Compaction boundaries count attempts, including failure.

## Calls and cancellation

PI preflight → inspectRequest (fresh context, no reservation) → existing inline compact if full estimate reaches 85% of model window → PI compact summary guarded stream → fresh final beforeRequest → budget.reserve → provider onPayload final check → stream nonterminal text → afterRequest/budget.settle → terminal message/tool execution.

`onBoundary` counts actual PI compaction attempts/tools; stop/resume/model/world boundaries do not cache authoritative state. Every inspection/request re-queries it. Runtime abort propagates to creation and summary streams. Review cancellation stays under review-jobs/main; the guarded stream ignores provider late success. The host must cancel its queued review/native jobs too. Player resume/discard is A/G, never automatic replay.

## Tool boundary

B filters to host-provided `plugin_craftmine_world_*` definitions plus runtime-local ToolSearch/new_context/AskUserQuestion. Only project_inspect and capabilities_read world tools are initially core; other world tools are discovered normally. G must independently validate exact built-in Craftmine plugin ownership in tools.execute before local tools/host forwarding. Prefix filtering alone cannot authorize an arbitrary plugin. Existing PI sessions remain unrestricted by this world-only policy. This does not establish an OS sandbox for plugin processes.

## Large review and packaging

New `plugins/craftmine-world/context-review.cjs` is required by review-jobs.cjs. Copy it into the packaged plugin. `integration.patch` contains that one baseline build change; root's actively edited bundler may incorporate it manually. Base blob is recorded in DELIVERY_B.json. No hotfile overlay was applied for B tests.

Small review input is unchanged. Oversized review includes changed resources, every behavior/system and a conservative transitive object-reference closure across both versions. Omitted unchanged objects retain names/anchors/hashes; global geometry is explicitly unverified. Global environment changes require all resources. The original 180k limit still applies after focusing, with no source truncation. Huge complete slices still fail explicitly.

## Validation boundary

Provider/domain fixtures validate B hooks, real PI compaction implementation and retained transcript, not Rust/native integration. G/F must run real Rust proxies, main one-shot hooks, cancellation across queued jobs, final native Agent tasks, and three actual real-model compactions followed by a green finish. B makes no completed W2/W3 claim.
