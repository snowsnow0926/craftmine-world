# B 给 M（版本管理）与 N（素材库）的进程边界评审

任务标识：`godot-remaining-B-20260910`

## 给 M：受管理 Git 调用不能通过工程 hooks 取得宿主执行权限

M 的计划第 141 行要求：Git 调用使用固定程序、受控配置和参数数组，不运行导入工程的
hooks、外部 diff/merge/filter 命令，不递归拉取子模块；构建只读取已核对的文件集合，
不能从项目自带配置取得宿主执行权限。从沙箱视角，这条要求成立，并且边界是清楚的：

1. **Git 与沙箱是两个不同的执行者。** 本 crate 只创建受限的 Godot 进程，从不执行
   `git`、shell 或工程自带程序。M 的 Git 调用必须自己保证"固定程序 + 参数数组 +
   受控配置"，沙箱不会替它兜底。
2. **不要把 Git 工作树当作执行隔离。** M 计划第 58 行已说明工作树不是执行隔离。
   正确接线是：Git 只产出已核对的**文件集合**，交给 broker 的 `projectRoot`；
   `.git`、`hooks/`、`.gitattributes` 里的外部 filter 不得进入该集合。
3. **进入沙箱的副本不含 Git 元数据。** `Task::prepare` 递归复制普通文件与目录，
   遇到 reparse point 或非普通文件即拒绝；物化限额为 4096 文件 / 单文件 256 MiB /
   合计 512 MiB。M 只需保证交给它的目录满足这些前提。
4. **hooks 不会在沙箱里执行。** 沙箱只运行固定参数集
   （`--headless --version` / `--path … --import` / `--export-release Web …`），
   没有 `git` 路径，也没有让工程指定可执行文件的能力。
5. **仍然存在的宿主风险在 M 侧**：如果 M 自己用 `git` 执行了工程配置里的外部
   filter/hook，那发生在沙箱之外。建议 M 用 `-c core.hooksPath=<空目录>`
   或等效受控配置，并把实际命令行记入证据。

## 给 N：脚本与模型资源导入必须走同一条已验证路径

N 的计划第 88 行要求：物件和含脚本作品的预览依赖 GD0 的可信隔离执行器；
第 147 行把"脚本预览需 GD0"列为 AL2 的依赖。本轮结论：

1. **导入阶段就会执行代码。** 固定 `@tool` 资源与启用的编辑器插件在 `--import`
   期间真实运行；本轮对抗用例证明它们受同一边界约束：
   哨兵读写被拒、同级逃逸被拒、子进程被拒、外部与回环连接均失败。
2. **不要另建宽权限预览器。** 若 N 为预览直接启动 Godot，就等于绕开
   AppContainer/LPAC、Job、原生网络预检和产物哈希。含脚本资源的预览必须复用
   `godot-host-broker.exe run` 的 `import`（以及需要时的 `exportWeb`）路径。
3. **静态资源可以走固定预览场景**，但仍应在受限进程中运行；预览缓存按内容哈希、
   预览器版本、引擎版本建立（N 计划第 88 行）。
4. **失败要分别展示。** 格式探测、解码、导入失败与超时分别记录；沙箱 `failed`
   不等于"资源损坏"，可能是超时或预算触发——`resourceEnforcement.reason`
   与 `state` 要一起看。
5. **取消要贯通。** N 计划第 137 行要求支持预览取消。对应机制是关闭 broker 的
   stdin 或发送 `{"cancel":true}`；取消后子进程 PID 必须消失（本轮 `cancel` 用例
   已断言）。强杀后必须调用 `recover`。
6. **导入的资源是数据，不是指令。** 资源包内脚本在受限进程中执行；其输出的
   文本、日志与 `@tool` 打印都不构成宿主授权。

## 共同约束

- 两者都不得请求或依赖沙箱之外的特权；不得为了通过而修改全机防火墙、审计或
  配额策略。
- 自动验证继续遵守项目 `AGENTS.md`：独立 headless/offscreen 进程、独立数据目录、
  禁用 Pointer Lock、不发送真实鼠标键盘、不激活窗口。
