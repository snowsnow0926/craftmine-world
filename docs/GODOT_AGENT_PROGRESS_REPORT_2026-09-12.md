# Godot Agent 能力提升进度报告（小白版）

## 结论

我们已经把内置 Godot 从“能启动世界”推进到一条可验证的开发链：Agent 可以读工程、修改已有对象、构建、运行、检查碰撞、保存、冷重开、恢复失败世界，并读取一部分真实运行指标。

这还不是“任意大型游戏都能自动完成”。当前目标仍为 active，下面的缺口都是真实缺口。

- 独立工作树：D:/cm-agent-godot-0912
- 分支：codex/agent-godot-capability-20260912
- 原工作区 D:/Craftmine World 没有被本计划的开发测试修改

## 已经完成的能力

### 工程理解

Agent 可以查询固定 Godot 4.7.2 的场景、脚本、资源、节点关系、输入、信号和部分存档字段。无法静态确定的动态内容会标记为 unknown，不会编造结论。

### 创作修改

真实普通玩家模型曾完成两类愿望：

1. 保留原来的两栋房子，只把它们左右分开；
2. 只把左边房子放大 2.5 倍、旋转 90 度并改为可穿过，另一栋不变。

修改经过实际构建、检查、采用和冷重开。对象、世界、构建版本、源版本和存档都被绑定，避免改错对象。

玩家模型验收沿用用户确认的 deepseek-v4.1-flash-expires-on-0910 和 max 思考强度；没有额外限制 token、调用次数或整轮时间。

### 独立运行和恢复

测试在独立后台进程和独立 profile 中运行，不抢鼠标、键盘、焦点或 Pointer Lock。已有碰撞和双向移动证据。原来失败的 side-view 废墟世界已经能通过正常 retry 恢复，原失败记录和源码保持不变。

### 开源资源

已经固定并试用 Kenney FPS、City Builder、Beehave 等开源 Godot 资源，检查了来源、哈希和适配过程。下载成功不代表完整玩法和授权审核已经完成。

### 性能和诊断

已接入一个只读的渲染进程内存观测工具；它读的是整个 renderer 进程的 OS 工作集，不是某个世界独占内存，也不是 GPU 内存。

另外完成了固定 Godot 4.7.2 的引擎监测原型：

- 单帧处理时间；
- 物理处理时间；
- FPS；
- Object 和 Node 数量；
- 有效绘制时的 draw calls 和 primitives。

真实测试中加入 256 个节点后计数增加，释放后回到基线。暂停时耗时和 FPS 会变成 unknown；headless 没有有效绘制时绘制指标会变成 unknown；GPU 时间始终 unknown。引擎原始秒数和换算后的毫秒都保留。

## 仍未完成

1. 普通玩家模型还没有专项证明它会主动使用全部新增 Godot 工具；已有模型记录只证明已记录的创作愿望。
2. 引擎监测 provider 已进入当前源码，但最新接线发生在 56b5aeca 封存包之后，需要重新封存并验收最新桌面包。
3. 没有完成同一设备、同一场景、同一规模的优化前后对照，也没有证明优化后画面、碰撞和玩法完全不退化。
4. GPU、完整渲染帧率、更多导航和物理指标还没有可信通道。
5. 同伴绕障碍、商店、宝箱一次性奖励、动画时序、复杂动态节点等完整 GA 矩阵仍有缺口。
6. 历史旧版本 side-view native 崩溃仍记录在账本中；新的 retry 成功不等于所有旧版本都修好。
7. 开源资源正式授权和长期兼容性仍需单独处理。

## 这对项目意味着什么

内置 Godot 的价值已经从“帮忙写代码”扩大为“把源码、真实构建、运行实例、碰撞、存档和失败记录串成一条可检查链”。没有内置 Godot 时，Agent 很难在同一流程中看到这些真实运行结果，通常只能给代码建议。

当前最接近完成的是基础创作、保存恢复、实例隔离和部分性能观察。距离完全发挥潜力，主要还差最新包的完整接线验收、引擎指标正式进入 Agent 工具、玩家规模优化和剩余玩法矩阵。

本轮收尾后停止继续开发；目标状态仍保留为 active，因为这些未完成项不能被改写成已完成。
