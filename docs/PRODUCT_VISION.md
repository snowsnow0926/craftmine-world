# craftmine world / 最中幻想：把想法变成可进入的世界

更新日期：2026-09-11。同步双模式、玩家主世界、C / D / L 与可复用能力积累方向；本文件描述目标体验，当前已实现能力以实际交付和验收记录为准。

早期验证：本地创作 Alpha 曾跑通“空白世界 → 真实 LLM 生成树 → 修改同一棵树 → 保存恢复”，详见 [实现记录](IMPLEMENTATION.md)。该历史结果不能替代当前 Godot 玩家版本的验收，后续进展见 [Godot 开发记录](GODOT_DEVELOPMENT_LOG.md)。

## 一句话说清楚

**我从一个空白的 3D 世界开始，可以在里面走动；接入 LLM 后，我用自然语言描述想要的东西，系统帮我开发出来，让它真正出现在这个世界里。**

核心体验是：走进去 → 说出想法 → 看见变化 → 继续游玩和创造。

## 北极星与能力积累

**让普通玩家用自然语言，持续把想象变成可玩、可改、可保存的世界；让同等要求的愿望越来越容易、越来越快、越来越省地实现。**

**让一次成功的创造，成为更多玩家下一次创造的起点。** 经过验证的模块、资源、世界模板与指导可以被后续 Agent 检索、配置和组合；常见请求由适合的小模型与确定性工具处理，新机制使用更强模型开发。社区共享由作者明确发布，复用仍保持原愿望的范围、质量与实际运行要求。

主指标采用“每周完成至少一个有效愿望并继续游玩的创作者数”，同时观察保存重开、后续修改、成功率、完整耗时与实际费用。C 描述创造什么，D 描述当前条件下的交付难度，L 描述技术改动范围；先查询可复用能力，再固定执行前难度与选择模型。定义、统计边界与实施方案见 [C / D / L 总体方案](WISH_CDL_FRAMEWORK_AND_NORTH_STAR_PROPOSAL.md)，本地 4B 和社区收益仍需实测。

## 两种使用模式与玩家主世界

工作台模式适合在完整对话、素材、参数和历史面板中创造世界。沉浸游玩模式让世界占满画面，玩家用快捷键呼出轻量对话窗，也能直接打开完整工作台浮层；关闭面板后继续游戏。两种模式共享世界、会话、任务与存档，收起面板不停止 Agent。

官方重点建设一个专门服务玩家的造物主世界，暂名“造物世界”：先采用单人 3D 第一人称空白场地，提供明确的指向、少量可组合能力与真实新增玩法开发路径，让玩家持续说出愿望并看见变化。每人创建独立世界，不代表多人共用的服务器大厅。

常见请求优先复用能力与资源；需要新逻辑时开发实际工程。明确请求在启用的自动应用策略内，经过检查与进度保护后生效；影响较大或不兼容时再说明选择。详细方案见 [沉浸游玩模式与造物主世界计划](IMMERSIVE_PLAYER_AND_MAIN_WORLD_DEVELOPMENT_PLAN.md)。

## 第一次打开时

用户已明确希望以类似《我的世界》的第一人称空间体验作为起点，可以是空白世界，只提供最基础的移动操作。

第一版建议把“空白”做成一块可行走的平地，配上天空和基础光照。玩家可以移动、环顾和跳跃，有基本碰撞，不会掉出地面。世界里最初没有树木、房屋或预先做好的采集玩法。

这是便于开始创造的默认方案。地图是否无限、是否使用方块表现、移动细节和画面风格不必现在全部定死。

## 第一条完整体验

1. 我进入空白世界，可以自由走动和观察。
2. 我打开对话框，输入：“我想要有树。”
3. 系统理解需求，准备一个简单默认方案，例如在我前方的空地添加一棵树。
4. LLM 通过开发执行器读取当前游戏项目，生成所需的代码或场景内容，并完成实际检查。
5. 系统通过检查，按我启用的自动应用策略让变化生效，或显示“已准备好一棵树”由我主动采用。
6. 根据实际支持情况局部应用或保留最新进度重新载入，树真实出现在世界里。我可以走近、绕着它看，它占据真实的三维空间并具有基础碰撞。
7. 我再说：“把这棵树变高一点。”系统关联这棵树，修改后让我再次体验。
8. 我关闭并重新打开项目，世界和已经创造的树还在。

默认造一棵树、放在前方空地、带基础碰撞，均为第一版建议。普通需求尽量给出合理默认；遇到影响已有成果的歧义，再做必要澄清。

## “生成树”具体意味着什么

对用户来说，只需要表达“我想要有树”，不需要寻找脚本、复制代码或手动安装模型。

实现上有几个不同层次：

| 层次 | 树的例子 | 第一版的处理 |
| --- | --- | --- |
| 外观 | 树干、树冠、颜色和高度 | 先让 LLM 生成简单程序化几何或方块构造，得到实际的 3D 树 |
| 场景对象 | 树在哪里、是哪一棵、是否有碰撞 | 保留稳定对象 ID、位置和基础碰撞，支持之后继续指向它修改 |
| 玩法 | 能否砍伐、掉落什么、是否生长 | 用户以后提出这些需求时再开发 |

第一棵树不依赖额外的 AI 3D 模型生成服务。LLM 可以编写构造树的代码或场景描述，由游戏运行器渲染出来；精细模型、贴图和动画可在后续接入。

对于已有对象，“变高一点”可以只更新受支持的数据；对于当前没有的能力，需要实际开发对应实现。系统应明确实际做了什么，不能用提前写好的关键词分支冒充通用开发能力。

## 以后怎样逐步长成游戏

这些是说明方向的例子，尚未承诺一次全部交付：

- “多种几棵，围成一片小树林。”——增加对象和布置场景。
- “在旁边加一条河。”——扩展环境。
- “让我能砍树，砍完掉落木材。”——给对象增加交互和采集玩法。
- “用木材做一座小屋。”——进一步连接资源、制作与建造。

世界从用户提出的需求中逐步生长。基础运行器负责让人能进入和操作，场景内容与玩法可以在后续对话中逐步形成。

## 第一版做到什么程度就有价值

**空白世界 → 一句话生成第一棵树 → 走近观察 → 指着同一棵树继续修改 → 保存并重新进入。**

这条流程需要真实接入 LLM，真实改变项目内容，并在游戏中显示结果。后台执行时正式世界仍可游玩，应用遵循用户已启用的策略和本次授权；必要时提示合适时机，失败时保留旧世界。生成不能保证每次成功，系统需要显示实际结果并支持继续修正。

第一阶段在用户自己的 Windows 电脑上完成。工作台模式保留完整创作工具，沉浸模式提供按需呼出的对话与完整面板；第一次造树可以全程留在游戏里，复杂修改也可切回工作台。

原有 0.2「林间起点」原型保留为技术参考和回归基线，可复用渲染、移动、输入与保存经验。新体验以空白世界起步。
