# ADR：托管观察器兼容升级与旧整底座升级分离

日期：2026-09-12。基线：`141642e9`。

## 已确认问题

原 `creation-source-migration.ts` 仅接受 preview.10 的三个固定文件旧哈希。只要固定文件需要升级，已修改的 `creation_world.gd` 或 `scene_contract.gd` 就导致 `CREATION_MIGRATION_NEEDED`。新增普通场景观察器后，旧世界的模型生成宠物虽然可以游玩，却可能无法继续进入创作链。

## 决策与合同

新增宿主源码中的 `CREATION_MANAGED_MIGRATIONS`，每条记录具有稳定 ID 和完整文件清单；每个文件明确 source、resource、已审核的 from 哈希和 to 哈希。LF／CRLF 分别固定，不接受通配符、版本大小比较或任意旧字节。

- **兼容增量模式**：记录中全部文件匹配已知来源或目标，而且实际安装资源命中目标哈希；未列出的原有保护文件也必须已经是当前受保护字节。只修改记录中明确需要升级的托管文件，保留全部普通脚本与额外文件，包括其他 `craftmine_shared/` 用户文件。
- **旧整底座模式**：继续保留原 preview.10 联动升级及普通源码改动拒绝规则。不能用兼容记录为未知旧整底座背书。如果目标兼容记录声明新增固定 helper，旧联动升级也会按该 helper 的精确前置补齐；遇同名未知内容拒绝。
- 新文件只在 from 明确包含 null 时以 `expectedHash:null` 添加。已存在且命中目标哈希时保留原字节；同名不同哈希必须在明确 from 表中，否则拒绝。不存在不等于任意内容可覆盖。
- 依旧对完整草稿清单做 CAS 前比对；升级后核对所有文件的数量、路径、哈希、长度，包含新增 helper。不是只确认改动列表，从而避免漏掉其他文件被删除或改写。
- 迁移记录保存完整兼容定义、模式、原始请求、绑定和回执。兼容定义参与 migrationId；重试／新 turn 依据原回执恢复，不重复发送不确定的 patch。原 `sourceMigration` advance 保持原合同。

兼容规则只能由宿主代码提供。内部构造参数保留测试夹具注入，未添加产品工具、项目配置或 renderer 的规则入口。此变更不调整任何固定 probe 或源码保护策略。

## 当前记录与后续维护

当前记录只审核 `940c5a84 → 141642e9` 的 adapter 增量，其他底座方法和进度合同不变。下一次合入 mesh 拾取、`headless_play_action.gd` 或 bridge 变化时，需要重新审查行为兼容性，将整组相关文件加入同一完整记录并固定新的目标哈希。需要支持新 helper 时把“原来不存在”作为显式输入，不通过仅增加路径白名单绕过源保护。

生产记录测试要求至少一组目的字节对应当前资源；更新资源却忘记更新记录会失败。机制测试使用独立冻结的 940→141 夹具，避免后续生产记录更新后把旧证据悄悄换成新字节。

未知 protected 哈希、未审核目标资源、同名 helper 冲突、未声明缺失、未采用草稿冲突仍拒绝，不以覆盖文件解除阻塞。此服务修改当前任务草稿，正式世界仍需要后续真实检查、候选采用和进度交接。
