# Alpha 0.6：把生成过的玩法记住，再放进新世界

2026-09-08，M2 完成。源码玩法现在可以作为完整创作保存、复用、导入另一个本地项目，并按实例切换版本。下一阶段是 M3 连贯创作与失败修复，个人创作 Alpha 的整体目标还未完成。

## 可以实际使用的能力

应用成功后，记忆库会保存与玩法有关的对象、原始源码、参数、状态格式版本、依赖和接口检查用例。卡片标记为“完整创作 · 含源码”；普通“对象”卡片仍供单独复用外观。

- 输入“用之前记住的木滑门，再来一扇”。真实 LLM 已在清空世界后找到记忆，交给宿主安装；新门源码和参数逐字保留，到了新坐标仍能实际打开。
- 在“素材与记忆”选择完整创作的固定版本，点击“复用到世界”，应用候选即可使用。可单独导出模块，在第二个兼容的本地项目导入再复用。
- 当前世界的完整创作提供“切换此实例版本”和“卸载此实例”。改作产生不可变的新版本，导入 v2 不会自动更新正在游玩的 v1。
- 兼容版本切换保留实例身份、开关状态、对象偏移与库存。卸载后代码进度和受损对象血量进入存档归档，恢复此前世界时找回原进度。
- 一次候选里安装两个副本时，身份与状态分别独立。自动摆放参考源码检查中观察到的活动范围，已经验证两扇门都能打开。

所有操作仍形成候选；应用时读取最新进度。错误源码不进入成果库，加载失败也不覆盖当前世界和候选。

## 底层设计

### 定义、实例与状态分开

`craftmine.module/2`、`craftmine-web/3` 的 `creation` 模块保存相对位置的几何、原始脚本与参数、稳定对象角色、每份脚本的坐标关系、依赖系统定义，以及 `craftmine.creation-tests/1` 的事件序列。内容哈希覆盖完整 payload，文件继续存于 `modules/<id>/<version>.json`，旧对象与配置模块格式保持兼容。

安装时创建新对象和行为身份，通过 `craftmine.behavior/2.binding` 保存角色到实例的映射。宿主先把世界快照转换到原作者坐标，再把源码返回的命令转换回实际世界；源码字符串、参数和任意 JSON 状态不做猜测性替换。转换后的命令重新接受真实目标权限、边界与碰撞检查。移动副本后再次提取相同内容，不会仅因位置或 ID 不同而产生新版本。

多个规则涉及相同对象时一起保存，独立规则分别保存。依赖声明可携带生命值、射击和近战配置；缺少的系统随创作安装，已有同类系统保持当前设置。共享系统不会因为卸载一个创作而一起被删除。

`craftmine.behavior-state/2` 保留最多 32 份已卸载或不同状态格式的历史代码进度；对象血量归档最多 128 个对象。达到容量会明确拒绝更新，不静默删除记录。相同 `stateVersion` 使用已有状态；需要新状态格式且没有兼容存档时拒绝应用，通用状态迁移函数尚未实现。

### 检查与长期记忆

导入的完整创作在本机重新验证。Node 只解析语法，实际代码仍在无开发凭据的独立 headless 浏览器和 Worker 中运行。事件覆盖启动、计时、两次互动、接触、攻击、落地与状态恢复。通过记录按模块版本和内容哈希保存在本地项目索引中，完整报告在构建目录；导出携带源码、来源和检查用例，接收项目不信任外部“已验证”标签。

活动范围来自该检查序列实际提交的对象移动，用于减少副本之间的摆放冲突。它不覆盖所有可能的代码路径，也不代替完整玩法语义验收；运行时仍会拒绝撞入玩家或其他实体的移动。

LLM 上下文优先检索相关的完整创作。根输出 `reuseCreations` 引用真实模块版本，宿主读取本地完整定义并安装；大型模块可先提供清单，避免源码超过上下文预算而完全丢失记忆。近期对话消失不影响已保存的成果。完整世界存档保存正在使用的源码和进度，所有历史模块仍通过模块库单独导出。
