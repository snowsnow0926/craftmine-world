# 真实端到端验证记录（2026-09-09）

本文只记录**用真实模型、真实沙箱、真实浏览器**跑出来的结果，不写设计意图，也不把没跑通的东西记成通过。

> Windows 开发接续：新增资源事务、验证沙箱装载扩展已修复，并补了确定性与 headless 浏览器回归。实测还发现玩法绑定会清空扩展依赖，以及重开世界和候选预览遗漏扩展表，一并修复。`tests/extension-behavior-browser.mjs` 使用固定源码、真实 Worker 与游戏页面，7 项检查通过（`test-results/extension-behavior-blHOLr/report.json`）。它证明接口接通，尚不等于下述真实模型全链路已通过；真实压缩状态也仍为待复验。

开发接口：`workspace.patch` 支持 `op:"add"`、`expectedHash:null` 新增对象、玩法或系统；省略 `op` 仍保持旧的替换语义。所有操作仍受草稿版本、调用去重、作用域和原子编译校验。新行为自动把 scene/2 升级为 scene/3，失败批次不留下半个草稿。

验证入口统一使用与游戏相同的扩展装载器；初始化失败显式报错，页面关闭会释放扩展 Worker。固定源码回归使用 start／tick 中第一次事件触发，避免把暂停世界中没有 tick 误记为扩展失效。

独立工作树首次全量回归另发现换行差异：10 个冻结文件在 CRLF→LF 后与原清单完全一致。仓库现固定 JavaScript 源码 LF；完整性校验仍按原始字节执行，只更新了本次增加共享装载器静态路由所对应的一项哈希。
两个入口：

- `node tests/live-extension.mjs` —— 真实端到端跑一次扩展（提议 → 自带测试 → 反造假 → 对抗评审 → 冻结回归 → 启用 → 玩法调用）。
- `node tests/live-compaction.mjs` —— 真实长任务的强制上下文压缩回归。

两者都使用独立数据目录，不读不写 `.craftmine/`，不操作用户输入设备。

## 2. 真实模型提议扩展的实测数字

一次典型运行（`test-results/live-extension-*`）：

- 提议轮：模型第一次就可能写出不合规的包，宿主把**具体的拒绝理由**回灌后重写，1–3 次内收敛。
- 自带测试：3 个用例，真实实现全过、空实现全红。
- 对抗评审：3 条发现（阻断 0、重要 1、次要 2），全部带可执行断言。
- 装载流水线：`status=ready`，`checks` 三道齐全。
- 启用：`ext:lifesteal-drain@1` 进入装载表，能力目录同步。

评审在**独立重跑**时会给出不同结论（同一份扩展，一次 0 阻断、一次 1 阻断），这不是 bug，而是把 LLM 当裁判的必然方差。

## 3. 这一轮真实运行抓出并修掉的缺陷

全部是**只有真跑才会暴露**的问题；每一项都补了确定性回归测试。

| # | 缺陷 | 后果 | 修法 |
| --- | --- | --- | --- |
| 1 | `workspace.patch` 编译草稿时没带已装载扩展 | 声明 `requires:['ext:…']` 的模块永远改不了，报「扩展没有装载」 | `compileScene(next,{extensions:store.extensionSet()})` |
| 2 | 分步闭环的能力文本 / `capabilities.read` 不含已装载扩展 | 模型根本不知道能调用哪些扩展命令 | 闭环与工具都带上扩展目录，提示词同步 |
| 3 | 能力文本仍写着「玩法模块还不能直接发出扩展命令」 | 陈旧描述误导模型 | 改成真实规则：可调用，但要声明 `ext:` 依赖与权限 |
| 4 | 模型把整个循环「演」出来（多个 JSON 对象 + 伪造 `<result>`） | 整步判为「不是有效 JSON」，任务空转 | 宿主确定性提取第一个满足 schema 的对象；提示词明确禁止模拟工具结果 |
| 5 | 沙箱超时关闭后 `dispose()` 的 promise 拒绝无人接管 | **未处理拒绝直接把本地服务进程带走** | 安全释放 + 沙箱时限可配（默认 10 分钟）+ 全局 `unhandledRejection` 兜底 |
| 6 | 沙箱代理写成 `page.evaluate(async (_, value)=>…)` | `page.evaluate` 第一个参数才是传值，真实服务里自带测试**必然全部失败** | 改成 `value =>`，并把代理抽成 `sandboxRunner(page)` 用测试锁住 |
| 7 | 扩展自带测试轨迹的 `change.fields` 写死成空数组 | 任何「变化字段」断言必然失败 | 用宿主已有的 `observableChange` 真算 |
| 8 | 评审漏写断言 `id/why/red` | 整份评审作废，扩展无法装载 | 宿主确定性补齐（判决不看这三个字段） |
| 9 | 评审把玩法模块的 `step` 约定套到扩展上 | 误报阻断 | 评审提示词区分产物类型，并传入真实自带测试证据 |
| 10 | `step` 断言只写 `min` 不写 `type`；模型常写成数组 | 报错信息是「undefined 应有 1 条以上」，模型看不懂 | 校验提前报错；两种写法都接受 |
| 11 | 模型在 `requires` 写 `health@1`、`permission` 写 `"targets.write,health.write"` | 一次格式错误就整件事失败 | 提示词写死规则；提议失败把宿主拒绝理由回灌重写 |
| 12 | 上下文预算没有人工上限、步数预算固定 16 | 无法回归压缩；压缩后重读把预算耗光 | 新增 `CRAFTMINE_CONTEXT_CAP` / `CRAFTMINE_HARNESS_STEPS`；压缩上限 3→8；压缩后保留「哪些资源改过」的机器事实 |

## 4. 还没打通的两段（玩法模块调用扩展命令）

1. **工具闭环只能替换既有资源，不能新增。** `workspace.patch` 要求资源已存在（真实运行报 `资源不存在：behavior:drain-once`）。
   因此「给世界新增一个调用扩展命令的模块」在闭环路径上做不到；单次生成路径可以新增模块，但那条路径默认关闭。
2. **隔离验证沙箱没有装载扩展。** `verifyBehaviors` 里的 `BehaviorSession` 不带扩展派发表，带 `ext:` 依赖的模块过不了验收。
   要在游戏里真正跑起来，必须把扩展表传进验证沙箱（`app/behavior-verify.mjs` + `app/harness/*`）。

这两段都属于「玩法调用扩展」这条链路的最后一公里，目前只有 Node 侧单元测试（`tests/extension-dispatch.test.mjs`）覆盖，没有浏览器端到端证据。

## 5. 强制压缩回归的实测状态

- 真实任务在 `CRAFTMINE_CONTEXT_CAP` 很小时**确实会撞上压缩阈值**：日志出现
  `上下文到压缩阈值，宿主执行第 N 次压缩：保留 X 条机器事实，把 Y 步原始轨迹压成短账目后继续`。
- 每次压缩都会落盘 `compaction-N.json`（机器检查点 + 上下文报告 + 短账目），恢复时接上检查点继续，
  草稿改动一条不丢（`loop.json`、`draftRevision`、`build` 都对得上）。
- 尚未拿到一次「压缩后把任务做完」的绿色收尾。原因是把上限压到 5000 token 时，
  **一次资源读取本身就接近窗口**，每压缩一次只够走 4–5 步，改稿又被压缩上限截断。
  现已修：压缩上限 3→8、步数预算可配（`CRAFTMINE_HARNESS_STEPS`）、压缩后账目保留「已改过哪些资源」。
  下一次运行应改用 `CRAFTMINE_CONTEXT_CAP=12000`（大于单条载荷）再验收。

## 6. 这次验证顺带确认的设计结论

- **对抗评审：必须运行，但结论是建议。** 连续多次真实运行中，评审的「阻断」都是设计意见
  （等量治疗、白名单、冷却、副作用断言……），改一稿又冒出新的意见，把它当硬门槛会让改稿循环永不收敛。
  硬门槛只保留机器能复核的检查：ABI 校验、沙箱自带测试 + 反造假、冻结回归、命令名冲突、世界编译。
  评审的每条意见仍必须带可执行断言并随候选留档，阻断级意见会显示给玩家——人是最终裁判。
- **模型提议要能自动改稿。** 提议接口把宿主的拒绝理由（格式、自带测试、评审意见）回灌给模型重写，
  这比「一次失败就整件事失败」更接近用户要的「言出法随」。

## 2026-09-09：桌面迁移测试中的扩展异常诊断

一个扩展在处理命令时抛出异常，宿主却将这条合法错误回执解释为“无效或过期的消息”，隐藏了真正的源码错误。已修复序号匹配的错误传递；过期消息仍然拒绝。`tests/extension-browser.mjs` 的真实 Worker 检查现在包含主动抛错与死循环终止，共 14 项通过。该脚本的模型评审和冻结世界回归钩子是固定测试数据，不能计作真实模型评审通过。

## 2026-09-09：Windows 原生后台检查与副本预览

本批使用真实 Electron、PI Rust tools.execute、插件 utility process、Craftmine
Rust 和游戏 Workers；模型调用由固定验收场景替代，不算真实模型创作验收。
原生检查链路曾通过，但截图显示黑屏，因此没有记为最终视觉通过。补上离屏
ResizeObserver 重绘和真实像素检查后重新运行，才形成第 4 批有效证据。

实测修复：
- Electron utility process 中旧语法检查器错误地以 Electron exe 执行 Node --check
  并超时。桌面改用打包的静态 Babel parser；默认 Node 路径遇到 Electron 直接拒绝。
- 空预览 iframe 没有初始化输入保护。改为打开预览时才创建，关闭时销毁。
- 隐藏画布先绘制后被 ResizeObserver 清空。增加布局后重绘，并拒绝黑屏截图。
- 验收快照漏了 solid/color，正常滑门被判失败。改为读取实际运行时碰撞和颜色，
  同时补齐物品与资源观察。通过真实 HTTP 共享验收器复验。
- 切换世界时旧检查卡片短暂保留。切换时立即清空并返回世界视图。
- 领取/提交证据的数据库回执失败可能留下持续运行状态。Rust 为未完成任务加
  60 秒失效与服务重启恢复，迟到回执不能转成成功。

此次静态资源白名单只增加 /app/behavior-check.mjs，用于共享现有验收实现；
核对变更后同步该文件在冻结清单中的哈希。验收断言、权限和冻结检查均保留，
没有增加给游戏内 Agent 修改清单的工具。开发授权来自当前 W0–W5 持续目标。
