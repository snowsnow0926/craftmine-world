# 自动采用期间周期保存误报修复

在城市两轮真实测试的 stderr 中看到成对的 `GODOT_CANDIDATE_ACTIVE`。
两轮内容都已成功自动采用，保存和冷重开正常。日志没有记录具体调用名或时间，
因此不能把每一条日志都断言为同一原因，也不能把它当成黑屏复发证据。

只读代码复现确认了一个真实问题：页面每十秒自动保存时，不知道 Main 正在
自动采用候选；保存被拒绝后，通用错误处理又请求恢复运行，再被拒绝一次。
原函数复现得到两次请求、可见错误条，但已加载画面没有被清空。

现在周期保存使用独立后台接口。Main 确认候选忙时返回“延后”，不触发保存，
页面不追加恢复请求、不隐藏先前真实错误。候选结束后下一个正常周期继续保存。
其他错误仍显示；玩家主动保存遇候选忙时，会提示完成预览或应用后再保存。
原候选排他保护、复制和恢复保护保持有效。

验证：26 项纯逻辑回归通过，覆盖真实页面函数与 Main 协调器、正常恢复保存、
先前错误保留、非候选故障、显式保存反馈以及既有黑屏恢复与兼容更新流程。
本轮未操作用户应用，未调用模型或 GPU。新包的真实界面复测由总控继续。
