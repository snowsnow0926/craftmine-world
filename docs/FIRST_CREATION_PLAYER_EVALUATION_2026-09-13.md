## 测试前由主持人记录

- 每人复制一份 [记录模板](templates/FIRST_CREATION_SESSION.md)，使用匿名编号，
  不记录账号邮箱、登录凭据或聊天中的私人资料；截图、录屏和分享范围由参与者自行选择。
- 填写实际 EXE 版本、源码提交、发行来源、完整文件夹或压缩包哈希、机器配置、
  系统版本、已有运行库、网络条件及资料目录是否首次使用。不得把源码 HEAD 当作成品版本。
- 使用自己的测试资料目录；不删除个人世界来模拟第一次启动。干净机器需记录实际
  已安装软件，开发机换一个资料目录只算“新档案”。记录从取得发行物到首次启动的全过程。
- 已交付 preview.21 仅用于既有世界、模板、保存及分享基线；其素材详情的直接加入入口
  尚不存在。自主创作开发版完成打包后，先填入新版本和实际支持的资产／编辑对象，再开始
  完整路径测试。若拿到 preview.21，直接加入项记为“该版本不提供”，不能通过 AI 代做后算成功。
- 不预先连接模型或替玩家布置内容。准备一个支持直接安装的确切组件及固定版本、
  一个有现成尺寸／颜色编辑支持的对象、以及足够空地；这些是明确的测试前置条件，
  不是把玩家自己的愿望替换为预设效果。观察其发现入口和理解限制的过程。

## 给玩家的任务卡

可以按自己的节奏操作、返回修改、求助或停止。请说出想达到的效果，而不是猜测试者
想看到什么。卡片是任务目标，主持人先不演示按钮位置。

| 阶段 | 玩家任务 | 观察和完成证据 |
| --- | --- | --- |
| 1. 首次打开，无 AI | 打开应用，选一个已有世界，走动并找到之后继续它的方法。 | 取得包、解压、启动、世界准备、第一帧、实际能走的时间分别记录；安装阻碍与警告照实保留。 |
| 2. 使用现成内容 | 在库中找到任务指定的受支持组件，确认版本，选一个位置加入世界。随后检查它是否真的出现、能否按预期使用。 | 记录搜索词、资产 ID／版本、位置选择、全过程提示、实际玩法及是否求助。开发版直接路径的真实模型调用应为 0；无法观测则记未知。 |
| 3. 做一次小修改 | 对一个界面明确支持编辑的对象调整尺寸或颜色；看结果，再按自己的判断改一次或撤销。 | 使用现有“编辑对象／检查并应用／撤销”能力；不假定任意 GLB、飞机或伙伴支持这些参数。记录原始愿望、每次尝试和最终满意程度。不能选中或编辑也算发现的问题。 |
| 4. 保存并再次使用 | 保存退出，完全关闭应用，再打开刚才的世界，检查修改和游玩进度。 | 记录关闭／重开时间、世界身份、对象状态、位置及玩法；未保存成功、错误世界、状态丢失不能被截图相似替代。 |
| 5. 交给另一位玩家 | 用现有“保存世界模板”（明确保存进度）→“我的模板”导出 ZIP，交给另一位有完整客户端的参与者导入并游玩。 | 接收者用独立档案／机器，只拿世界 ZIP，不复制作者资料目录、素材库、账号或聊天。记录两侧包版本、文件 SHA-256、导入时间、可玩性及冷重开。世界 ZIP 需要客户端，不等于独立 EXE。 |
| 6. 可选 AI 修改 | 若愿意，连接自己的 Codex CLI／账号，核对实际模型和思考强度，说出一个真实想改的需求；按原始意图回答澄清，试玩并再次修改或取消。 | 单独记录连接门槛、实际选项、完整请求／澄清／重试、等待、采用和最终玩法。AI 失败不替代前面无 AI 路径的结论。 |

如果参与者的目的只是让朋友玩，另行评估产品已有的独立游戏导出流程，记录实际
导出目标、接收环境和能否无需完整创作客户端启动。它与模板迁移是两条不同用途的
已有流程；本轮不新建第二套导出界面，也不把模板 ZIP 宣称为独立游戏。

## 主持和测量规则

先记录玩家的原话。玩家需要帮助时再给最少必要提示，并写下提示内容、提供时间和
是否由主持人代操作。独立完成、得到提示后完成、代操作完成、失败、主动停止分开统计。
可以给玩家功能说明，但不要通过缩减其要求把失败改记为成功；例如需要战斗就验证战斗，
需要能进去的房屋就实际进去。指定测试任务和玩家追加愿望也分开记录。

计时从每个任务发给玩家开始，到玩家实际接受的可玩结果为止；记录发现入口、思考、
下载、加载、检查、失败重试、求助和采用。可另外报告引擎／Agent 阶段耗时，但不能
只挑运行最快片段。没有结果就记录停止时间和原因，不设置强制整轮超时。

AI 环节保留玩家实际选中的模型、思考强度和产品配置。不另加 token、模型调用次数或
整轮时长上限，不替换为受限评测器或其他模型。既有产品错误／超时照实记录，玩家要求
停止时正常取消。区分 total、cached input、uncached input 和 output tokens；日志没有
给出的数据记“未知”，中断也不能记成零。不得把 token 总量直接写成费用。

参与者自己手动使用应用不受自动测试输入方式替代。开发自动验证保持独立 headless／
offscreen 进程及数据目录，禁用 Pointer Lock，不抢占焦点，不发送真实鼠标键盘，也不运行
历史输入模拟测试。自动检查结果与人的判断放在不同记录项。

## 汇总和下一轮选择

使用实际参与人数作分母，分别报告：首次自主创作完成率、完整时间分布及中途停止、
第二次修改成功率、保存冷重开成功率、接收者能玩和再次打开的比例。不要把未参与的
5–8 人或未执行项目当成通过。保留每次失败和求助，不只统计成功者的速度。

按发生频率、阻止完成的程度和恢复成本排列问题；区分文案／入口、能力边界、加载、
数据恢复和发行环境。下一项开发选择重复阻止真实任务的具体问题。现有本机庭院和
四世界时间只作为历史对照，不能承诺新人速度或替代此处尚未取得的数据。
