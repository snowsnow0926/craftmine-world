后续设计以当前实际 pi-desktop 界面为底稿，保留其窗口、主题、侧栏、会话、对话输入区和设置体系。优先调整现有组件的入口、文案和状态：

## 1. 需求与现状

| 用户需要 | 当前事实 | 缺少的使用体验 |
| --- | --- | --- |
| 在应用内使用 Codex | 普通世界对话和 F2 浮层已接入；显示 Codex、模型、思考强度、回复、工具与状态 | 首次连接需要手动准备兼容 CLI、登录并填写绝对路径 |
| 其他玩家也能接入 | 连接器已打包；CLI 本体没有随包分发；每名玩家使用自己的本机账号 | 安装检测、版本兼容检测、登录引导、状态与失败修复入口 |
| 一个客户端选择四个演示 | 已有世界列表、新建、切换、复制与版本记录；部分入口在高级存档管理 | 四个演示当前分属四个独立档案，通过 CMD 分别启动，没有作为同一档案的四个作品发布 |
| 快速打开同样成果 | 便携备份已保存并验证，可恢复源、资产与进度 | 面向单个世界的导入/模板发布；现有备份恢复是整个档案的操作 |
| 在新世界使用同款内容 | 已有素材目录、检索、版本、预览、源组件导入与内置包发布机制 | 本轮成果需要整理成可复用条目；Codex 工具目录还未开放素材库检索/复用 |
| 再次使用自然语言复现 | Agent 已能读取当前世界源并续做 | 需要检索已有条目、判断功能和兼容性、应用固定版本；相同提示词不保证重新生成同样作品 |

### 1.1 Codex 前端接入的实际边界

现在的路径是：设置 → General → `World authoring backend` → `Local Codex CLI (experimental)` → 填写 CLI 路径。进入 Godot 世界后，用普通 Agent 对话或 F2 对话继续创作。

目前固定 `gpt-6-astra / xhigh` 和 `codex-cli 0.154.0-alpha.6.2`。前端没有接入 CLI 安装器或登录按钮；只有执行路径输入和保存。连接前会读取实际账号，当前实现要求 `account.type === "chatgpt"`。API key 登录虽然是 Codex 官方支持的方式，但不是这个实验适配器目前接受的方式。应用原有 API 提供商仍是另一条独立通路。

Codex 只用于 Godot 的 Agent 创作模式，不能把 Coding、Plan、Web 世界以及所有辅助 AI 功能都视为已接通。不存在静默更换模型的回退。

官方 App Server 提供账号查询、登录开始/完成/取消、退出等接口，支持把登录过程接到自有前端。实现应使用后台受控接口管理登录，在前端只呈现连接状态和必要的登录引导。账号登录由玩家自己完成；不能随作品附送开发者凭据。每个玩家的模型权限须实际检测，不能由本机成功推断所有账号可用。

官方来源：[App Server](https://learn.chatgpt.com/docs/app-server)、[认证方式](https://learn.chatgpt.com/docs/auth)。这些官方能力不等于当前实验版本已经实现连接向导。

本地依据：

- `vendor/pi-desktop/apps/desktop/src/pages/SettingsPage.tsx`：`WorldAgentBackendRow`。
- `vendor/pi-desktop/apps/desktop/src/components/Composer.tsx`：Codex 标签和状态。
- `vendor/pi-desktop/packages/shared/src/codex-world-backend.ts`：固定模型、思考强度与工具集合。
- `vendor/pi-desktop/packages/agent-runtime/src/codex-app-server.mjs`：固定版本和账号检查。
- `vendor/pi-desktop/docs/spec/codex-desktop-world-backend.md`：既有真实桌面创作与重开证据。

### 1.2 素材系统已有基础，但 Codex 还看不到完整入口

已有 `AssetLibraryPanel`、Rust `asset_catalog`、内置源包导入以及 `godot_source_library` 的检索/读取/安装建议服务。当前封存包包含 20 个内置组件或场景，已有树木、城墙、宠物和基础战斗等条目。

不过，桌面的 `CODEX_WORLD_TOOLS` 与项目命令行的 `TOOL_NAMES` 都没有开放 `asset_library`、`godot_source_library`、`package_library`。`godot_asset_list` 面向当前世界的 Godot 资产，不能替代本地素材目录检索。桌面还在工具注册、原生权限和适配器处重复校验，不能只改一段提示词解决。

内置“白色博美”也不等于这次认可的模型：现有内置视觉 GLB 哈希为 `bde68ac018214c1af54c77f24b292ba77e80d4c74d5bc86debf39130cfd66fd6`；本轮可爱博美为 `1ab9f354598df75504b061fb06e1e5e386bd59c878afcec3bad8388832dadd0b`。入库时需要明确来源和版本，不能因名称相似就宣称复用了同一外观。

当前检索是名称、ID、备注与标签的文本匹配。需要让 Agent 从自然语言提取检索词、中文/英文别名和功能条件；后续语义检索是增强项，首版不必先建设向量服务。

## 2. 四类内容应分别处理

| 类型 | 示例 | 保存与复用内容 | 使用结果 |
| --- | --- | --- | --- |
| 世界存档 | 玩家已经探索 6/6 的城市 | 世界源、依赖、个人进度、版本 | 继续原来的游玩 |
| 世界模板 | 城市漫游、雨技能演示、飞行世界 | 固定世界源与资产、作者定义的初始状态、预览及兼容信息 | 新建一个独立世界 |
| 模型素材 | 白色博美 GLB、歼-20 GLB、房屋 | 几何、材质、尺寸、朝向、碰撞或动画声明、来源 | 放入目标世界；模型本身不自动具有玩法 |
| 可玩组件 | 博美伙伴、驾驶飞机、控雨技能、武器与敌人 | 模型加脚本、相机/输入需求、交互接口、存档协议和完整依赖 | 在已有世界中安装并适配对应玩法 |

现有世界复制与组件安装应继续复用。世界模板不能通过依次恢复四个整档案备份实现，否则会替换档案而不是向同一个“我的世界”列表增加作品。

模板发布需要世界范围的数据边界：只导出指定世界及其必需的源和资产，不携带账号、无关会话或其他世界。导入在 Rust 管理的事务与原有初始化流程中创建新世界，重映射世界与组件实例身份；不能直接拼接 SQLite 或复制旧玩家 ID。

“继续存档”和“从模板新建”必须有不同语义。前者保持当前进度；后者使用作者定义的初始状态，不应默认继承演示玩家的胜利次数、死亡或全部探索结果。首次加载仍可能需要本机导入、构建和检查；应明确显示阶段，不能把免 AI 重生成称为零加载时间。

## 3. 玩家应能完成的操作流程

### 已有世界

启动应用 → 我的世界/示例世界 → 选择预览卡片 → 进入游玩 → F2 继续创作 → 检查并应用 → 保存 → 重开后继续。

现成世界的游玩与恢复不需要模型调用；AI 连接应在生成或修改内容时才成为前置条件。

### 新世界复用内容

新建空白世界 → 输入“给我一只和演示里一样的白色博美，会跟着我走” → Agent 检索已发布组件 → 读取精确版本、外观与行为能力 → 兼容检查及位置选择 → 正常源安装/检查/采用 → 实际出现并能互动 → 保存重开。

对于“我要驾驶歼-20”，检索目标必须包含可驾驶行为；只有 GLB 的候选应标明为模型素材，不能当作已完成驾驶需求。雨技能包要处理天气、输入和存档依赖；不能通过把整个原世界覆盖过去来完成技能复用。

没有匹配条目时才进入新制作流程。找到相近条目可以复用后修改；玩家明确想重新设计或不喜欢候选时应允许新生成。不能强制选择名称最接近的第一项。

成功结果显示“复用了哪个版本、改动了什么、是否已应用”，保留来源和实际耗时。后续愿望仍只影响当前绑定世界，后台结果不能因用户切换世界而串入另一个世界。

## 4. 建议的开发顺序

### 第一轮：同一客户端里的打开、连接、创建与保存

1. 将“我的世界”“示例世界”“新建世界”置于可发现的主入口，复用现有世界列表、复制和切换服务。保留 Godot/Web 类型，给用户显示作品名称和预览。
2. 制作四个认可世界的模板发布清单与单世界导入流程。在一个全新的普通档案中导入四个示例，全部在同一个客户端访问；不使用写死开发目录的 CMD 代替产品入口。
3. 完成 Codex 连接页：检测本机路径/版本、选择文件、安装指引、登录与取消、连接验证、当前账号与模型状态、可操作的错误反馈。继续保持用户选定的 Astra/xhigh，不静默替换。先验收兼容版本，再考虑随程序管理 CLI 更新。
4. 把任务进度、应用结果、保存状态与错误恢复整合到正常对话/世界界面。复制世界后使用独立创作会话，原示例作为不可变来源保留。

### 第二轮：先打通“同款博美”完整复用

1. 将认可博美的 GLB/材质作为有版本的素材条目，将跟随、抚摸、等待和存档逻辑整理为可玩组件；复用现有组件接口，声明必要的源依赖。
2. 补充预览、别名、风格、能力、来源、版本、兼容条件以及经验证的表现；本地收藏和发布到其他玩家应分开。
3. 在桌面与项目 CLI 中统一开放经过原生权限验证的素材检索/读取能力，补齐 CLI 的服务接线。复用当前源包安装与候选流程，不把通用文件系统或 Core RPC 开放给模型。
4. 在全新世界提出同款博美愿望，验证确实引用既有资产，未调用 Blender 重新建模；再放第二只，验证实例身份与互动进度独立；修改一只的外观，不改变另一只或素材原件。

现有组件提取会拒绝整世界根、多身份节点树和可检测的外部依赖；还存在源读取、组件大小与 ZIP 限制。将演示整理成组件时须检查实际依赖和体积，不能假设所有动态世界都可一键打包。若需调整限制，应有真实资产需求、原生边界和回归验证。

### 第三轮：扩展到飞机、雨技能和城市片段

逐项整理飞行组件、控雨组件和建筑/街区模块。分别处理玩家控制器、输入冲突、相机、环境覆盖和状态迁移。需要整城时创建世界模板；只需要一栋建筑时使用独立模块。

确认上述流程稳定后，再做更多素材、语义检索、远程素材分发和拍摄工具。远程共享不自动携带私人作品或账号数据；发行来源和再分发许可作为素材发布流程的一部分记录。

## 5. 操作流畅性的验收

本次是源代码和交付记录核对，没有冒充新一轮真人操作验收，也没有发起新模型生成。

下一轮从全新的隔离客户端档案开始，记录实际步骤、结果与耗时：

| 场景 | 验收条件 |
| --- | --- |
| 首次打开、尚未连接 AI | 能看到示例并游玩；没有 CLI 时给出连接入口，不能把现成世界挡住 |
| 连接 Codex | 路径/版本/未登录/无模型权限分别有明确反馈；成功后前端显示实际模型与强度 |
| 同端切换四个示例 | 切换前正确保存，界面显示真实阶段；失败保持原世界与进度；不弹出四个独立应用 |
| 模板新建与重开 | 原示例不变，新世界与会话独立，重开后源、进度和目标对应正确 |
| F2 对话与继续游玩 | 不丢输入、不会把打字当成开枪或移动、关闭对话后不会卡住按键 |
| 新世界复用同款博美 | 实际检索到认可版本、外观一致且能跟随/互动；无需重新建模；保存重开正常 |
| “驾驶歼-20”与“放一个歼-20 模型” | 前者匹配可玩组件，后者可只放模型；结果按真实需求判断 |
| 创作中切换/取消/失败 | 状态明确；取消后没有迟到写入；失败不丢原世界；恢复采用原操作身份 |

界面反馈延迟、加载/构建阶段、F2 响应、卡顿与游戏运行帧率分别测量，不能把模型生成时间当成 UI 响应时间。记录冷启动、再次进入、复用及新生成的实际用时，不先给出未经测量的“秒开”承诺。

自动验证继续使用独立后台档案，禁用 Pointer Lock，不发送真实系统键鼠、不抢焦点、不操控用户浏览器。使用普通页面处理流程和原生通道；保持可取消。涉及 AI 的体验验收使用玩家实际选择的模型与强度，不新增 token、调用次数或整轮时长上限。最终再由用户在 Windows 候选版进行自然操作试玩。

## 6. 首轮交付建议

首轮 Windows 候选版重点交付：**四世界同端入口 + Codex 连接向导 + 同款博美复用完整流程**。飞机和雨作为整世界先保留，再逐项组件化。这样可以同时验证打开世界是否方便、普通玩家是否会连接 AI、以及 Agent 是否真的复用已有成果。

当前代码主要落点：

- 连接：`SettingsPage.tsx`、`codex-world-backend.ts`、`codex-app-server.mjs` 及受控 Electron IPC。
- 世界入口：`CraftmineNavigation.tsx`、`WorldListPanel.tsx`、`AdvancedWorldSaves.tsx`、`CopyWorldButton.tsx`，以及原生世界复制/初始化服务。
- 素材：`AssetLibraryPanel.tsx`、`asset_catalog/`、`builtin-source-library.cjs`、`source-library-service.cjs`、`godot-package-source.mjs`。
- Agent：桌面 `CODEX_WORLD_TOOLS`、CLI `scripts/lib/codex-world-host.mjs`，共同使用注册插件与正常创作权限。

已有基础应逐项验收和扩展，不另建世界数据库、素材存储或只供宣传片使用的平行创作入口。
