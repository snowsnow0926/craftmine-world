1. **完整进度存入真实 Rust。** `craftmine.godot-progress/1` 将世界、底座和版本与
   完整原生进度正文绑定，不再把俯视/横版强制塞进体素玩家坐标结构。Rust 校验身份、
   大小、版本和修订并保留正文，底座校验原生字段。支持大段 Unicode 和 Godot JSON
   浮点书写形式，不要求 JavaScript 重序列化得到相同字节。
2. **正式产物由核心解析。** 宿主读取 Rust 核验过的已应用构建、检查记录与文件哈希，
   页面不能提交任意目录或入口。只读候选描述符绑定准备令牌及当前世界、工程、素材、
   检查状态；完整候选应用协调器仍待实现。
3. **Electron 宿主接入完整存档。** 主进程、preload 和面板已接线。保存确认来自
   真实 Rust 耐久回执，绑定当前实例和原始快照；回包丢失只查询已保存结果。
   隐藏页签暂停并移除原生视图，退出先确认保存；保存失败阻止离开或退出。
4. **三个作者底座接入统一生命周期。** 支持显式加载、暂停、快照、保存确认和恢复。
   E 保留装备、任务、时间戳；F 恢复场景、朝向、商店、奖励账本；G 恢复生命值、房间、
   能力进度。横版编辑器退出的资源泄漏已修复。
5. **隔离诊断取得新证据。** LPAC 加仅 `registryRead` 的候选策略，在可信原生探针中
   对 IPv4/IPv6 TCP 连接、监听和外部连接返回权限拒绝 `10013`；宿主正常通信的正向
   对照通过。固定 Godot 在同策略下完成导入和 Web 导出，完整门禁仍未通过。

## 审计发现与修复

- 完整客户端发现主进程私有白名单漏了三个 Godot 方法，导致旧世界切换也失败。
  已补齐精确方法及有界等待，重新构建和回归通过。
- 原生重启发现 E 读取快照会重写 `savedAt`。已改为无副作用读取，完整保留时间戳
  和暂停时接地状态；验收没有删除或归一化字段。
- Web 测试首次遗漏导出预设必要字段，导入失败。已补齐预设，保持严格错误检查。
- 旧网络诊断把 `raw_os_error=None` 错当成功，实际为 `TimedOut`。
  撤回前一轮“普通 AppContainer 允许回环”的结论；超时只能算未知。
- 普通 LPAC 的 Winsock 初始化失败不能算可用方案。精确注册表读取能力加入后才
  观察到正常初始化和明确拒绝。实际 LPAC token 查询错误 `87` 仍按未知保留。

## 未完成与下一轮入口

完整进度指底座定义的持久状态，不含瞬时速度、动画帧和攻击碰撞框。额外原生字段
无法恢复时明确拒绝，扩展需同步 capture/restore。旧 Godot 进度需要显式迁移；
现有体素世界兼容保留。

E 已做真实 Web/Electron/Rust 验证，F/G 目前只有 Godot headless 证据。
完整产品 25 项回归使用旧世界，不能替代“从产品新建 Godot 世界并游玩”的验收。
截图证明场景与装备可渲染，没有验证可见窗口合成、玩家输入或手感。

世界选择写入失败后从耐久状态重建原世界，并非保留旧实例到提交的两阶段切换。
恢复再次失败会暂停并隐藏不确定视图、显示错误，等待重开。服务产物前核验哈希
也不等于已经证明能抵御并发原生文件系统篡改。

诊断策略尚未进入产品任务 API。Godot 编辑器脚本网络只给出通用 `error=1`，
不能独立证明 OS 权限拒绝，完整门禁保持失败，正式任意工程执行器仍关闭。

不能用游戏脚本输出自证权限，UDP 也需补明确拒绝。
