# M3.3：长期方向、需求来源与运行上下文

2026-09-08。实现、后台界面验收与真实模型跨对话窗口的多轮验收已完成，随 Alpha 0.7 交付。

## 三种记忆各自保存什么

1. **创作记忆库**保存实际对象、玩法配置或带源码的完整创作与版本，用于再次安装。沿用 M2 的实现。
2. **创作方向与长期约定**由用户明确编辑，包含整个世界的方向和可限定到某个对象的约定。不从讨论文字中偷偷推断永久规则，不允许模型自行覆盖约定。当前明确需求优先，选中范围仍由程序校验。
3. **已应用需求**在应用事务成功时自动保存用户原文、任务身份、基准、结果版本和摘要。候选、讨论、取消、失败、丢弃不进入此记录。历史需求仅说明过去发生过什么；以当前场景为准，不自动恢复已删除的内容。

这些数据放在项目的 `projectContext` 字段，和世界提交使用同一个原子文件写入。旧项目首次载入时先备份，再添加字段；只从现存任务里明确标记已应用的执行任务补录，不重写世界、进度或未处理候选。

## 使用与读取

右侧“创作方向与长期约定”打开开发工作区。方向可编辑，约定可添加、删除或限定对象；从已应用需求整理约定先进入草稿，用户编辑保存后才生效。每次保存检查编辑版本；后台刷新不覆盖尚未保存的草稿，旧版本提交被拒绝并提供重新载入入口。

每次生成固定当时的方向、相关已应用需求和当前版本运行问题，写入 `tasks/<id>/project-context.json`。任务中记录读取的方向版本、约定 ID、历史任务 ID 和错误模块 ID；开发工作区可以查看实际读取的数据。自动修复沿用同一轮方向，用户运行期间的新编辑用于下一次需求。

已保存的源码错误只有在其 revision 与当前构建一致时才进入运行问题。记录包括源码身份、关联对象、错误文字、模块状态和游戏时间；不把旧版或已删除模块的错误当作当前问题。问题入口选中相关对象并准备修复描述，发送时读取最新进度。错误文字始终是诊断数据，不是可执行指令。

## 明确的容量和边界

- 方向最多 4000 字；最多 24 条长期约定，每条 1000 字。它们不会随对话或任务列表裁剪而消失。
- 自动保留最近 64 条已应用需求，每次最多提供 8 条。用词匹配、对象身份与最近记录排序；中文按相邻双字检索，英文按词检索。这是本地确定性检索，不宣称语义向量搜索。
- 重要约定可以从历史需求整理后长期保存。早于 64 次成功修改的需求不承诺自动检索；任务文件仍依现有存储规则保留。
- 暂只在本项目保存方向。完整存档与模块导出仍使用原有格式，不包含整个项目的方向、对话或全部需求记录。
- 运行错误以最近成功保存的进度为依据，不是持续上传诊断；没有错误记录也不等同于玩法已满足需求。
- 限定到已删除对象的约定仍可在界面整理，但在对象不存在时不提供给模型。恢复相同身份的对象后重新生效。
