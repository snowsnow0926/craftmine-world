# DeepSeek 玩家连续造物流程测试

基线：preview26 / `19a5e153`。本轮使用用户授权附件中的 Flash 服务，在新建 Godot 3D 空白世界内连续创作，保留上一轮已经产生的内容。

## 实际配置与边界

- 通过应用普通配置和会话入口调用 `deepseek-flash`，上下文 1,000,000、最大输出 384,000、最高思考 `max`、有效权限 `auto`；启动和发消息前核对真实配置。
- 不额外设置模型调用次数、token 或整轮时长上限。模型自己选择素材复用、建模与实现方式。
- 独立后台应用、独立档案；不抢占鼠标、键盘、焦点或 Pointer Lock。
- 操作驱动只提交玩家话语、按玩家原始目标回答澄清、观察并通过现有运行接口试玩。不会写数据库、人物位置或存档来伪造成功。
- 原 preview26 ZIP 和原玩家档案保持原样。修复在本次独立工作树实现并重新验收；原失败记录保留。

已确认的问题：

1. 树已自动应用后，世界页仍显示先前 `GODOT_CANDIDATE_ACTIVE` 错误。实际截图和碰撞正常，普通重新打开同一世界可恢复；这是过期展示错误残留，不能误写成世界运行已黑屏。
2. `cw.module.sandbox-combat` v1 声明了 3 个实体，但只定义一个怪物节点的自动安装方式，安装器正确拒绝 `PACKAGE_SINGLE_ENTITY_DECLARATION_REQUIRED`。公开接口没有“选择包内实体”参数，改位置或分组安装不能修复包数据。模型自行推断并尝试未知参数，又产生参数无效等错误。
3. 模型向玩家输出大量内部标识，已自动应用的流程仍反复建议刷新。已开展提示与工具说明改进，实际效果需更新包后再验证。

## 剑的首段等待问题

“给我一把剑。”首轮 `e5ea4f90-e045-4516-8233-69fa37e97e46` 在 HTTP 200 后等到闲置超时。通过应用工作台的正常“继续”表单产生 `69966612-996e-40c4-9c4b-85c635283821`，第二轮同样在首段内容前停止。两次均没有报告 token 用量，不能记为 0 token 或免费；没有执行源码工具，保存状态仍与怪物移动测试结束时一致。

旧判断只按文本、思考或工具参数的语义增量续命，不识别有效等待心跳。独立复现已证明标准持续心跳、150 秒后才返回内容的请求会被旧 120 秒判断中断。历史两次真实请求没有记录原始心跳，不能据此断言它们一定收到过心跳。下一候选需要通过不记录正文或凭据的连接活动数据区分实际情况，并保留原失败。

另发现旧 v1 复用提案仍有“继续”提示和可点击安装入口，虽然其固定归档声明已确认不能自动安装。正在修正这些旧卡片和同源素材入口的展示；不删除历史、不静默替换版本、不将未知兼容状态一概禁用。

原始报告目录：`D:/cm-deepseek-monster-hunter/test-results/desktop-native-product-vJtlTm`。结果按实际发生补充，不预填成功，不把开发者诊断修复混作自然 AI 创作。
