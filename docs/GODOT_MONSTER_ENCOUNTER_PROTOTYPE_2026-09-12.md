# Godot 遭遇战预制行为原型

## 当前交付范围

新增第一人称底座的 `MonsterEncounter` 场景和行为，复用实际武器射线、TargetDummy 状态、玩家生命和库存。近距且视线无遮挡时对玩家造成伤害；被真实武器击杀后可以拾取掉落；领取、生命及怪物攻击剩余冷却进入存档。复活后可以再次被武器命中。

库存领取先在副本中验证容量、重复物品合并和堆栈上限，再一次性提交；失败保持库存及掉落状态。恢复先验证新增字段，旧死亡靶没有掉落标记时按已结算处理，避免凭迁移生成奖励。原型没有增加生产测试操作、强行移动或直接写入存档的接口。

此阶段仍使用训练靶外观，不是最终怪物美术。组件依赖第一人称 `BaseWorld`、Inventory、TargetDummy；尚未包装为造物沙盒可安装模块，也未声明普通玩家在空白造物世界输入一句话就能获得完整战斗。下一步需明确沙盒玩家生命接口和通用组件状态接入，再加入可辨识的怪物模型、动画、声音与可配置参数。

## 审查发现及修复

子任务初稿虽然可以击杀与拾取，但存在：掉落部分领取后重复发放、恢复校验在修改状态之后执行、隔墙伤害、剩余冷却丢失、为测试引入额外生产操作等问题。总控逐项审查并完成最终集成，保留原始失败和独立分支记录，不以旧版简单测试代替最终结果。

## 实际验证

```powershell
$env:CRAFTMINE_GODOT_CACHE_DIR='D:/Craftmine World/desktop/build/godot/4.7.2-stable'
node tests/godot-components/monster-encounter-headless.mjs
```

报告：`D:/cm-promo-loop-0912/test-results/monster-encounter-EeAv6S/report.json`。

- 实际训练场派生夹具中五次武器射线攻击击杀，靠近后领取 `coin`、`fang`，保存后第二进程恢复死亡和领取状态；重复拾取不增加库存。
- 独立 SceneTree 夹具加载真实生产节点，容量不足连续两次领取均保持库存不变，腾出容量后恰好领取一次。
- 实际 StaticBody3D 墙体挡住攻击，移除墙后玩家受伤。
- 非零怪物攻击冷却快照恢复一致；无效扩展字段拒绝且不半写；怪物复活后再次被实际武器射线命中。

测试中直接配置库存容量和布置墙体是开发夹具准备；交互及伤害经过实际游戏方法。没有模型调用、鼠标键盘操作、前台窗口或 Pointer Lock。非零冷却验证是同进程恢复，死亡和掉落另有第二进程冷重开证据，不混淆两者。
