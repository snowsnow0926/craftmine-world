Godot 3D 样本检查相机挂点、装备 UI 状态、真正的物理射线命中、弹药和目标血量。2D 样本通过 CharacterBody2D 移动到 Area2D 商店范围后购买，范围外拒绝购买，并核对金币和物品。两个工程均在完整结束并重启 Godot 后保留进度。

无窗口 Godot 使用 64 × 64 的虚拟渲染表面。本轮准星测量仅证明 Control 覆盖当前虚拟视口，不能当作屏幕画面或 GPU 性能验收。单次样本中，3D 和 2D 导入分别约 2.23 秒、1.94 秒；这是当前开发机已有系统文件缓存的观测，不能作为新机器冷启动或最终创作耗时保证。

已保留的失败与修复：

1. Windows PowerShell 下载路径改用无 HTML 解析的下载模式并增加超时，避免后台准备挂起。
2. 首轮日志收集器在断言失败时覆盖原始输出，已改为追加错误。后续保留了具体引擎日志。
3. 独立 USERPROFILE 缺少 Desktop/Documents 等目录，导致编辑器目录查询报错；补齐测试目录后导入通过。
4. 3D 示例预先创建后被替换的网格节点未释放，导致引擎退出报泄漏；改成单一挂载节点后通过。
5. 2D 重启后的物理重叠状态尚未稳定，首次读取为 false；保留正常物理更新并等待初始化后，恢复检查通过。

失败记录见 [Godot 失败记录目录](evidence/godot-cycle-01/failures/README.md)。没有通过放宽数值或忽略引擎错误取得通过结果。

## 下一轮入口

继续 GD0：准备匹配的导出模板，将同一批固定工程导出到 Web，在独立 headless 页面中验证载入、渲染、状态桥接和再次构建。对照原生呈现的实际接入条件，记录功能、等待时间和包体开销；普通独立窗口不能替代中央嵌入。

同时确定导入、工具脚本、构建和运行的操作系统隔离边界。在完成这一层之前，固定作者探针不能升级为允许产品 LLM 任意生成工程并自动运行的入口。之后再推进 GD2 的 PI/Rust 工程事务与真实模型创作。

继续执行时先核对本地最新提交、Goal 状态和工作树，不复用已结束轮次的工作目录，也不重复执行历史禁止的输入测试。尚未完成的 GD0–GD8 工作继续由当前 Goal 推进，不将本轮检查通过视为整份计划完成。
