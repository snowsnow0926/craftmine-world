# 宣传愿望采用：保留未用完的模型预算

日期：2026-09-12。基线：`43203d8e`。分支：`codex/promo-adoption-budget-20260912`。

## 改动

`tests/promo-wish-adoption.mjs` 原来强制剩余预算为 0，并在采用过程中重新启用模型评测环境。现在接受合法的剩余额度；隔离依据改为模型已停止、干净结束、真实检查通过、明确的模型入口与凭证剔除，以及原始账本不可变。

新增离线合同 helper，要求 `latest.active === false`、有效结束时间、无强制停止、退出审计正常；检查任务必须实际通过且不陈旧，包含非空且全部通过的检查断言，世界、候选、构建和检查 ID 完整。预算各项必须为合法整数，remaining 等于 limit 减 reserved，账本保留相同上限和完全相符的唯一请求数。

采用进程使用 `checkpointEnvironment`，随后只保留有限的操作系统与隔离运行变量。剔除所有模型评测开关、模型凭证和任意额外环境配置；唯一允许的 token 是隔离 profile 已验证的 headless 控制句柄。没有初始化评测入口、发送愿望或恢复任务的 RPC。

流程仍是原产品的预览、采用、保存和冷重开。启动及退出核对同一冻结包；只允许报告中的原世界和原候选，采用后的实际 build 必须等于原检查 build。原报告、profile 标记和请求账本从预检到最终退出保持字节不变。新报告分别记录预算前后值，只有成功完成账本验证后才记录新增模型请求为 0。

`model-report.json` 与 `profile` 位于同一恢复目录时无需另加路径规则。进程日志只保留字节计数，不额外复制旧会话内容。预算采用成功后继续保留余额，不通过额外模型请求消耗它。

## 验证与边界

- 13 项离线测试通过，覆盖有余额／无余额、活动模型、缺失停止证据、失败检查、候选身份、非法预算与账本、凭证过滤、禁止模型 RPC，以及恢复目录内报告／账本变动检测。
- `node --check tests/promo-wish-adoption.mjs` 和 `git diff --check` 通过。
- 只读核验真实第二次 PET01 报告：`latest.active=false`，预算 10／已预留 10／剩余 0，三个文件证据有效，预检通过。
- 本轮没有启动任何 profile、调用模型、采用候选或运行 UI。实际成品采用由总控集成后执行。

此改动仅处理采用驱动。既有 checkpoint 导出 helper 的首轮“预算耗尽”限制未在本轮调整；后续若需直接导出带余额的采用结果，应另做账本延续审查，不能据此自动重置额度。
