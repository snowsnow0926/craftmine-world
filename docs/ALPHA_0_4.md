# Alpha 0.4：花草、创作记忆与基础玩法

日期：2026-09-08。

## 结果

修复了“一格是最小尺寸、所有部件都有碰撞、仅有建筑材质”造成的砖块花草。新场景支持 0.02 米起的细粒度部件、独立颜色、尖薄叶片和逐部件碰撞；LLM 可以生成细茎、彩色花瓣、花蕊及草叶。旧格式的构建和哈希保持兼容，旧作品不会因程序更新而被静默改写。

素材工作区增加创作记忆库。已应用的对象与玩法自动保存为不可变的模块版本，记录真实定义、内容哈希、原始需求、来源构建和依赖。失败、未应用或丢弃的候选不进入成果库。修改实例产生新版本，移动实例不产生几何版本；删除实例不删除记忆。库中可以选择历史版本复用，或单独导出、导入另一个兼容项目。

Agent 在每次执行前检索模块名称、需求记录和当前选中对象，最多传入六个模块定义，并限制总输入大小。执行日志记录实际读取的模块和结果中的来源引用。检索使用本地词匹配，目前没有向量数据库或社区搜索。实例嵌入自己的定义并记录来源版本，库中更新不会改动其他实例。

实现 health、ranged、melee 三类玩法及对象受伤/接触伤害组件。运行器支持玩家血条、坠落和接触伤害、死亡复活、训练枪/剑外观与攻击反馈、弹匣、换弹、冷却、射线遮挡、目标生命值和击破。生命值、弹药和目标伤害分别进入运行存档，重新加载时保留兼容进度；新参数缩小时裁剪到可用范围。

## 模块边界

保存的是 **可运行的声明式定义**。`app/gameplay.mjs` 实现系统代码和状态，LLM 生成符合这些运行约定的配置与场景组合。它目前不能编写任意新 JavaScript 系统。新增背包、采集、任务、敌人 AI 等能力时，需要注册校验、依赖、生命周期及状态迁移；任意代码的隔离构建与验证仍是后续工作。

详细方案见 [模块记忆设计](MODULE_MEMORY_PLAN.md)。本地库不是公共社区；多人、外部图片/3D 服务、第三方脚本和跨引擎适配未实现。

## 文件和约定

| 文件 | 职责 |
| --- | --- |
| `app/scene.mjs` | scene/1 兼容、scene/2 校验、构建哈希、小数几何、范围和预算 |
| `app/geometry.mjs` | 小尺寸长方体/薄叶网格、材质比例、射线与 AABB |
| `app/gameplay.mjs` | 玩法注册表、配置依赖、生命值/武器/目标状态 |
| `app/memory.mjs` | 模块提取、不可变版本、校验、检索、复用放置 |
| `app/store.mjs` | 应用事务中写入模块索引，迁移时先备份 |
| `app/agent.mjs` | 真实 LLM、模块上下文、来源引用检查 |
| `scripts/stage-verified-repair.mjs` | 停止本地服务后，将已验证的修复准备成候选，拒绝过期基准，不改变当前进度 |

新模块：`craftmine.module/1`，运行约定 `craftmine-web/2`。每个模块写入 `.craftmine/modules/<id>/<version>.json`；项目文件保存目录和实例绑定。内容先写盘，再原子提交索引和当前版本。旧 scene/1 哈希仍按原方式检查，scene/2 和模块内容使用对字段顺序不敏感的规范化哈希。

场景预算：最多 128 对象、每对象 128 部件、总共 4,096 部件、24,000 体积、100,000 绘制面。薄叶不能作为实心碰撞体，跨对象实体重叠会被拒绝，装饰可以自然交错。相机继续使用旧运行器；小数几何使用连续碰撞检测，避免取整成隐形砖块。

## 验证方式与设备约束

用户明确要求开发测试不抢鼠标，已写入 `AGENTS.md`。默认 `npm run test:browser` 使用独立 headless 浏览器、禁用 Pointer Lock，通过 HTTP、页面脚本和纯游戏逻辑验证；不发送真实输入，不激活窗口，不使用用户的浏览器。`npm run test:live` 同样遵守此约束，使用独立旧版场景夹具；`--repair-current` 才读取个人世界副本。

本轮验证环境为 Windows / Chrome / WebGL。尚未验证真实移动设备、其他 GPU、无 WebGL 的兼容渲染器、多人和跨机器服务。武器是基础训练玩法，暂不含敌人 AI、网络同步、完整枪械动画/音效或武器库。
