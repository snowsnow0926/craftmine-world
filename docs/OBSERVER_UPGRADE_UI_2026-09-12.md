# 旧世界观察组件的正常升级入口

## 原因

静态 ArrayMesh 拾取更新了固定观察器哈希。32cd879d 与 594f698b 的已采用世界仍运行原观察器；旧 `prop` 目标不能提升为新观察器的可信场景对象。原代码在生成 captureId 前拒绝，但现有迁移只在带 capture 的正常任务开始后触发，界面又只提示“指向暂不可用，可继续输入文字”，没有升级入口。原兼容表的目标哈希也仍指向旧拾取器。

## 本次处理

产品提交 `ca9bb0dd`。精确识别两个已发布版本的完整五文件观察器集合及 LF/CRLF 哈希，只返回不可编辑的 `upgradeId`；普通 `captureId`、选中对象、落点均为空，聊天不会绑定旧对象。未知文件、缺文件、资源别名或修改后的旧观察器仍拒绝，不自动信任或覆盖。

玩家在现有目标面板明确点击“更新世界观察组件并检查”，复用原 creationEdit 的 operationId、持久状态、源迁移、check、候选采用和结束流程。维护只消费专用句柄，不调用模型或普通造物操作。原 CAS 迁移证明普通源码未变；既有草稿冲突会阻止升级。采用前再核对迁移回执源码、通过的检查、候选、当前分支和原正式身份。完成后沿已有 refresh 重新捕获新实例，不沿用旧 prop 身份。

补充修正了兼容表选择：新完整集合不能遮住旧 preview.10 迁移中允许新增缺失 helper 的目的地。未改变正式世界的进度格式，也未修改六组作品或旧试验报告。

## 验证和待验

69 项不同回归用例通过，包括旧两版本 LF/CRLF 的只换拾取器 CAS、普通脚本逐字节保留、未知/别名拒绝、维护句柄不可用于聊天和物件编辑、跨会话/世界拒绝、原操作状态与失败路径、候选源码核对、旧 prop 信任边界以及目标面板按钮渲染。desktop 完整 TypeScript 检查通过。

这些是服务/CAS 夹具与组件渲染检查，尚未宣称冻结产品中的完整升级成功。发布前仍需在独立旧 profile 中，通过正常界面入口完成检查、采用、冷重开及重新捕获；失败应保留原资料和真实错误，不手改报告、草稿或观察器文件来通过测试。
