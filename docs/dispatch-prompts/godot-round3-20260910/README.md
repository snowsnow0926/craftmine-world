# 第三轮并行开发：修复审计缺口并完成实际交付

本目录提供 **8 份给新 agent 的完整提示词，以及 1 份给现有 R2 的补充提示**。每份可以单独复制分发，已包含共同规则、代码范围、依赖和实际验收条件。

本轮目标是完成 [第二轮审计](../../audits/godot-round2-20260910/REPORT.md)指出的产品缺口：正式创建与应用、版本和进度一致性、作品实际安装、完整备份恢复、素材预览、真实模型创作，以及包含新工具链的 Windows 发行物。当前先实现这一完整交付，不在同一批任务中展开社区、L3/L4 或新的效率实验；总计划中这些后续内容仍保留。

本次只准备分发文件，没有启动这 8 项产品开发，也没有停止或替换 R2。主任务 Goal 当前暂停，本文件不修改其状态。

## 2. 这轮避免反复交接口的执行顺序

1. **先交共同起点。** S7 从 R2 已提交内容建立综合基线，记录已合入/缺失/暂不可用。它是开发起点，还没有被宣告验收通过。各模块可以先基于该版本修复并提交。
2. **先接一个实际流程。** S1 的正式 RPC、S2 的私有服务和 R2 的 Electron 注入同步落地；从产品创建一个世界，构建、检查、首次可玩、修改、应用、重开。接口提供者先给小的可消费提交，不等待全模块结束。
3. **补完整复用与恢复。** S3/S5 修安装与素材，S4/S1 补耐久恢复和强制引用保护；R2 接对应 UI，S6 使用实际采样与模型工具。
4. **冻结功能候选。** S7 固定完整源码/核心/引擎/broker/插件身份，先做非模型启动探针，再跑一条真实模型需求，随后覆盖适用冻结集合。执行器不可用时先修环境，不重复消耗整批模型请求。
5. **先做候选包，再做同包终验。** S8 从该源码真正构建安装器并标为待终验；S7 在包中跑模型与功能，S8 完成安装/许可/性能等终验。两者不互相等待“对方全部通过”才开始。
6. **主任务最终审计和合并。** S7 交可合入综合分支，S8 交包与证据；主任务核对修复、实际流程与未完成项。产品代码不由这 8 个任务分别直接合进 master，不推送或对外发布。

修复造成源码或载荷变化后，更新候选身份并重验受影响范围。不得把旧二进制的成功归给新源码；旧通过数字仅作回归依据。
