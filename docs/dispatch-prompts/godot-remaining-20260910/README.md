## 主任务负责集成，不再与专责 agent 同时开发其模块

- 主任务先确认旧工作树已经停止写入，建立只读交接清单；原成果的未提交状态不等于可以删除或重写。
- A 接手现有 root 的 Rust 工作；B 接手旧隔离模块；C 接手 root 的私有执行服务接线；D 接手旧预览宿主；F 保留已提交底座历史。主任务以后在这些范围的修复，应先与负责人约定交接。
- 主任务统一合入共享 `electron/main/index.ts`、`plugins/craftmine-world/view.mjs`、全局依赖/版本/锁文件，以及总 spec/ADR/E2E 编号和映射。各 agent 提供最小可合并片段，不能把整个共享文件搬入交付。
- A 独占 Rust `main.rs/lib.rs`、`worlds.rs` 和共享数据库迁移登记；H 的作品迁移模块通过 A 登记。A 负责首个 Godot 世界的初始化事务和长期源码/资源/历史存储计量，F 提供初始状态，C 构建检查，D 首次加载确认，E 调用实际创建入口。
- C 独占插件 `main.cjs`、私有服务与 `plugin-runtime.ts/plugin-host-process.mjs`；L 独占 `world-tools.cjs`、`manifest.json` 的 agentTools 与模型上下文。C/L 先交服务与工具契约；manifest 其他贡献项由 root 协调合并。
- D 独占 Electron Godot 视图及 Web 桥，F 独占 Godot GDScript 共享适配与已有三底座，G 独占新挖掘分支。E 的 React 界面不另写游戏宿主。
- F 提供组件及底座清单；H 拥有作品包格式；K 负责最终发行/许可清单和文件核对；I 保持冻结验收独立；J 不能改 I 的评分来证明效果。

主任务集成顺序：先收 A/B 的可消费提交与契约，同时收 D/F 修复；接 C 的实际执行和检查，再接 E/L 的真实新建与创作入口；并入 H/G 及其适用功能；I 完成真实模型及恢复验收；K 做固定包实测/同包回归；J 按 GD8 依赖完成独立评测。可以分批集成，并不要求一个 agent 全部结束后下一位才开始。

## 交付与完成边界

所有 agent 交付自己的干净分支、逻辑提交、接口与最小接线片段、可复现命令和原始证据，保留失败及未验收项。主任务按整份总计划审计、合并并复验。每个模块的“开发完成”、正式产品接线、真实 AI 验收与可安装交付分别记账。

完整 Goal 不因某一批提交通过而完成；首个可用版可以先交 3D/俯视和必要恢复能力，但不会删除 G/J 或其他尚未完成的总计划条目。人工试玩及独立 Windows 环境缺失的项目应明确保留，不能改成离屏测试通过。
