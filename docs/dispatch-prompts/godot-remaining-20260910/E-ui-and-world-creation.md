## 专责任务

你的目标：完成用户真正能操作的 GD1/GD2 界面，从“选择底座新建”到“右侧对话创作、预览、游玩和继续修改”。

独占 vendor/pi-desktop/apps/desktop/src/App.tsx 中 Craftmine 相关 UI、styles/craftmine.css 及新增专属 React 组件/状态模块。插件页面的新 UI 尽量拆到你独立命名的模块；现有 plugins/craftmine-world/view.mjs 与 Electron main/index.ts 的最小接线交 root。不得在 UI 内另建数据库、伪造已通过构建或绕过 C 启动 Godot。

现有代码已实现 craftmine-world-first 的基础排列和窄窗样式，不要从头换掉整个客户端。主流程“创建 Godot 世界并选择空白/样例”仍未完成，D 的候选应用当前要求已有正式 Godot 世界。

必须完成：
1. 左侧世界列表、中央主要游戏区域、右侧完整对话与输入；世界带底座标签及状态。辅助作品/检查/记忆/任务/备份按需展开，避免多排固定栏长期挤压世界。
2. 新建流程：选择已交付底座 → 空白或小样例 → 命名 → 创建。调用 A/F/C 的真实工程创建和初次构建服务；初始化成功后才登记可游玩世界，失败展示可恢复进度。规划中的底座不伪装成可选成品。
3. 多个世界分别保留名称、底座、进度、会话、记忆和任务。切换不改后台任务归属；迟到结果留在原世界。保存失败停留原世界，调用 D 的受管理切换。
4. 创作/游玩切换、面板伸缩和宽度记忆/恢复默认；检查长中文、缩放、深浅主题与窄窗。输入框、返回入口、候选操作始终可达，聊天输入不会触发游戏动作。
5. 清楚显示正式世界、草稿预览、检查结果、等待/失败和恢复动作；玩家主动应用。只讨论模式不创建或修改候选。按机器错误、模型代码错误、需求未满足、平台限制和体验意见展示，不把客观必需失败标成通过。
