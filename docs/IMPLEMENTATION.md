# 本地创作 Alpha 0.3：实现与验证

日期：2026-09-08。

本文为 Alpha 0.3 的历史记录。当前功能和验证请见 [Alpha 0.4](ALPHA_0_4.md)。其中原生输入测试执行于用户提出“不抢鼠标”之前，当前默认验收已改为禁用鼠标锁定的后台检查。

## 已交付的体验

空白平地与第一人称操作 → 在工作台输入自然语言 → 真实 LLM 生成新场景内容 → 校验并构建独立候选 → 用户应用 → 保留最新位置 → 对准同一对象继续修改 → 保存并重新进入。

首轮实际验收使用用户原话“我想要有树”，随后通过准星携带生成的 `tree-001`，输入“把这棵树变高两格，保持它的位置和 ID，继续保持树的形状。”两个请求都经过真实模型调用，得到不同的场景产物并成功应用。取消第三项请求后，没有产生迟到候选。

本版本覆盖计划中的本机基线、空白世界、场景候选和真实场景生成闭环。**当前 LLM 生成的是项目场景内容，尚不能自主新增任意玩法 JavaScript。** 计划中的通用源码开发、代码版本兼容迁移和真实外部素材接入仍需后续实现。

## 实现选择

- Node.js 标准库提供本地服务，运行时无需安装 npm 包。
- 继续使用旧原型的 WebGL 渲染器、方块网格、相机、物理和碰撞。`app/game.js` 提取空白起点与基本操作，不加载旧森林、小屋或采集规则。
- 工作台与游戏分离。游戏在带 sandbox 属性的 iframe 中运行，只允许脚本及鼠标锁定，不授予同源权限。
- 本地 Codex CLI 作为首个真实模型适配器。使用非交互 JSON 输出和 JSON Schema，复用本机已保存的登录；应用不读取或复制登录凭据。官方说明：[非交互执行与结构化输出](https://learn.chatgpt.com/docs/non-interactive-mode)。
- 执行时使用只读模式，关闭 shell、统一命令工具、应用、插件、联网搜索和多 Agent 功能，并忽略用户配置。完整场景和所需上下文直接作为输入；由受控服务校验返回结果并写入项目内容。CLI 使用其默认模型，可通过进程环境变量指定其他可用模型。
- 单个任务最多运行 4 分钟，无应用层自动重试；取消终止此次子进程树，等执行进程退出后才记录取消完成。

页面上的“Codex 已登录”反映本机登录检查结果。是否能成功生成，由实际任务结果确认。游戏运行和保存是本地的，生成请求仍需要连接模型服务，并使用该登录账号的模型额度。

## 文件与数据

```text
app/server.mjs       本地 HTTP 服务、会话、接口与页面分发
app/agent.mjs        真实 LLM 调用、取消、日志及场景候选
app/scene.mjs        场景格式、校验、几何编译及状态约定
app/store.mjs        原子持久化、版本、备份及应用事务
app/client.js       工作台交互、任务、三个工作区和载入流程
app/game.js          从既有运行器提取的空白世界与消息协议
app/index.html      工作台入口
app/style.css       工作台样式
app/game.html/css   隔离的游玩区域
.craftmine/         当前本地项目数据，已加入 Git 忽略规则
```

`.craftmine/project.json` 记录当前版本、进度、任务和对话；`builds/<版本>/scene.json` 是生成后的项目内容，`build.json` 保存可载入产物与内容哈希；`tasks/<任务>/` 保留输入、结构化响应以及改动前后的场景；`backups/` 保留应用前的完整记录。

当前场景格式为 `craftmine.scene/1`，由带稳定 ID 的对象及其长方体几何部分组成。没有预定义“树”处理分支：模型可以组合支持的材料和几何描述不同对象。范围为 96 × 96 有限场地，最多 64 个对象、每对象 128 部分、累计构造体积 24,000 格。拒绝未知字段、脚本、非法材质、越界内容和跨对象覆盖。

当前操作层只有移动、环顾、跳跃和冲刺。新项目进度为 `craftmine.progress/1`，保存玩家位置与朝向；已经创造的对象保存在场景版本中。旧原型的背包、采集与手动搭建仍保留在原型中，不与这个新项目混用。

## 应用与恢复

1. 固定当前版本作为生成基准。候选在独立目录构建，不改变游戏。
2. 用户应用时暂停输入并读取即时快照，等待之前的保存请求结束。
3. 服务先写入完整备份和应用事务，当前版本指针暂时不变。
4. 在另一个游戏 iframe 中载入候选，执行实际场景生成、恢复位置和 WebGL 绘制检查。
5. 成功后持久提交版本与最新状态，再切换游玩窗口。
6. 失败则取消事务并恢复旧窗口；提交响应丢失时核对已提交事务 ID，避免把成功提交误判成失败。无法核对时保留数据并提示刷新。

服务重启或工作台刷新时，未提交的应用恢复为旧版本。完整存档导入也先形成候选，应用前备份当前世界，应用时恢复文件内的位置。场景版本回退则保留当前兼容位置。

## 已知边界与下一步

- 当前能生成和修改方块场景内容。任意脚本玩法、砍树掉落、生长动画、外部模型和图片生成尚未接入，模型会说明超出范围的需求。
- 基础碰撞对所有构造方块生效；玻璃也使用当前运行器的基础材质表现，不是完整物理材质系统。
- 此轮验证了 Windows 桌面 Chrome；真实移动设备、其他浏览器与跨机器使用尚未验收。
- 第一版限制单控制窗口。另一窗口需在原窗口关闭并等待约 15 秒后接手。服务重启后需要刷新工作台。
- 数据备份与版本暂不自动清理。磁盘满或写入失败会报告错误，保留旧版本；仍建议通过导出存档主动备份。
- 这是个人受信任项目的场景生成工具，不是任意第三方脚本执行平台或完整安全沙箱。

下一步最值得做的是用户实玩：检查第一棵树的位置、比例和对话修改是否符合预期；随后选择一个小的交互能力，设计受控的玩法代码开发接口，逐步从场景生成扩展到游戏规则开发。
