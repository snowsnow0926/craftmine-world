# 可玩预制组件下一批计划

## 顺序与目标

用户要求预制资源让游戏内 agent 更容易呈现好效果。首批 18 个包已支持环境搭建和真实模型成组拼城门；继续以普通玩家愿望、实际画面和保存后的行为作为验收依据。当前先闭合城门的视觉纠正及连续创造基线交接，再建设宠物伙伴，不用新增资源数量代替现有流程质量。

| 顺序 | 工作 | 完成标准 |
| --- | --- | --- |
| 1 | 修复素材候选采用后的会话草稿基线交接 | 原会话继续输入能正常工作；有未采用编辑、过期世界、未完成采用和错误身份时仍拒绝；保留真实失败输入，不手改玩家数据库 |
| 2 | 完成城门视觉纠正 | 原模型原配置收到真实游戏图片，或明确记录供应商拒绝；模型按自然愿望调整遮挡的树，保留门洞、花草及原对象，正常检查、预览、采用和保存重开 |
| 3 | 可玩宠物组件与外观资源 | 正常安装的伙伴能够跟随和互动，名字、外观、模式、位置及身份能保存恢复；两实例分别修改不串对象 |
| 4 | 后续战斗、雨场及驾驶组件 | 根据宠物的通用身份、动画和状态能力逐项扩展，分别验收真实攻击击杀、具有深度的雨效果、登离机及驾驶，不以静态外观代表行为 |

## 宠物首版范围

先做一套伙伴行为以及普通犬、白色博美两种可辨识外观。外观必须有真实形体差异，不能仅涂白。资源和动画需保留原始文件、版本、哈希、作者和允许随成品分发的许可；尚未找到和确认的资源明确保持待定。与现有环境采用协调的低多边形风格，实际 Compatibility/Web 加载通过后才入库。

伙伴在平地跟随玩家，接近后停止；碰到障碍不穿越，也不以瞬移冒充跟随。首版不扩展复杂全场寻路。近处 E 抚摸产生可见反馈，远处无效；至少有待机、行走和互动反馈。换名字或外观保留同一伙伴身份，两个实例分别保存名字、外观、跟随模式及位置。

动态角色不能破坏原有树木、城墙的对象选中。现有拾取逻辑遇到 AnimationMixer 或 Skeleton3D 的 fallback 行为需按实际生产代码验证并建立明确目标合同；不能为了新增角色而放松全局来源与身份保护。组件状态必须通过既有有版本的保存/恢复协议接入，不能假设场景脚本变量会自动入档。

验收顺序为：独立档案中正常安装、检查、预览、采用，真实有限跟随和互动，障碍阻挡，两实例独立修改，保存冷重开。之后用原玩家配置提交自然愿望，单列模型发现与复用结果。开发者预制场景与模型作品分别留证。

## 执行约束

仅用 Codex 子 agent 并行，主控负责集成与成品。记录使用中文。自动验证在独立后台，不使用真实键鼠、Pointer Lock 或用户浏览器；真实玩家模型流程不新增评测 token、调用次数或整轮时长上限。冻结成品和失败记录保持不变，不手改模型作品作为成功证据。

当前前两项已完成：`DRAFT_BASE_CONFLICT` 通用修复通过核心回归和同会话真实重试，模型获得正式游戏图片后只移动四棵遮挡树，正常预览、采用、保存及冷重开通过；见 [真实纠正记录](PLAYER_VISUAL_CORRECTION_RESULT_2026-09-12.md)。候选预览及采用仍经正常外部确认，不声称完全无人参与。

早期宠物资源筛选曾受官方下载配额阻断；该记录保留。后续采用原创犬类资源并完成下文所列引擎验证，不再把早期阻断作为当前资源状态。

## 宠物首版实现进度

原创普通犬与白博美已各有独立低多边形 GLB，均含 `idle` / `walk` 刚性分件动画；真实 Godot Compatibility/Web 导入、动画采样、无脚底下穿及动态网格选中通过。宠物行为已在独立真实引擎中验证跟随、靠近停止、墙体阻挡、近距/视线互动、双实例计数隔离、换外观和状态冷重开。

状态跨 Native→Web 的一次真实失败已定位为 `global_rotation.y` 矩阵再分解造成的 1e-9 级差异。现改用权威 heading 标量，同时继续检测外部旋转变化；原有严格 JSON 状态校验没有放宽。修复后的 Web 恢复、抚摸反馈和提示恢复通过。详细证据见 [宠物运行时集成](PET_RUNTIME_INTEGRATION_2026-09-12.md)。

可玩宠物已包装为内置 `cw.module.pet-companion@1`，包含两套外观、行为脚本及三项托管运行时源码依赖；19 包素材库预检通过，旧 18 包字节不变。Windows `0.14.4-preview.15` 的普通安装、采用、互动及保存重开已经通过，实际玩家模型随后完成同一伙伴改名和变为白色博美的自然输入案例；详细证据见下方当前安排。

宠物首版采用保守圆柱碰撞：普通犬半径 0.75 米、高 0.77 米，白博美半径 0.36 米、高 0.48 米。普通犬有效占地直径约 1.5 米，而首批森林门洞净宽 1.4 米，因此窄门穿行和一般导航尚未宣称完成。下一批先做带转身空间的折线走廊，用真实长向包络、旋转扫掠和静态地面碰撞验证，再决定是否扩展复合碰撞或局部导航。

早期 `CombatEncounter` 是旧 JS 逻辑层原型，不能当作 Godot 游戏战斗证据。当前第一人称真实怪物、武器命中、掉落和冷重开已验证；造物沙盒新增可选玩家生命组件，完整怪物与武器玩法仍在接入。不同底座和验证层级分别记录。

## 当前推进安排

1. 现有宠物包的成品互动、保存及同档重开验证已完成，见 [Windows 续验结果](PET_WINDOWS_CONTINUATION_RESULT_2026-09-12.md)。玩家自然语言修改同一伙伴也已完成实际采用、跟随、抚摸及重开，见 [真实改形结果](PET_PLAYER_RESTYLE_RESULT_2026-09-12.md)。已修复这次发现的多词检索漏项并更新配置修改指引；新指引效率对照及空白世界首次新增宠物仍待验证。
2. 真实沙盒已经接入可选生命、射线武器、追击怪物、掉落、宠物隔离和跨进程恢复，见 [战斗连续流程](SANDBOX_COMBAT_INTEGRATION_2026-09-12.md)。目前仍是源码原型，下一步封装兼容版本玩法包，补攻击动画/音效和更多武器，再用玩家自然语言新增怪物。沙盒模块不需要扩展所有静态生成器 kind，也不能直接照搬第一人称 TargetDummy。
3. 改善宠物在环境素材中的通行。先核实实际动画每轴连续包络，再做旋转过程碰撞验证；不把径向包围半径误当身体宽度，也不通过缩小到模型以内解决门洞问题。
4. 扩展雨、可驾驶载具和城市组合。每个预制包都需同时包含许可明确的素材、可配置行为、保存合同和调用说明；以可游玩的代表场景验收，新增数量不作为完成标准。

现有 19 包资源库及冻结 preview.15 保持原始身份；新的素材或行为修改不能静默替换已经发布的同版本包。通过后的改动再更新包版本、调用目录及 Windows 成品。
