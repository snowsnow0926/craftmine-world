先读本目录 01/02/03、根 AGENTS.md、主计划、`docs/LIVE_VERIFICATION.md` 和第 5 批报告。仓库 `D:/Craftmine World`，从 `dispatch/w2-w5-v1` 建 `codex/dispatch-d-<唯一后缀>` 独立分支/工作树。禁止真实输入、Pointer Lock、显示/置前测试窗口或个人数据改动；不合并 master、不推送、不启动自动循环/子 Agent。

## 先检查而非重复修复

阅读实际 `app/gameplay.mjs`、`game.js`、behavior 系列、`app/harness/extension-*.mjs`、断言与冻结内核，以及原生 `verify-view.mjs`。历史上出现过“不能新增 behavior 资源”“验收没加载 ext 依赖”“扩展断言只留档”等问题，逐项确认基线是否已经修复，保留真实剩余缺口。

作品包和安装索引由 A 维护；不要另建玩法库。生成的玩法/扩展仍在受控 Worker 中运行，不能直接变成有文件系统权限的 PI 插件。

## 必须完成

1. **可复用组合示例。** 在 `examples/dispatch-d/` 提供树/花草，以及生命值 + 近战 + 射击的最小玩法组合，保存依赖、初始状态和验收请求。能被 A 按固定作品版本安装，不把示例写死在正式引擎里。
2. **可辨认的花草。** 利用已有几何/材质能力，让花有细茎、花瓣，草为轻薄叶片，贴合 y=6 地面。明确尺寸、碰撞和分布，不用大砖块堆出默认花草；保持玩家能通行。给实际画面证据和几何/碰撞检查，审美仍需预览确认。
3. **真实战斗状态。** 验证生命、受伤/死亡、近战距离与冷却、射线/弹道命中、弹药/装填、射击冷却及奖励。使用实际伤害和状态变化，不能靠 HUD 文本或直接修改测试期望值代替。
4. **组合与迁移。** 生命、近战、射击和附加行为共存，安装时 ID/共享物品/状态版本不冲突。保留玩家和背包进度；兼容变更迁移成功，不兼容变更拒绝并保留旧世界。
5. **启动/重启语义。** 检查预览、预检、正式激活、保存、重启后，不因重复 start 或重复应用发两次奖、扣两次料。不能只依赖模型“记得别重复”；运行状态和事务需要可复核证据。
6. **扩展闭环。** 实际新增带 ext 依赖的行为、在编译/编辑/验证/预览/应用/重启中加载相同固定版本扩展。对抗评审必须运行，结论只作建议；其中的可执行需求断言必须在实际轨迹执行，不能只写文件或直接相信自述。
7. **反例与资源保护。** ABI、权限、命令名冲突、空实现、伪造测试结果、缺扩展、沙箱超时及 dispose 拒绝要有适当反例；沙箱失败不带走宿主进程。保留冻结回归的独立性，不能把被测实现拷贝进预期结果。
8. **与 C 的对象选择接入。** 提供只含实际对象 ID/world/build 的选择事件与旧版本拒绝规则，由 G 接入可信上下文；不暴露任意宿主桥或开放自动 Pointer Lock。

## 所有权与依赖

按 01 的 D 范围开发，玩法运行契约和 Worker 由你负责。库捕获/安装逻辑归 A；界面归 C；Rust 应用事务归 A。需要调整这些部分时在 `INTERFACE_D.md` 给出最小契约和样例，不直接跨组修改。

静态路由、公共 domain-adapter、插件 manifest、冻结清单属于 G 接线。新增能力要给完整的能力目录、语法/ABI 校验与运行证据；提出冻结清单变更的具体理由和差异，不能自动更新哈希让失败变绿。

## 验收重点

- 实际运行器中验证命中/未命中、超距、冷却中、无弹药、重载及死亡分支。
- 持久存档重启后生命、背包、奖励与行为状态正确；重复回执和预览不重复改变正式世界。
- 一个真实扩展确实被新 behavior 调用；扩展的空实现会让针对其效果的断言失败。
- 至少一份复合玩法在新世界安装、检查、应用和重启；A 未到时先跑基线/契约测试并明确最终安装项待集成。
- 独立 headless，初始化禁用输入锁/焦点；使用真实游戏事件脚本和逻辑，不用真实鼠标键盘。按键数据回放不能声称已验证玩家实际操作体验。
- 截图/轨迹给出源码和二进制版本，保留失败。真实模型全链路由 F/G 复验，你的固定示例不能冒充模型创作。
