# M3.1：有限自动修复与可追溯的失败记录

2026-09-08，M3.1 开发切片已完成并验收。随后差异预览与长期上下文也已验收，M3 整体随 Alpha 0.7 集中交付，个人服务已更新。本文件保留自动修复切片的实现与验收记录；当前版本状态见 `ALPHA_0_7.md`。

## 交付行为

一次创作最多进行首次生成和两次自动修复。场景格式、构建、对象范围、记忆来源、源码运行或兼容进度检查失败时，把实际诊断、失败输出、原始需求和当前进度交给模型修正。每次仍以原始世界和原始选中范围验证，不把失败产物当成已经确认的新世界。

所有尝试共享默认四分钟总时限，后台验证的启动和执行也受剩余时间限制；到期停止生成与修复并关闭资源。取消会中止当前模型进程树、后台验证和整个重试循环。模型连接、本机文件保存或验证环境故障不触发反复改写源码。超过修复次数仍失败时明确结束，保留原世界、最新进度和失败产物。

发送需求前先保存游戏的当前进度。检查候选时，在执行源码前后分别确认已有状态格式、对象偏移和几何兼容性；后台检查期间玩家仍可在原世界互动，应用时继续读取最新进度。此兼容检查不执行模型源码；源码仍只在独立浏览器 Worker 中执行，工具和开发 API 没有开放给生成模型。

## 执行记录

任务目录新增 `attempts/1`、`attempts/2`、`attempts/3`。每轮单独保存请求、回复 schema、模型原始输出、通过构建的场景、源码检查报告和失败诊断。通过后在任务根目录保留最终产物，兼容已有查看方式。

诊断记录阶段、错误、可否自动修复和失败模块；源码失败还记录具体事件，例如 `interact:wood-slide-door-01`。每次模型实际用量分别保留，总用量为各次之和。重启遇到未完成尝试时标记中断，不假装通过或继续后台请求。

“开发 → 执行记录”可以展开每次生成和修复，查看真实失败源码及其检查。访问接口需要已有的工作台会话与项目租约，只接受已存在任务中的 1–3 次尝试，不接受任意文件路径。产物以文本显示，不在工作台中执行。

真实修复测试的故障来源需要区分：首次失败源码由**测试夹具主动注入**，在门的互动事件调用不存在的 `missingDoorMotion`，确实被生产验证器执行并报错；第二次由**真实 Codex 模型**读取诊断和原始请求完成修复，不是测试代码替它改正。真实模型保留门与弹跳板的范围，把门的移动距离改为 2.4 米。测试在修复期间用旧源码开门，应用后保留原来的打开状态和 -1.8 米偏移；再次关门和开门实际使用 -2.4 米偏移。

可复现命令：

```sh
npm test
npm run test:repair
npm run test:repair-cancel
npm run test:live-repair
node tests/repair-browser.mjs --live-cancel
```

最后两项使用真实模型登录和执行进程。测试夹具只由独立测试服务的 `--import` 显式加载，生产服务不会读取它，也没有新增允许用户从 API 切换虚假模型的入口。测试使用独立数据、随机端口和禁用鼠标锁定的 headless 浏览器，不发出真实键鼠输入、不使用个人浏览器。
