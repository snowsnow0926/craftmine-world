# 固定引擎监测：宿主校验服务

实现提交 `3945d15d` 接续 opt-in `engine-monitor/1` 桥接与来源校验。它新增严格宿主读取方法以及采样服务：先从宿主取得当前实例，再读取正式构建描述和源码清单，以应用自带资源的固定字节为依据验证源码和真实 PCK，最后发送一次随机 nonce 请求。返回后再次核对描述、源码、PCK、实例及采样时刻；重放、换实例、换源码、迟到结果或取消均拒绝。没有任何保存、全局作业取消或修改源码操作。

通用运行时请求不再允许 `engine-performance`；专用宿主方法仅接受当前世界、构建、实例和固定长度 nonce。冻结的快照允许这个只读动作，但构建切换、保存进行中等忙碌状态仍拒绝。

来源校验不是同进程脚本隔离：固定脚本哈希、PCK 和 nonce 证明加载文件及本次请求的绑定，不证明运行中任意项目代码无法干扰引擎。

## 默认兼容性

默认 materializer 输出保留原桥接，只有显式 opt-in 才增加继承桥接和采集器。观察器识别器只有在完整新桥接链逐项匹配时，才识别其原有 legacy/controller/collision 能力；缺失、修改或重复依赖被拒绝。普通创作 PCK 校验也覆盖新增依赖，实际 v2+monitor 导出共核实 14 项保护脚本。

## 验证

35 项协议、PCK、materializer、观察器兼容性和宿主服务测试通过；桌面 `pnpm exec tsc --noEmit` 通过。类型声明已覆盖跨 JS/TS 模块接口。

真实 Web 实验 `engine-bridge-web-HcBqsU` 使用固定 4.7.2 Web release 导出、生产 GodotWorldViewHost 和新宿主服务。在独立 C 盘目录运行，原始报告和日志保存在 `docs/evidence/gu6-engine-host-service-20260912/`。

- 宿主前后读取并验证真实导出 PCK，哈希 `1f38012e70d411985c6bbfec8dd6fcc297b70d08457c3bcaaba62887cf3e4dc4`。
- 活动采样取得引擎发布值：process 56.775 ms、physics 0.891 ms、FPS 30、节点 33、对象 1417、draw calls 17。它们是单次软件渲染试验的监测值，不能解释为硬件性能或优化收益。
- 暂停时 process/physics/FPS 明确 unknown，快照保持一致；GPU 时间始终 unknown。
- 独立后台窗口隐藏、不可聚焦，Pointer Lock/focus 计数均为 0，进程退出码 0。

Core 正式描述和源码响应在这份实验中是明确的测试夹具；引擎、导出文件、宿主方法与采样服务是真实实现。尚未把新服务注册进主应用生产 provider，也未由普通 Agent 工具读取这些引擎指标。`56b5aeca` 封存包的内存验收保持原范围，不覆盖此后的引擎桥接。
