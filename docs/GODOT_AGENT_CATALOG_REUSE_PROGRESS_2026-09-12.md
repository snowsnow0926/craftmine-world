日期：2026-09-12。工作树 `D:/cm-agent-godot-0912`，开发计划 GU6。模型建议、资源选择和宿主安装已接通，精确包 `a9b4c0e299c7a40f88c4e004f02a9fe658016159` 完成 25 个实际产品步骤。完整 GU0–GU7 目标仍未完成。

## 当前行为

Agent 使用 `package_library / propose-source-install` 读取一个固定资源库版本，返回其 ID、版本、catalog contentHash 和绑定世界的复用建议。该路径只读 task.context 和一次 asset.read，不创建草稿租约，也不赋予建议安装权限。

Godot 作品界面可按名称或 ID 检索、分页，并选择确切旧版本；新版存在时不会自动升级。核对单 ZIP 的元数据后，玩家选择安装。宿主再次验证所有者、库记录、blob 元数据和实际字节，调用原有源包安装器。库哈希、完整 ZIP 摘要和包内资源哈希分别校验。源码修改、检查通过、预览和正式应用保持独立。

新路径沿用既有持久操作记录，并在规划前保存宿主来源与所有者。相同操作可以跨服务重启恢复；即使 ZIP 字节相同，换引用或换所有者仍被拒绝。私有安装派发是接受边界：已接受的固定世界事务可以继续完成，但新查看会话不能确认旧所有者的回执。

审查复现了“已写入但回复丢失，授权过期后一直无法重试”的缺口。现在显式重试会重新验证元数据、blob、原 ZIP 摘要及所有者，再使用有效授权恢复原持久操作；没有放行旧过期授权。界面只释放首次新操作的确定前置拒绝；出现未知结果后，继续使用原操作和原引用，不能因后续元数据失败就推断原先未写入。

## 未覆盖与下一步

这次没有让玩家模型生成复用请求；模型路由、UI逻辑与实际宿主接受分别验证，不能合称普通玩家自主完成。实际产品链通过面板通道调用，没有把它冒称逐按钮完整视觉验收。两模块仍用默认原点，参数修改、单独瞄准、导航、规模性能和质量收益未覆盖。

下一步是导入模块的实例局部参数持久化。独立派生引擎诊断已发现：运行中调用 configure 可改变一个实例且不影响另一个，但普通 capture 不保存这些模块字段；从未改源码重建实例后仍恢复默认参数。应沿原源码覆盖与版本化接口实现，不能把内存修改或同实例 restore 当成保存成功。另需对齐模型资源分类与核心的七种标准分类。完整验收项继续保留在 [GA01–GA28 账本](GODOT_AGENT_ACCEPTANCE_LEDGER.json)。

随后已合入七类筛选修复，保留旧别名；真实核心返回的分类可以原样用于模型筛选。模块参数问题的 [实际诊断与实施方案](spec/godot-module-instance-persistence-audit.md) 也已归档。两项增量的主集成组合回归共 41 项通过，但它们发生在 a9 包之后，不能回填为上述成品验收的一部分；参数持久化本身仍待实现。
