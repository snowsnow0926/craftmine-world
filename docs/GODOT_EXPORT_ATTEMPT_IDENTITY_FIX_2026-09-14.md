# 应用更新后重新构建相同世界的产物身份修复

真实第 047 轮在同一份 revision 14 草稿上遇到两个连续拒绝：先是旧检查的
`GODOT_CONTINUATION_TOOLCHAIN_CHANGED`，随后完整重建出现
`GODOT_ARTIFACT_CONFLICT`。这不是世界脚本编译失败。

只读核对确认：打包前后的 broker 源码摘要相同，但二进制 SHA256 分别为
`7b53fb24d81dbba338cb1b5a75190ab064db46901056010de1e55e3e62a5d448` 和
`bffa28bc7612adb75bf163a9819ee9c19d9927339d2b0282a8053182c2c5e32c`。
仅替换该值即可精确重算新旧作业的工具链证据哈希。Godot、导出模板和桥接脚本没有变化。

这次重新导出的 9 个文件中，8 个与旧产物完全相同；等长的 `index.pck`
从 `13e3fce0cd57e111d3da027e389408e2650781b904a74124d24c88178c02c03b`
变为 `aa0fbcf73eb17c568d77bc77e501cfb7b1ee8a74af1c5443ce059eca5893d3bc`。
旧 BuildID 只区分源码等输入，因此再次导出会指向同一目录，正确的不可变校验阻止了覆盖。

修复在 Rust 的 `godotBuild.start`：将既有、由宿主控制的确定性 jobId 纳入 v2 BuildID。
同一次工具调用仍重放原收据；不同的完整构建调用各有不可变目录。这同时覆盖工具链升级和
同一工具链重新导出的非确定性。原 `godotJob.continue` 仍复用精确旧产物并严格核验工具链，
没有降低安全校验、修改玩家源码、重置进度或改动公开工具目录。旧 ID、作业、文件与历史不迁移。

Rust 回归覆盖新旧目录隔离、旧 PCK 字节与修改时间不变、原作业输出不变、调用幂等、
新候选检查与正常采用，以及冷重开查询。使用的是独立临时档案及模拟启动证据；实际成品
中的模型续检、原生加载和游玩须由集成验收单独记录，不能用这些测试替代。
