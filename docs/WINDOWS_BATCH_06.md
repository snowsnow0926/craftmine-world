## 2. Harness 的底层补了什么

Rust 现在统一保存世界版本、草稿、作品、类型化记忆、任务代际、请求预算、验收回执及备份事务。Electron 主进程提供真实的会话和世界身份；模型与页面不能自己填写这些身份，也不能把“我已测试通过”变成正式证据。

PI 继续负责唯一的 Agent 循环，React/TypeScript 保留桌面体验，现有游戏和受控 Worker 继续运行玩家玩法代码。这不是整套重写 Rust：把持久状态和事务放入 Rust，能保留已有桌面及游戏能力，避免两份正式世界同时写入。

长任务有以下保护：

- 创作、摘要、评审和重试向同一个任务账本计量。压缩、恢复不会清零预算。
- 请求发送前计算完整载荷的保守估计，发送边界再次检查；收到真实用量后结算。失联请求保留未知用量预留，不假装免费。
- 每次重新提供原始需求、最新纠正、草稿版本、已修改资源、当前任务状态；较长原文可以分页读取。
- 世界任务只开放世界工具。通用文件、命令或其他 Agent 工具不能绕过世界事务。
- 已结束或已取消任务不能因旧摘要或迟到回复重新获得写入权。恢复会产生新代际，旧调用随即失效。
- 手动压缩沿用原世界任务，只做摘要；不会新建草稿、取消原检查或重置原预算。没有世界的普通 PI 会话保留原有压缩行为。
- 对抗评审必须执行，但设计意见是建议。编译、隔离运行、冻结回归、实际断言等机器检查仍是硬门槛。

## 3. 真跑暴露的问题和修复

这些不是只看代码推测的问题；失败记录保留在各组证据目录。

| 问题 | 后果 | 处理 |
| --- | --- | --- |
| JSON 转义后的最终评审请求比预约估计大 | 真实模型评审在发送前被预算门槛拒绝 | 按实际 JSON 形式保守估计，保持发送前检查 |
| 评审模型用了不存在的字段或漏字段 | 创作完成但评审 JSON 无法验收 | 先保存失败原文和用量，最多自动进行一次明确的格式纠错；第二次仍错即停止，解析标准未放松 |
| 作品安装后继续改草稿时漏带扩展 | 带扩展的模块无法编译或应用 | 编译、检查和正式应用使用准确的草稿依赖，拒绝同版本不同内容 |
| 短界面任务结束后重试丢回执操作 | 可能新建任务或重复写入 | 先查真实历史回执，核对原参数，再决定是否启动新动作；记忆也有跨短任务的精确回执 |
| 手动压缩误开启新世界任务 | 原检查被取消、预算关系改变 | 增加只读维护通道，摘要仍记在原账本 |
| 已恢复任务启动模型失败 | 草稿还在，但任务可能失去恢复入口 | 明确中断新一代任务，保存原预算和草稿，允许再次恢复 |
| 重开玩法模块再次发启动奖励 | 玩家可以因重启重复拿奖励 | 持久化初始化标记，重开保留奖励和扩展状态 |
| 备份界面携带了领域服务不接受的 worldId | 备份状态与取消请求被拒绝 | 主进程只传实际服务接受的业务参数；恢复仍是整个客户端领域备份 |

## 6. 还没做完的内容

1. **W4 最终组合链验收**：从原生作品库安装生命/射击/近战/扩展组合，再正式应用、实际运行和重启。已有游戏与库的分层证据，仍不能把它们拼成未经执行的一条完整通过。
2. **W5 干净 Windows**：无开发工具首装、实际覆盖升级、升级失败恢复、卸载、跨 Windows 用户凭据。当前有构建和合成档案保护测试，没有隔离 Windows VM 的安装证据。
3. **可见桌面与手感**：完整窗口的可见合成、物理双击、移动和攻击手感、美术观感尚未人工验收。离屏图像不能证明这些。游玩布局目前是较宽面板，不是全屏游戏模式。
4. **性能与发行**：程序尚未签名；有体积和进程内存样本，没有稳定帧率、启动时间、长期运行占用的完整基准。诊断接口存在，部分性能采样尚未接线。
5. **少数故障体验**：关闭整个界面后，尚未确认的按钮请求 ID 不会持久恢复；若安装已提交而检查排队失败，会提示查询/重提检查，尚无专门的一键补交检查动作。
6. **扩展能力边界**：同一事件的多条扩展命令逐条执行，后续失败不会自动撤销之前命令；扩展状态版本不兼容会安全拒绝，尚无通用迁移语言。草稿仍有 2 MB 上限。

备份排除凭据存储，但包含世界、草稿、记忆、任务需求和相关证据；如果你曾在需求中输入私密内容，它也可能在备份里。升级保护快照还包含 PI 会话文本，仅用于本机恢复准备，不能等同于可分享的脱敏诊断。
