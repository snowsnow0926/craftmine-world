# FB02-007 全自动源码闭环与证据

本记录属于本轮 goal 的集成证据，不代替最终 Windows ZIP、真实模型创作与玩家验收报告。

## 已落实

- 全局或该会话的全自动权限由主机读取，直接绑定本轮世界自动采用授权。无需额外勾选每世界开关；ask 模式仍保留独立明确选择。权限撤销在实际采用前重新读取。
- 没有准星捕获的普通工作台和纯对话创建，也绑定主机确认的世界、正式构建、源码版本和原请求摘要；不伪造准星位置。
- 一般项目修改不再被有限关键词词典永久挡在手动采用之外。精确识别的要求保留原有语义断言；其他全自动修改要求实际源码发生变化，以及真实运行、画面、无错误、快照、隔离和恢复的完整检查证据。
- **通用运行检查并不证明任意自然语言要求已经满足。** 模型指导明确要求继续做行为和视觉检查，不把宿主采用回执误当作品质量结论。
- 自动采用归属持久化。检查晚于对话结束、用户暂看另一会话、切换世界或重启后，主机仍能核对原授权并在正确世界空闲时续作。检查 callback 丢失会通过持久捕获与精确 taskId 发现。
- 采用前后保留候选身份、源码版本与内容提交校验，复用原保存、候选试载、进度兼容性、正式事务及回滚流程。旧世界发生真正变化时，不自动重定向旧任务。
- 检查失败或重启中断时，进入主机的普通会话自动修复桥。保留原目标、要求和模型配置；修复消息明确标示由应用接续，不冒充玩家新要求。持久回执用于防止重复派发；由总控实现和验证该桥。
- 检查通过但采用失败时，只有固定诊断中的玩家与候选碰撞、规则拒绝已有进度、已知组件/实体模式变化，且已完整回滚、正式世界仍未变化，才允许进入源码自动修复。CAS、身份、权限、磁盘及事务不确定错误不会被误交给模型盲修。
- 用户停止修复会撤销共享原始捕获的整个修复链。正常退出等待正在采用的事务，暂停新工作；取消退出后可恢复。
- 对话状态区可区分等待自动续作、正在自动修复、已正式采用和明确失败。旧执行器回执不会永久覆盖后来确认的正式构建事实。

## 本轮另行发现并修复的旧世界兼容问题

原观察器迁移表的三个目标哈希已经落后于实际打包资源；当前 adapter 还新增了 `component_state.gd` 依赖，仅更新哈希会产生缺依赖的迁移。

本轮建立 v4 完整目标，固定记录 LF/CRLF 两种实际哈希，并把组件状态 helper 作为必须明确缺失或完全匹配的文件。迁移保留原发布 cohort 和上一迁移目标来源。自定义脚本、作品、其他 helper 以及未采用草稿仍受原 CAS 和全文件核对保护。历史发行测试保留真实“当时尚无新 helper”的事实，没有伪造已存在文件。
