# 造物世界指向与任务上下文开发记录

本次完成“这里／这个对象”从游戏观察、桌面主进程、创作输入框到模型任务的接线。界面显示命中的对象或地面坐标，并提供“更新指向”。发送、排队时保留原来的指向，之后移动摄像机不会改变已提交请求的目标。

## 已完成内容

- 主进程生成不可猜测的 `captureId`，保存真正的运行实例采样。界面仅提交句柄，不能用自行构造的 `targetSnapshot` 证明目标合法。
- 捕获绑定主进程解析的项目、会话、世界、正式构建、运行实例及正式源码版本和哈希；提交和绑定任务时再次检查。跨会话、跨世界、替换构建、实例重启、源码身份变化和超过五分钟的未提交句柄均拒绝。
- 新聊天尚未生成会话时，先按主进程当前项目捕获；首次发送创建会话后，只允许同一项目的第一个会话认领一次。已绑定会话的目标不得转移到其他会话。
- 任务上下文按项目、会话、轮次持久保存。正常创作、摘要、评审、重试都带回同一份目标；缺少命中时保留世界信息，不虚构原点或物体。
- 世界“自动应用通过检查的安全改动”选项默认关闭，由主进程保存。任务提交时未开启的权限不能事后扩大；玩家关闭选项后，当前任务下次读取上下文也会失去自动应用权限。实际检查和应用仍由世界工具事务完成。
- 新建世界显示“造物世界”，使用各底座自己的起点目录，避免把其他底座的模板套进空白造物底座。浮层状态取自实际模型等待、重试、子任务等待、待确认等状态。

## 验证记录

本工作树完成共享依赖构建、桌面 TypeScript 检查及 Electron 主进程、预加载、React 渲染器生产构建。新增主进程边界测试覆盖伪造输入、会话隔离、重复认领、并发绑定、正式源码身份变化、实例变化、权限撤销和持久恢复。针对导航、创建流程的回归测试一并通过；修正原有导航测试仍期待旧 `world.creationAction` 重试通道的过期断言。

`tests/creation-ui-headless.mjs` 使用真实 React 指向组件、新建世界组件和应用 store，以明确标注的本机传输夹具验证排队目标冻结、切换会话的迟到结果、世界权限隔离及真实任务状态显示。浏览器使用独立 headless 进程和独立数据目录，在初始化时禁用 Pointer Lock，全程通过页面脚本验证，没有鼠标、键盘、点击、填写或窗口置前操作。测试输出包含 JSON 报告和选中目标、未命中目标的截图。

这份界面报告验证的是实际组件及任务队列，不把夹具当作真实 Godot 引擎或真实模型创作成功率。真实引擎观察和源码检查、应用、保存重开的联调由整体计划的集成验收完成。

## 自动采用检查结果

“自动应用”已经接入主进程候选事务。执行器完成检查后只上报任务上下文和 `jobId`，主进程重新读取检查任务、候选版本、当前源码和已保存的玩家授权；通过当前任务身份、正式世界实例、源码版本及检查证据的核验，才进入采用流程。任意模型参数、源码日志和执行器自行声明的“通过”都不能替代这些事实。

采用时先暂停并保存最新正式进度，再加载候选版本验证恢复结果，最后走原有持久提交事务；不会先展示或游玩临时候选世界。世界切换、任务结束、权限撤销、源码变化在启动后和提交前都会再次检查。玩家切换到其他任务或关闭所属窗口时不自动接管世界。全过程不请求系统窗口焦点。

失败、取消或权限撤销时保留原来的正式构建；已成功保存的最新游玩进度保留。检查已经通过而后续自动采用失败时，应继续如实保留检查通过状态，由执行器单独报告采用失败，不能把检查任务反改为失败。未开启自动应用仍使用原来的手动预览与采用入口。

本批主进程服务和候选事务共 47 项测试通过，覆盖重复完成回调、跨任务或伪造证据、源码过期、检查失败或取消、启动后撤销、保存失败、加载失败、恢复状态不同、提交回复丢失，以及最新进度保存和原实例保留。完整 Electron 生产构建与 TypeScript 检查一并执行。
