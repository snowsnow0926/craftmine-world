# Alpha 0.5：模型编写可执行的新玩法

2026-09-08，M1 完成。新场景格式与独立源码执行已接入日常创作和保存事务，下一阶段继续做源码模块记忆，完整产品目标仍未完成。

## 实际交付

自然语言可以生成 `behaviors` 源码。源码接收现场快照、事件、参数和可保存的状态，返回受校验的命令；运行器没有根据“门”或“弹跳板”名字选择预置逻辑。

- 真实生成的木滑门收到互动后左移 1.8 米，原通路可通过；瞄准打开的门再互动可关闭并恢复阻挡。
- 真实生成的弹跳板根据高度计算冲量，实际物理上升 **2.89899 米**，有 1.2 秒冷却。
- 新增 E 互动与画面按钮、物品计数 HUD、开发区源码查看。
- 首次模型误把门板 offset 当中心，画面出现悬空。补充最小角坐标说明后，第二次真实请求修复了门板和附属几何，原有两份源码没有变动。
- 在门已打开时应用上述外观修复，开关状态、-1.8 米偏移、玩家位置均保留；关闭服务再启动也保留。

模型产物已保存为 `examples/door-and-bounce.save.json`，可通过“开发”中的完整存档导入形成候选。示例导入会恢复示例世界；个人已有候选和世界没有被本轮测试替换。

## 构建与运行

场景和进度增加 `/3`，旧版哈希与完整存档继续兼容。模型 JSON 通过显式转换将字符串参数还原为对象；源码只在独立 Worker 中执行，Node 的语法检查不执行源码。

生成和完整存档导入都先在独立 headless 浏览器检查代码。页面没有开发会话凭据，不能访问项目 API；测试禁用 Pointer Lock，不发出原生键鼠操作。错误模块被终止，最新确认状态保留；不兼容的状态版本在候选加载时终止应用事务，原世界和候选保留。

主线程对整批命令校验后才提交状态与效果。几何变化检查真实边界、物体重叠和玩家身体；库存不得负数或超限。更新场景后，已保存的对象偏移如果与新实体冲突，也会拒绝载入。旧进度里的已摧毁目标不阻挡恢复。

本地服务启动时固定本轮静态文件。后续持续开发的磁盘改动不会让已运行服务混用前后版本；每个可玩版本验证后再更新服务。
