# 造物世界可持久组件状态

为宠物及后续可玩组件增加通用状态接入，不改造物底座原生世界脚本，也不把 addon 脚本变量假定为已经保存。托管适配器负责 `body.components` 可选账本，未安装组件的旧世界仍输出原有完整字段；原生玩家、背包、门、宝箱、规则及时间由原底座恢复。

## 组件合同

实际世界子节点加入 `craftmine_persistent_components`，提供非空 `entity_id`、`snapshot()`、纯校验 `validate_state(data)`、完整恢复 `restore(data)`。每实例快照包含 `format`、同一 `entityId`、`settings`、`sourceSettings`，其余字段由自身版本合同验证。名字、外观、跟随模式属于设置；位置、朝向、互动次数属于运行进度。最多 64 项账本、每项 64 KiB、JSON 深度 8；容量约束不涉及模型用量。

源码初始设置由组件在初始化时固定。候选迁移使用真实候选默认快照：同身份仅在 `sourceSettings` 某项发生明确变化时应用对应新设置，其他设置和运行进度保留；状态格式或配置键类型不兼容时拒绝。JS 预览迁移和 Rust 采用证明执行同一规则，组件恢复还需验证当前源码设置匹配。旧组件移除后保留账本，重新出现同 ID 不清空计数或复制新实例的进度。

## 恢复与错误处理

组件输入先完整校验，再恢复原生状态及组件。校验器只收到深拷贝，修改输入或自身快照会拒绝；组件恢复前后核对实际节点、成员、身份以及完整快照。可选 `validate_restored_state()` 在所有组件和原生玩家恢复后检查实际放置，例如新外观与墙、玩家和其他伙伴的碰撞。

组件错误会回滚原生玩家和其他组件。回调错误删除成员、改变身份或使回滚不完整时，明确阻止继续保存，必须重新加载；不能在丢失节点后把剩余状态当作成功。`snapshot/load/save` 都通过实际捕获错误门禁，错误不会生成新的保存回执。

Godot JSON 编码只输出其确定的数值精度，组件快照与恢复投影比较使用同一真实 JSON 往返形式，避免内存浮点额外尾数导致误拒绝；没有新增数值容差，也没有修改 Rust 的精确 JSON 比较。Unicode 文本限制统一按字符数计算，较长 emoji 不会因 JS 的 UTF-16 长度规则而在迁移时误拒绝。

## 互动入口

普通 E 和托管 `interact` 共享适配器分发：从真实当前相机和原生物理射线定位已注册组件，再调用该单个组件 `interact(player)`。普通输入仅在组件命中时消费事件；其余仍走底座原入口。模块不自行给所有邻近实例广播按键。底座原脚本保持，因此自然日光包原先的源码兼容要求没有被改写。

## 当前验证

- 真实锁定 Godot 中 25 项运行时/账本检查通过，覆盖旧状态不加空字段、双实例、校验器改输入拒绝、移除后保留、JSON 精确往返、恢复后放置拒绝、原生与组件回滚、删成员后的保存阻断。报告：`test-results/component-state-fH8Z1d/report.json`。这是有意故障注入的测试组件，不冒充已完成真实宠物玩法。
- JS 组件及已有造物迁移 8 项检查通过；Rust 完整核心 327 项通过、0 失败、7 项既有忽略，包含新增组件迁移及伪造证明拒绝。日志：`test-results/component-core-full.log`。
- 修改共享运行桥后，四个既有底座的 26 项真实完整进度回归通过，包括冷启动、暂停恢复和无效状态原子拒绝。报告：`test-results/godot-managed-progress-OKWFLd/report.json`。
