# 最近对象来源不能作为放置落点

日期：2026-09-11。本批 CN1／CN2／CN3 集成审查修复。

## 已确认的缺陷

直接界面原本会拒绝最近对象来源的放置，但文字要求冻结和结构化操作编译未限制该来源。只读最小复现使用同世界、同构建和有效身份：最近选择指向树的原点 [4,0,0]，文字“在这里放一棵红色的树”得到 `verifiable`；同一最近捕获提供明确 position=[8,0,0] 的 place 操作，生成一个新实体。原始输出为 `{"frozenStatus":"verifiable","compilerCreated":1}`。

这证明最近对象的原点可以被错误解释为“这里”。默认位置发生碰撞并不能保护此边界，显式坐标和偏移仍可能写入草稿；未知源码修改也不能依赖该碰撞阻止自动验收。

## 修复

宿主文字和直接 place 要求均拒绝 source=recent。源码服务明确把宿主 source 保留到编译快照，并为新放置写入保留同样限制；操作编译器在 place 分支独立拒绝 recent，即使请求包含显式坐标或 offset。旧快照没有 source 时继续视作 ray，现有射线行为不变；最近选择仍可修改、复制或删除同一对象。

已在正式操作日志中精确匹配的操作保持只读重放，返回原回执和空补丁，不受新写入限制影响。现有 ray／缺省来源的丢回复回查继续使用原操作身份；没有加入绕过检查或重新提交写入的特殊模式。

## 验证

操作编译、源码服务、愿望要求、直接放置和最近结果五组定向单测共 55 项通过。新增覆盖文字／直接 place 要求、显式坐标／偏移反例、源码服务来源传播、精确日志只读重放、普通丢回复恢复及 ray 兼容。没有调用模型、引擎或真实输入。

其他审查未确认新的正确性阻断项；正式日志读取仍校验不可变源码身份及哈希，最近选择跨世界拒绝且不可见实体不自动换选，复制数量与各目标位置保持受检查。最终实际引擎、中文愿望和成品故事由总控执行并登记。
