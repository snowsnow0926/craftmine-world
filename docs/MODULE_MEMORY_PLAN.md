# Alpha 0.4：细粒度场景与创作记忆

## 本轮要解决的体验

花草不能再只能用一米立方体和建筑材质拼接。生成的内容应用成功后应成为可复用成果，用户关闭程序、删除世界里的实例，甚至导出到另一个本地项目后仍能继续使用。

## 分层

1. **场景实例**：稳定对象 ID、摆放位置、细粒度几何、碰撞和组件。外观由小数尺寸的长方体与薄叶片组成；颜色与材质独立；花草默认无碰撞。兼容读取旧 scene/1，新的创作使用 scene/2。
2. **模块定义**：对象模块保存相对于锚点的几何和组件；玩法模块保存运行器支持的系统类型和参数。模块包含稳定 ID、不可变版本、内容哈希、运行约定、依赖、来源需求。实例带来源版本，实际内容嵌入场景，旧世界不会被库中更新悄悄改变。
3. **项目记忆**：成功应用后自动提取成果，旧世界在首次升级时登记。失败、未应用和丢弃的候选不进入成果库。原始需求与模块一同保存，不依赖近期聊天窗口。下一次生成检索相关模块，把真实定义送入 LLM 上下文，执行记录显示检索结果。
4. **运行状态**：位置、生命值、弹药、目标受损等存档与模块定义分开。改变外观保留状态；改变参数时裁剪到兼容范围；完整导入才恢复文件中的状态。

## 开发顺序与本轮交付

- 支持 0.02 米起的部件、独立颜色、薄叶片、部件碰撞；修复现有世界的三朵花和两丛草并保持树、对象 ID、位置与历史。
- 本地模块库：自动记忆、版本浏览、单击复用、导出和导入受校验模块。安装仍形成候选并由用户应用。旧版本能复用；单个实例变化不会修改其他实例。
- LLM 检索已保存模块，能按需复用或改作；不把文本记忆当作执行权限。
- 注册并实现 health、ranged、melee 三种玩法系统，以及对象的可受伤/接触伤害组件。提供 HUD、命中/近战反馈、冷却、弹匣、换弹、死亡复活与持久化，验证玩法模块能跨独立项目复用。
- 对旧存档迁移、候选隔离、持久化、版本锁定、植物渲染/碰撞以及真实 LLM 生成和记忆引用做回归验证。

## 扩展方式和本轮边界

这轮保存的是实际可运行的声明式定义，并非任意 JS 文件。基础玩法的代码由运行器中的独立模块实现，模型生成配置和对象组合。新增系统需要注册配置校验、依赖、创建/更新/输入处理和状态迁移，再提供给 LLM；未知类型明确拒绝，不能只造一把枪的外观就声称已实现射击。

以后加入采集、背包、任务、AI 等模块时沿用同一身份和版本协议。任意代码生成需要另做隔离构建与测试；社区市场、联机同步、第三方脚本和任意引擎兼容均不在本轮范围。

## 数据与回退

模块内容写入 `.craftmine/modules/<id>/<version>.json`，目录由服务端生成和校验。项目文件记录目录索引和实例绑定。内容先落盘，再原子提交项目索引；磁盘失败不提前改变当前版本。现有 build 哈希保持兼容；迁移不覆盖旧场景。服务更新前备份当前项目，修复世界使用候选流程，历史版本仍可恢复。
