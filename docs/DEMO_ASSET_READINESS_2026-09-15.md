# Demo 素材跨世界可用性复盘

本轮发现：伙伴 v3 已声明必须配置保存范围，但普通素材搜索/读取仅检查底座
源码前提，安装器仍直接采用 ±80 默认值。这样在出生点检查通过，走到大城
更远处仍可能无法保存。另发现工具参数 schema 漏列已有的组合方案版本 3。

修复把配置接入真实共享安装链：自动单装、自动组合装、单提案确认、组合
提案确认都先解析范围，再写每个新实例的两个导出属性。已知沙盒/城市必须
同时匹配控制脚本、工程入口和主场景哈希；自定义世界要求 agent 查看源码，
提交绑定当前 revision/manifestHash 的结构化 positionBounds。缺配置或源码
已变化时，在计划安装、写源码和启动检查之前拒绝。实例 ID、原有对象、
进度和已发布素材字节均保留。

界面仍基于 pi-desktop。新版伙伴缺少所需配置时，素材详情说明要让 AI
查看世界源码并配置。旧版没有同样的强制配置契约，仍允许有限区域使用，
但显示每个坐标只支持 −80 到 80 的保存范围，并建议大世界跟随使用配置后的
新版或明确审查的源码升级；没有擅自禁止所有旧素材，也没有改旧 ZIP 哈希。

验证使用独立真实 Rust Core，实际导入 ZIP、生成场景、执行源码 CAS 并记录
检查任务。四种安装流程覆盖冷重开、两个不同范围实例和幂等重试；缺配置、
源码变更、NaN/Infinity、倒置边界和注入字段均有针对性回归。实际 PI 参数
校验器也验证了版本 3 与新字段。打包插件重复运行同套 Core 测试。

CPU 测试中的引擎执行器不可用，检查真实返回 blocked；不把此结果描述为
游玩/保存成功。大城跟随、保存冷开和视觉体验由总控的真实玩家流程验收。
既有自动保存候选切换的七个回归继续通过，此轮没有凭推测再改保存逻辑。
