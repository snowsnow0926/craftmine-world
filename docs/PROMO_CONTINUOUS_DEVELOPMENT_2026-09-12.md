# 宣传愿望驱动的持续开发记录

用户已授权持续循环开发，直到主动要求停止。主线以宣传分镜及 v2 愿望测试
方案为准，每轮按“定位缺口→通用实现→独立验证→提交→下一轮”推进。
不将预置目标场景作为模型生成成果，不将离线断言当成实机宣传依据。

## 本轮基线和已确认事实

起点为 `82380309`，已验证 Windows 包的产品源码为 `04a2ef6d`。
主工作区其他产品文档的未提交修改保留；开发在独立工作树完成。

## 第一轮

1. 复用 `39e634d5` 的离线清单和自主率分母修正，保留原始 Linux 证据。
2. 修正依赖图：狗失败只阻塞依赖狗的修改；怪物等独立步骤继续，完整主线
   仍保留失败，不能将部分成功汇总成全通过。
3. 为现有隔离模型评测增加单条普通愿望提交入口，只接收当前玩家文本与
   愿望 ID，通过原 agentPrompt、目标捕获和原请求预算执行。未来题目和
   裁判答案不进入模型上下文；提交前持久登记，回执丢失或重启后不重发。
4. 修复 Godot 历史、资产、创作包的能力报告与实际路由不一致。

## 随后的循环

- 冻结新构建，先进行零模型驱动和账本验证；再选择小范围真实愿望尝试。
- 第一条重点为宠物：外观、同一身份、约定行为、保存和后续修改分别判定。
- 根据实际失败补观察和交互能力，保持平台权限、采用与迁移检查。
- 宠物闭环稳定后推进固定版本复用、战斗和天气；飞机与城市各自保留独立
  探索，避免前置失败挡住其他组，也不拼接成同一世界的连续成功。

## 证据口径

新增愿望入口沿用既有每个隔离评测 profile 最多 40 次产品请求的持久预算，
不自动使用文档建议的 120 次上限。是否扩大真实调用范围另按实测成本决定。
本记录创建时没有发起本轮真实模型调用，没有六组功能通过结论。
所有测试禁止真实鼠标键盘、Pointer Lock、窗口激活和用户浏览器操作。

## 首次真实宠物摸底（独立组 PET01）

受测构建 `cf6f895a`，模型 deepseek-flash / high，在官方空白世界提交原句
“我希望有条宠物狗。”。10 次实际请求用尽上限；模型提交普通 GDScript
和场景修改并启动检查，无工具调用错误。最后状态为检查 import 阶段，
未确认采用、外形、交互或保存重开；不能记为宠物成功。

主任务约 140.8 秒，报告用量 503350 token，其中缓存读取 320512，输出
33419（推理 27491 包含在输出内，不重复相加）。6 次 ToolSearch 分布于
2 个模型批次；7 次文件读取。既不能把 6 次搜索说成 6 个模型往返，也不能
把所有用量当成未缓存费用。

本轮驱动在模型停止后过早关闭应用，打断正在进行的检查，已补测试并修复：
请求额度结束后继续等待已有检查和采用事务收尾，仍受墙钟上限约束。
原始失败记录保留。对原模型输出的独立副本执行 Godot headless 导入通过，
没有修改源码；它是定位证据，不是原任务已采用或功能通过证据。

下一轮针对真实发现优化 Godot 初始工具集合：由宿主已绑定世界的类型选择
必要读写工具，减少已知底座仍需反复搜索的步骤；权限和可用工具定义继续
由实际注册表和宿主校验决定。对照采用新冻结构建与新隔离档案，独立记录。

摘要证据：[首次宠物摸底](evidence/promo-cycle01-20260912/pet-first-pilot.json)。

空白世界和独立档案，最多 10 次产品请求。真实 import、export、runtime
