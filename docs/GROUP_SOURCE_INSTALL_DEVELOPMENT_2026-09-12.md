# 成组源码素材安装底层

本批为宿主增加 `createManagedPackageInstaller(...).group(args)`，供同一次确认安装 2–8 个现有格式的精确 ZIP。单包调用、旧包格式和检查后采用流程保持原有行为。

## 宿主接口

```js
installSource.group({
  operationId, worldId,
  expectedSource: {revision, manifestHash},
  items: [{archiveBase64, position: {x: -3, y: 0, z: 0}},
          {archiveBase64, position: {x: 3, y: 0, z: 0}}],
  // scene 可省略；沿用当前项目主场景。
});
```

`expectedSource` 必填；位置可省略，沿用模板。位置仍要求有限数值、每轴 ±80、该 ZIP 只有一个安装场景且根节点为 3D。结果仍包含 `source`、`job`、`instanceIds` 和 `applied:false`；新增 `archives:[{archiveSha256,instanceIds}]`，与输入顺序一一对应，其实例 ID 展平后严格等于顶层数组。没有冒充单包的聚合 ZIP 哈希。

## 事务与身份

一次读取并冻结原源码，独立验证原始 ZIP、源码前置要求和只读核心规划，再合并锁文件、负载与场景编辑，执行一次完整预检、一次 `godotProject.applyFiles` CAS、一次检查启动。源码前置要求全部针对原始世界，不依赖组内输入顺序悄悄满足。未制造新混合 ZIP。

重复资源共享不可变文件与锁条目，每个输入通过世界、组操作 ID、序号派生独立规划 ID，获得不同实例与实体身份。拒绝版本/内容冲突、不同资源声明的命名冲突、脚本或场景资源 UID 的跨路径冲突；原有文件冲突、脚本类名检查、UID 配对与源保护仍由现有完整预检执行。

全部验证完成后才原子写入世界。检查失败不会自动采用，也不回滚已明确保存的待检查源码；结果保持现有待检查/阻断状态。相同操作重放使用持久回执，不增加实例或启动第二个检查；阻断后的新检查应走正式重检流程。单包原有阻断重试策略未改变。提交已成功但回执丢失时，沿核心操作幂等性恢复原提交。

资源边界沿用现有安全限额：2–8 个包、整组压缩与展开正文各不超过 6 MiB，最终单次源码请求不超过 8 MiB。它们是文件事务约束，不是模型预算。

## 验证与范围

`group-source-core.test.mjs` 使用隔离临时目录和实际 Rust 核心，覆盖相同资源两实例、不同资源按顺序回执、提交回执丢失恢复、错误第二包/兼容性/内容/UID/声明冲突零写入、缺失或过期源码身份、并发源码修改后的 CAS 拒绝。原单包与真实素材目录安装回归一同通过，共 10 项。

这证明规划和源码事务，不等于引擎检查、视觉效果或模型主动组合素材已经通过。产品工具提案、确认界面与成品集成由总控另行验证；本批没有启动模型、引擎、玩家 profile 或发送实际输入。
