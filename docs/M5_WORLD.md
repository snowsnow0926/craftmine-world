# M5：一个由自然语言逐步做出的可玩世界

当前状态：M5.1 已实现并验收；M5.2 的真实模型采木、制作、开关门、持久任务及两次重启已通过，战斗和一次性任务奖励的完整串联仍待完成。M1–M4 已提供新源码执行、记忆复用、多轮创作、素材与完整作品迁移；M5 完成个人 Windows 创作 Alpha 的端到端体验，不包含多人服务器或公开发布。

## 验收故事

从空白世界开始，由真实模型根据逐条需求完成：树能被砍 → 获得木材 → 库存不足时工作台给出提示 → 收集足够木材后制作可开关的门 → 用武器击破目标 → 任务给出完成状态和奖励 → 保存、重启、导出到第二个项目 → 从另一个空白世界复用带源码的创作。

每一步必须实际操作对应游戏逻辑，核对库存、碰撞、伤害、门的状态和任务进度。模型输出、人工测试夹具和后台检查各自标清来源；“有代码”“出现提示”或“检查通过”不能替代可玩的完整流程。

## M5.1：补齐通用运行接口

- 当前源码只能增减共享库存，不能读取库存；配方无法可靠地判断材料是否足够。增加受限的只读库存快照，并让模块按稳定顺序读取及提交，避免多个配方从同一份旧快照扣料。
- 提供物品显示名称和简短说明，界面以玩家能理解的名称显示库存；实际保存和配方引用使用稳定身份。模块复用仍共享同一个玩家背包。
- 提供纯文本、容量受限的持久任务提示，归属于来源代码模块，随保存恢复，卸载时隐藏，恢复模块时继续显示。模型不能提交 HTML 或改动工作台。
- 用明确的能力声明和运行约定扩展源码及模块格式；旧场景、旧模块哈希与旧进度继续兼容。新能力随完整创作一起保存，旧运行器不能误认成可用的旧模块。
- 保留整步命令先校验后提交、Worker 执行限时、最新进度保护及失败恢复。库存不足是正常玩法分支，应显示要求，不能让配方模块永久停止。

## M5.2：真实模型连续创作与试玩

- 用两种可观察的玩法验证接口：采集掉落与消耗材料制作；随后增加目标战斗、任务要求和一次性奖励。
- 采用连续需求修改同一世界，保留已经收集的物品、已制作对象和既有源码状态。至少跨两次重启，并实际测试材料不足、重复交互和完成任务后不重复领奖。
- 不为“树”“门”“任务”添加关键词分支或固定玩法菜单。具体规则由模型源码和参数表达；树木几何、物品、配方与目标也由实际模型产物提供。
- 运行器资源和写权限仍有明确边界。制作出来的对象可以由模型在创作时定义，其出现、状态和互动由源码驱动；不以一个没有碰撞或不能互动的外观代替成品。

## M5.3：作品复用与个人交付

- 完整存档导入第二个独立项目后，保持相同源码、资源版本和已玩进度，继续完成未完成目标。
- 单独创作包从另一个空白世界安装后，使用独立实例身份及初始状态；旧版固定、更新、卸载和恢复继续工作。
- 提供可导入的真实模型示例、简明操作说明和验收记录；示例应从可玩的初始进度开始，用户个人世界和待处理候选继续保留。
- 集中交付本地可运行版本，保存升级备份并核对个人项目完整性。所有实现、验收和本地启动继续遵守 `AGENTS.md`，不抢鼠标。

完成 M5 后再逐条审计 `CONTINUOUS_DEVELOPMENT.md` 的 M1–M5 证据；全部满足才可完成当前持续目标。

## M5.1 实现与证据

`craftmine.behavior/3` 保留 /2 的依赖与实例绑定，并声明 `inventory.read@1`、`inventory.items@1`、`hud.panel@1` 中实际使用的能力。库存快照仅发给声明读取能力的模块；不同模块按场景顺序执行和提交，后一个配方看到前一个已扣除的材料。Worker 修改自己的快照不会改宿主库存。物品定义采用首次登记的名称，避免复用其他创作时覆盖相同物品身份。

持久面板是每模块最多三个的纯文本标题和行列表，不能写 HTML、控制工作台或覆盖其他模块面板。`behavior-state/3` 保存物品目录和面板；旧进度按需升级，旧世界仍使用原有格式。卸载将面板随模块归档并隐藏，恢复兼容源码后继续。注册物品、扣料、对象变化、任务提示和源码状态全部通过后一起提交，任何一步失败都不提前发布奖励。
