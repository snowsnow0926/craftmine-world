# Blender background modeling

Use the player's selected model and normal creation workflow. `blender_status` reports the bundled runtime gate. Discover `blender_generate`, `blender_job_read` and `blender_cancel` with ToolSearch. A missing runtime or failed native isolation is a capability gap; report its actual reason.

Read the current Godot project revision and manifestHash first. Generate a model with a lowercase asset name, that exact source identity, `expectedHash:null` for a new `assets/blender/<name>.glb`, or the actual existing file hash to replace it. Supply a Python script using `bpy` to create or modify geometry, materials and animation. The trusted driver saves the scene and exports the GLB; do not select files, executable paths, output paths, shell commands or external dependencies. Use meters, meaningful object names and a sensible origin. Prefer export-compatible materials and embedded textures. Network access and the player's files are unavailable to scripts.

Generation is asynchronous. Keep the jobId and poll `blender_job_read` until terminal. `blender_cancel` cancels only a job from the current host-bound turn. Host turn end and plugin unload also cancel running jobs. There is no extra model, token or whole-turn limit for this workflow. Normal existing asset import limits still apply: the current Godot source file ceiling is 4 MiB. Larger generated assets remain in managed job storage with an explicit import failure; simplify geometry/textures or split a model into separately generated assets.

The host retains verified `source.blend`, `script.py`, `model.glb` and `report.json`. For further edits, pass a previousJobId from this same world; the source is rehashed before the driver opens it. To retry a preserved model against a newer source revision, use that previousJobId and script `pass` with current pins. You cannot import into another world or overwrite a stale source revision.

`imported` means the GLB was committed to Godot project source only. Read the new revision, instantiate it in the actual scene, implement the requested collision and gameplay behavior, then follow the normal Godot build, check, candidate and application workflow. A modeled vehicle needs driving behavior; a character animation needs combat logic. Do not present generated geometry, model statistics or a source receipt as playable completion. Preserve the player's requested scope, interaction and visual quality when responding to clarification.
